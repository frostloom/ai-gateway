# 小规模 V1/V2 配对测评准备

本阶段完成免费准备与本地验证，没有启动真实模型测评，没有读取 `.env`，外部模型/JEV 请求均为 0。已有 1220 条真实首轮输出、历史分数和既有归档保持不变。

V1 使用 `model`：模型判断工具与回答。V2 使用 `jev_selective`：先由 JEV 判断，高置信且符合安全规则的请求直接处理，其余交给模型。两臂使用相同模型、协议、提示词、工具定义、输出限制、账户模板和代码版本。写操作继续先预览、等待用户明确确认；必要补问是合法中间行为。实际低置信回退须看 JEV 遥测，不能人为指定一条句子必然是低置信。

## 12 个代表任务与开发预期

冻结文件：[plan.json](../eval/paired-pilots/2026-10-13-dev-v1/plan.json)。来源为已冻结的全量任务定义，保留每轮允许动作、回答 assertions 与终态断言。它是开发标准，仍需独立语义审定，不是人工盲审金标，也不能代表全部 1220 条准确率。

## 调用与费用控制

准备文件提出最多 24 次模型上游请求、每次输出最多 128 token。24 次是试验调用总上限，不是“24 臂必然全部完成”：模型一次工具选择后可能再生成回答，追问任务还可能多轮，因此预算耗尽时保留未执行臂，不扩大预算补满。

`PairBudgetTransport` 在每次 HTTP 尝试前持久化计数和费用预留，再交给上游；重试也逐次计数。运行方必须明确填写请求字节限制、输入 token 预留上界、人民币预算及输入/输出最坏价格。禁止自动猜价格或读取密钥。费用预留不释放，以保证同一轮不能用实际消耗较低为由继续增加尝试次数。

支持 OpenAI 和 Anthropic usage；Anthropic 缓存读取、创建的输入 token 一并按声明最坏输入价格计算。缺 usage、上游错误、响应越界或调用中断时，费用标记未知并停止后续模型请求。预算日记与配对日记绑定路径身份、配置、价格和前后计数状态，不能换一个新预算文件继续原试验。

这控制的是声明价格及 token 上界下的预留额度，不能保证供应商实际账单。真实接入前还须核实模型价格和输入上界；JEV 价格未知，不默认免费，不发布全系统人民币成本或节省比例。

## 执行接口与可恢复记录

`RunPreparedPair` 接收明确构造的 `ConversationDriver` 工厂。真实运行需显式开启 `AllowPaid`，使用 `recorded_run`、同配置预算对象，并把受控 HTTP client 注入每个模型 client；接口不自行查找密钥。`ConfigureEvaluationClient` 限制输出、禁止重定向，并限制超时，普通服务默认配置不变。

工厂、状态 oracle、记录器与配置属于可信适配器。当前完成的是运行接口和本地真实 agent 接入验证；尚未提供自动读取 `.env` 的在线 CLI 或生产运行工厂。未来真实适配器必须为每臂创建独立初始账户，并把模型所有请求接到同一预算传输层。

两臂顺序按案例交错，记录逐轮观测、开始/完成、执行错误及耗时。已完成臂不重复；边界处正常停止后可续跑未开始臂。只有 start 没有 finish 的臂可能已扣费，需要人工核对，不能自动重发。初始化、执行、终态读取和清理失败都保留；原始依赖错误文本不写入日记，避免携带连接串等信息。fixture API key 在落盘前清除；日记仍含客服原话和回答，应按评测数据保管。

## 报告口径

每个计划案例保留 V1/V2 两行，包括未开始、未知中断、服务失败和语义待审核。报告从记录重新检查结构、事实、终态和回答要求，不信任保存的成功标签；真实记录拒绝 `local_stub` 合成审核。

- 任务完成：结构/终态和独立语义都满足才通过；必要追问、预览、确认属于任务过程。
- 回答：列出事实核验、事实错误及待审核要求，缺证据不补零、不猜真值。
- 模型资源：预算层上游尝试次数、遥测调用/token、按配置价格计算的费用与预留金额分开。
- 时间：保存遥测和 `runner_elapsed_ms`。后者包含初始化、工具、状态核验和清理，不是纯模型延迟，也不含用户思考时间。
- 比较：只有完整、契约一致的记录可进入现有比较器；未审核不发布质量收益，本准备报告始终不自动宣称真实 JEV 收益。

本准备阶段 CLI 提供离线准备和报告，拒绝在线参数、未知模式及覆盖已有输出；后续增加的离线 `preflight` 见下面的适配器文档：

```powershell
go run ./cmd/paired-eval -mode prepare -out .paired-plan.json
go run ./cmd/paired-eval -mode report -journal .paired-run.jsonl -out .paired-report.json
```

第一条选择开发任务，第二条要求已有配对日记，输出 JSON 和 `.json.md`。两条均不会触发模型或 JEV。
