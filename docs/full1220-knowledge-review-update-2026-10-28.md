## 最小改动方案

仅在知识增强变体启用一个`knowledge_need` choice，追加到原本发生的同次JEV请求，复用其置信度；不创建第二个分类器或分类调用。

| 分类 | 后端动作 |
|---|---|
| none | 不预取；只表示无需额外平台/账户资料，不证明模型记忆可靠 |
| platform | tool模式复用Corpus.Search有界取批准来源；resident完整携带时不重复搜索 |
| live | 实时余额、价格、订单、额度仍由原业务工具提供，分类不授权写入或越权 |
| mixed_or_uncertain | 平台部分取来源、实时部分取业务证据；不明确先澄清，不盲调全部工具 |

低置信和有效但矛盾的分类保守处理；非法枚举、缺字段、协议/usage失败仍按技术停止处理，不能借“不确定”隐藏故障。平台或混合需求不得走只返回业务结果的single_read快路径。

预取使用后端只读context及真实来源记录，不能伪造assistant/tool_call。无命中明确说明未核实；短query、256字符限制和轮内复用须记录原因，不暗增模型改写。新增JEV问题即使请求数不增，也会增加token、费和延迟，必须重测包络。

最少涉及五处：JEV问题及解析、受限预取/注入、共同知识运行身份与工具契约、最终outcome/Langfuse关联、题级来源金标及汇总指标。现阶段先设计与离线验证，不改原主范围冻结材料。

## 实验矩阵和新增题

1. 原1220主对照：model/off与jev_selective/off，保持完整三轮真实目标。
2. 知识补充A：model/tool与jev_selective/tool，双方关闭预取，单独观察知识存在时的路由差异。
3. 知识补充B：同一路由的tool与resident，使用同一语料和回答指导，区分知识方式与提示改变。
4. 预取补充C：jev_selective/tool对同配置加knowledge_need预取，明确是增强策略的增量效果。

不同时铺开全部付费组合。已有100题可复用为新补充范围的题源，旧结果不能混入新同期分母。`eval/knowledge-integration/draft-v1/`已有20题草案，覆盖闲聊、纯改写、平台、实时、混合/模糊、上下文跳过、短query及伪来源；尚未独立标注或运行，不是新增金标，也不是1220子集。先复核来源和边界，再决定需要新增哪些题。

两臂共同配置应校验strategy、corpus/编译SHA、提示、工具集、注入与输出上限、实现版本。只有selective预取即已改变知识策略，不能继续命名为纯路由收益。如果未来启用知识作为主产品基线，必须两臂一起启用并重新冻结完整原1220，不能沿用已消耗claim或只换一臂。

## 指标和Langfuse

最终任务正确率保留全部计划分母；技术失败、未运行及待复核不算正确。另报应取未取率、无效检索/片段相关率、模型/JEV调用和失败尝试、含检索的两币种总成本、每正确任务成本、原生cache hit/miss/creation及缺失、Handler和完整任务P50/P95。未知费不能按0，供应商账单、估算和永久预留分开；0正确时每正确任务成本N/A。

漏检分母由独立题级证据需求及可用批准来源决定，不能用JEV自己的分类作为真值；resident检索漏检率N/A，另报跨策略的相关资料携带覆盖率。缓存反事实与实际运行分开，失败/超时和完整可比配对分层，不能用0补未运行延迟。

Langfuse按scope/pair/pass/order、request ordinal关联分类/置信度/skip、真实检索query、语料/片段/来源SHA、included context、业务结果及最终回答。内容捕获关闭时不记录正文/query；只有元数据不冒称正文读回。`included`表示请求携带，不等于模型实际采用；采用情况只能通过引用和答案与来源的一致性独立审查，不能声称可观测内部注意力。
