# JEV 分流与效率统计离线核查

## 目标 1：本地执行门控

新增确定性审计测试直接调用 `fastPathReason`，不连接 JEV、模型、数据库或 HTTP。逐项核对意图/形态 0.90、合法性 0.85、风险置信度 0.80 的等号与相邻浮点值，以及风险分数 0.50 的排除边界。NaN、Infinity、负风险、不可用结果和无效 schema 均回退；待确认退款、多轮上下文和充值意图不得绕过执行边界。四个既有读工具白名单保持不变。

另运行既有 fast-path、schema、路由及写操作边界集成回归：

```powershell
$env:AGENT_LIVE_JEV='0'
go test ./internal/agent -run 'TestSelectiveGateExactBoundaries|TestJevFastPath|TestFastAnswers|TestRouting|TestSelectiveRouting|TestSelectiveWrite' -count=1 -json
```

退出 0，逐测试结果见 [门控摘要](../eval/jev-offline-readiness/2026-10-20/gate-summary.json)，完整压缩日志同目录。此轮只补现有行为的测试，未调整阈值或产品策略。既有集成测试使用模拟推理及专用测试数据库。

本地执行门控正确不等于 JEV 意图准确、置信度已校准，不能把这些测试通过率当真实用户准确率或 1220 条评测成绩。

## 目标 2：既有真实小样本的费用与延迟对账

新增 `scripts/audit-jev-efficiency.py`，只读 10 月 17 日已有的完整 Anthropic 配对样本。逐项校验原 manifest 的文件 SHA、报告对 journal 的 SHA、每个实验臂与回合、原始 usage、预算逐请求记录与连续快照、完整执行回执及报告汇总。缺 usage、异常延迟、重复实验臂、预算错位或回执不一致均拒绝。工具明确不支持不完整/中断/续跑样本及其他协议，避免把未知缓存量记零。

```powershell
python scripts/audit-jev-efficiency.py eval/paired-pilots/2026-10-17-jev-acceptance-v1
```

[派生核查结果](../eval/jev-offline-readiness/2026-10-20/efficiency-audit.json) 不覆盖原成绩。四个任务、八个实验臂重新核对结果如下：

Anthropic 的 `input_tokens` 不包含缓存读取及写入；因此旧报告的普通输入统计不等于全部计费输入。预算流水已经把两者相加，本轮没有发现预算漏算缓存输入。新核查结果补充展示缓存分项；不会把缓存 token 再次加进已含缓存的协议字段。本次缓存创建明确为零。

**旧 manifest 中费用摘要有误：** `priced_usage_micro_cny=46612`，但逐请求预算、逐臂报告及执行回执均为 **46592（0.046592 元）**。差额为 20 微元；原 manifest 与历史文件均保留，以 `manifest_priced_usage_mismatch` 单列发现。此错误不是一次新扣费，也不改变正确行为率。

以上费用使用历史运行声明的保守单价，未应用缓存折扣，不是供应商账单。JEV 的人民币单价和账户实际扣费未核验，**全系统费用仍为未知**，不能宣称总费用节省多少。无需重新请求模型即可完成本次对账。

余额样本确有一次 JEV 直读，绕过了两次模型调用；其余回退路径保留模型处理。四个任务的选择性分流服务端延迟总和反而略高，不能仅挑直读样本宣称整体加速。上述合计也不是包含用户思考、夹具准备和清理的完整任务耗时。
