# 本轮现金余额读取修复（2026-10-23）

第二批真实评测两条路径均在第二轮复用历史余额，未发生冻结要求的新读取。排查确认：`llmLoop` 的 readResults 缓存本来就是请求内局部变量，没有跨轮缓存泄漏；模型直接生成正文绕过了工具选择，原回复修复只检查虚假确认和重复询问金额，没有核对当前轮读取证据。`conversation_runner` 对无工具的 unreviewed 回答统一留待语义复核，因此仅允许 read 的轮次也被结构检查放过。

## 修复

在已有模型循环的有界回复修复中，出现中文“余额”及邻近显式人民币金额（¥、￥或数字加元）时，要求当前轮 trace 存在成功的 `get_balance` read。历史消息、失败读取和其他工具均不算。明确标注历史、用户引语和金额举例的分句保留，其他分句的当前声明仍逐一检查。缺失时最多纠正一次，由模型选择工具；再次缺失就返回“本轮未能核实当前现金余额”，不回显无依据金额，不自动选工具或执行写操作。工具预览附带的无依据金额正文改为无法核实的说明，保留待确认预览，不为纠正正文额外调用模型或重复操作。两条路由路径共享该模型循环，原当轮读取复用保持不变。

评测器现在对冻结 `expected_actions=[read]` 强制要求成功读取 trace；允许澄清/read 多种动作的轮次仍需语义复核，不从正文猜测动作。冻结案例、实际第二批原记录和评分不修改。

## 验证与限制

新回归先复现历史金额正文绕过新读取，以及必读轮次无 trace 仍结构通过；修复后验证当前读取、一次纠正后安全停止、失败/无关读取拒绝、必要澄清保留。测试使用脚本 LLM、本机假 billing 与测试数据库，不发真实模型或 JEV 请求。

这是针对显式中文现金金额的有限一致性守卫，不是通用事实校验器：不声称覆盖中文大写金额、英文表述、未输出数字的“余额不变”等语义，也不核对模型复述数值与工具数值是否相等。纠正可能增加模型调用；既有调用及预算守卫仍约束每次请求，不能为通过测试提高旧付费上限或删除原领取记录。

代码尚未部署到运行客服，也没有执行新付费重测。后续真实复测必须绑定新的代码和执行计划，明确批次/调用预算与授权，不得复用已经消耗的第二批领取记录。历史第二批在原审核版本的报告继续保留；新评测器可能对同一原 journal 给出更严格的结构失败，不覆盖旧档案。

另用新评测器离线重放第二批真实原始 journal，两臂均报告 `structural_pass=false`、`read action lacks a successful read trace`，金额事实仍无错误。脱敏验证绑定原 journal SHA 和修改源码 SHA，见 `eval/paired-pilots/2026-10-23-balance-read-fix/replay-validation.json`。这证明新检查能捕捉实际缺读，不是修复后模型行为的真实重测结果。独立审查发现的历史解释误拦截与预览正文绕过均补了先失败后通过的回归，复审无剩余重要问题。

最终验证：`SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk go test ./...` 退出 0，18 个测试包通过；客服与 taskbench 的回归、实际日志离线重放及独立复审均完成。本轮新增真实模型/JEV请求均为零。
