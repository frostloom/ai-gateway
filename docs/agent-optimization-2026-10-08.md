# 客服优化实验记录（2026-10-08）

## 目标与证据规则

用户指定无 JEV 历史结果为 V1，有 JEV 历史结果为 V2；优化过程需要成为面试中的可复核证据。两组原始数据、失败、样本、评分版本和报告必须保留，禁止覆盖、筛掉失败、修改标签或把澄清计入原有 Top-1。新的实现记为 V3，JEV 开关分别单列，不将不同代码版本的差异称作 JEV 因果收益。

## 已复现与根因

- Docker MySQL/Redis 启动后，当前提交 `b266428` 全量 Go 测试通过；此前集成测试失败来自基础设施未启动。
- 明确要求「订阅月度旗舰」「换成旗舰」的样本，工具 schema 强制模型先查询内部 `plan_id`，导致合理流程被首工具指标判错，同时多出一次模型往返。
- 充值、退款、订阅和改套餐有大量真实缺少金额或套餐的请求。安全反问不能为了指标改为猜参数。历史 `ask_back` 标注并不完全准确，保留数据并单独解释，不能据此宣称所有低命中都是真实失败。
- JEV 合法性问题将“本人账户业务”定义为正常，未明确接纳闲聊和一般咨询，历史出现九次非业务请求误拦。
- 写守门拦截后将结果回填给 LLM 继续循环，模型可能重试被拒动作或引导再次确认，增加调用和绕过安全判断的风险。

## 实施顺序与验证路径

1. 原始五份 V1/V2 产物以确定性 gzip 和 SHA-256 清单归档到版本管理目录；归档验证工具检查字节完整性和两组配置一致性。原路径保持不变。
2. 使用失败回归测试驱动套餐名称解析：服务端按实时目录唯一解析并冻结 ID，兼容既有 ID，拒绝冲突、歧义、下架和缺参数，不执行写操作。
3. 调整提示词：参数明确时直接调用业务工具，退款工具自己读取实时余额；参数不足仍澄清。调整 JEV 问题定义，区分“非业务”与“越权”。保持既有阈值，避免通过降低安全要求刷指标。
4. 写守门拒绝立即结束当前轮次，保留真实工具 trace 和审计；回归确认不重复请求 LLM、不挂起、不写入业务。
5. 完整 Go 回归、30 条功能用例、数据集校验。真实模型先抽样检查，再执行独立的新全量实验。保存未通过样本和完整原始报告。
6. 新报告单列 Top-1、Reach、全请求首工具命中率、确认、OOS、误拦、延迟、真实调用次数；补充澄清和参数充分样本分析，主评分公式与数据集保持不变。有效模型凭证恢复后，再加入独立业务 fixture、多轮真实执行和未参与开发的新说法验证；本轮不能宣称已经完成这些在线验收。

## 可归因性边界

历史模型别名、上游服务负载和租户状态可能随时间变化；V2→V3 历史对比属于观察结果。归档里未记录评测时 Git 提交，不倒推捏造。预算和工具次数不等于 token 或费用；单轮挂起不等于最终资金与订阅操作成功；20 条对抗样本不能证明全面安全。

## 已实现与回归证据

- 套餐工具接受用户指定的 `plan_name`，根据当前在售定期套餐目录唯一解析；拒绝歧义、下架、未知、ID/名称冲突和小数 ID。预览冻结服务器解析后的 ID，确认时保持同一对象；兼容旧 ID 入参。单独红测曾暴露旧实现缺名称入口和冲突校验，修复后定向测试通过。
- 安全守门拒绝后直接结束当前轮次，保留真实 trace、审计和拒绝文案；不会让模型重新尝试或诱导用户确认被拒动作。新增回归先因“脚本耗尽，发生预期外 LLM 调用”失败，修复后通过。
- 同轮同工具同参数的重复读第一次复用结果，允许“查余额后退款”继续预览；再次重复时停止循环。复用不伪造新的已执行工具 trace，保留协议消息配对；后续轮次重新查询实时数据。直接遇重复即终止的初版会丢复合写请求，独立复核后新增失败回归并修复。
- 明确退款参数时直接调用退款工具，其内部负责实时余额与订单校验；明确套餐名不再要求模型额外查询内部 ID。缺参数仍必须追问，不允许猜金额或目录。
- 报告模板把“错分明细”改为“首工具未命中明细”，注明必要澄清与合理读前置不能直接称业务错误。`EndToEndAccuracy` 的原 JSON 字段与公式保留，新展示名为“全请求首工具命中率（含失败）”，避免误称业务任务完成率。零成功请求明确不可评估；成功对抗比例同时显示总量和失败。
- 功能评测保留原30条，新增5条“追问→补参数→预览→确认/取消”和复合读写场景；新增逐轮回复断言。首版用例误把首轮追问文案放进末轮断言，产生30/35，报告保留；加入正确逐轮验收后35/35通过。假 LLM 测执行层状态机，不证明真实模型理解能力或真实账务最终状态。

## 必要追问的历史修订视图

400条充值/退款/订阅/改套餐请求逐条复核：162条文本槽位充分，224条缺少信息需澄清，14条语义或目录证据不足。V1/V2识别出182/193条必要澄清候选，不能把这些严格首工具不命中当业务错误；自动回复检测仍需人工复核，不把候选与挂起加成“业务正确率”。原始数据和分数均不覆盖。

复核规则、所有样本注释、独立分母和代表样本见 [行为复核说明](intent-behavior-v1-v2-review.md)。伴随规则版本与客服运行V1/V2是不同版本轴，后续变更只创建新版本。状态“已经满足”的回复缺少独立请求时 fixture，保留待复核，不武断计成功或失败。

## 任务评测扩展设计与验证路径

用户随后提供有效官网模型配置，并明确授权模拟账务数据发送给DeepSeek。接口鉴权恢复后，采用同一个`deepseek-flash`模型、相同1220条样本、每组4并发，执行旧代码/优化代码和JEV关/开四组对照。原始历史分数不改写；新实验不是历史模型条件完全相同的重演。

新增独立多轮任务评测，目的为核验真实客服是否完成用户目标，包含必要澄清，不把首工具路径当任务正确率。每个案例使用新建模拟租户，准备可复现充值与订阅状态；不修改原开发租户。步骤为首轮请求、缺参数时补槽、预览校验、确认或取消、独立账本与订阅状态核验。工具名称正确但金额/套餐错误不能确认或通过；写前必须无账务变更。保留每轮原始回复、参数、状态快照和全部失败，不仅检查最终文字是否说“成功”。

指标定义：任务完成数/全部尝试任务数（包含基础设施失败）；缺槽案例的有效追问覆盖；参数充分时的冗余追问独立记录；确认前写入违规、取消无写入、确认后幂等分别核验。任务耗时从首个请求到最终状态核验，排除fixture准备和模拟用户思考时间；保留失败尝试耗时并分别报告全部尝试与成功任务的P50/P95。小型固定任务回归集不能代替大规模独立泛化准确率。

实施顺序：先为错误金额、提前写入、缺槽追问、取消、失败分母等评分行为编写失败测试，再实现`internal/taskbench`与独立命令入口；由独立复核检查账务单位、退订状态过滤、下期改套餐等领域语义；运行单元及全量Go回归后，用同一模型对四组实现运行真实多轮任务。新增案例与评分版本单独哈希，原单轮评分公式保持不变。

## 官网模型实测与任务验收结果

上面的401阻塞记录属于早期实验。用户更新官网凭证并授权模拟余额发送后，鉴权恢复。相同`deepseek-flash`、相同1220样本四组单轮全量均完成，HTTP失败为0：旧/新无JEV的Top-1为61.75%/71.92%，旧/新有JEV为67.67%/71.58%。这些是首工具诊断，不是任务完成率。优化有JEV仍有2条正常业务被拦；20条对抗有1条未达到约束判定，不删除这些失败。

最终独立任务评测使用同一`taskbench.v2`评分器、相同24个固定任务和96个新建模拟租户。核验真实账本、订单、订阅、审计以及Redis待执行状态；必要追问补全后执行，退款上限和下期套餐变更按领域语义验收。旧代码无/有JEV均19/24（79.17%），最终优化无/有JEV均24/24（100%）；四组追问覆盖与追问后完成均4/4，正确预览均19/19，确认前写入违规均0，重复确认均1/1。全部任务都进入分母，HTTP和fixture失败均0。

旧代码五项失败为自然语言取消时只让LLM口头回应，服务端挂起动作未清除；本次没有发生业务写入，但后续确认可能执行。修复执行层明确取消分类，排除否定、问句及新退订意图，复用原有清理和审计路径。新增25个工具与取消说法组合回归证明不调用LLM、不写账务、清除Redis挂起，后续确认不再执行旧动作；实测成功取消从0/5变为5/5。完成率增加20.83个百分点由此状态机修复驱动，不冒称意图识别改善20.83个百分点。

所有24个任务尝试的平均耗时：无JEV旧2.532秒→新2.179秒，有JEV旧3.143秒→新2.677秒；P95分别4.063秒→3.733秒、5.078秒→4.539秒。完整报告另列成功任务与相同成功任务的匹配耗时，避免成功样本组成变化造成误读。任务计时包含实际模型、工具与最终核验，不含fixture和用户思考。四组并行、单次随机模型运行，这些观察不代表生产SLA或JEV的稳定因果收益。

评测本身也保留了修正过程：外部JSON探针字段继承错误由红绿测试修复；初版规则接受名称或固定`套餐#ID`格式，却未接受`#3`、`套餐 #3`等价表达，误拒了正确套餐ID，升级评分为`taskbench.v2`后四组完整重跑。原探针、旧规则结果、全部失败和日志不覆盖。9条冗余追问候选经编码代理复核，均为正确查询后的可选服务提示，不是阻塞任务或必要追问失败。

最新全量Go测试、静态检查、agent/评测器构建均通过。原历史五份、原优化22份、此次96份新证据分别校验原始与压缩字节SHA256；新归档不含API凭证。当前24例是开发回归集，24/24仅证明这些已知任务，不是所有真实用户说法的泛化正确率。后续重点是版本化独立盲测、任务中改意图、语言变体、更多安全样本、故障恢复与重复测量。

完整指标、相同成功任务耗时、追问复核、评分版本说明和原始归档见 [DeepSeek真实任务实验](../eval/experiments/2026-10-08-deepseek-flash/README.md)。

## JEV核心效率目标核对

用户进一步明确项目重点为高置信度场景的降本与提速。相同优化代码开启JEV后，本轮单轮平均耗时2.229→2.554秒，正常请求LLM调用总数2092→2111，正常业务JEV短路为0。当前高置信意图只注入提示，尚未直接路由以省略LLM；确认/取消省略模型属于独立状态机，不能算JEV的贡献。因此这批数据目前证明的主要是安全判定作用，不能宣称已经实现JEV高置信降本提速。
