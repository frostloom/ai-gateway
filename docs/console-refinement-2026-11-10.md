# 模型目录与控制台交互修正

## 模型与定价

用户商城、管理员定价列表和公共 models 接口统一采用启用上游的显式模型编号与定价目录交集。通配符继续用于既有路由，不能将全部预置模型列为可上架商品。billing 启动不再调用自动模型 seed。

新增定价必须选择上游已配置的编号，明确填写输入价、输出价和上下文。后台 API 拒绝遗漏单价，允许管理员明确设置零单价。未配置上游的模型不能通过状态接口上架。创建时默认合法 JSON 标签数组，避免空标签导致 MySQL 拒绝写入。

## 布局与交互

模型定价的右侧详情栏改为居中弹窗。上游编辑使用同一弹窗体系，字段说明放在控件下方，同一行字段顶部对齐。模型编号支持逐行填写，删除使用应用内确认框。弹窗锁定背景滚动、管理键盘焦点、支持 Escape，并在提交中阻止关闭。桌面浏览器量测弹窗中心偏差为 0，同一行控件顶部一致。

工作台保留多轮、流式输出、停止和错误恢复，忙碌时锁定配置。失败或中断消息不进入后续请求历史。手机端折叠设置，390px 首屏可见输入区。

接口调试提供对话、请求 JSON、响应检查，显示 HTTP 状态、Content-Type 和耗时。复制与响应预览脱敏当前 API Key。预览限制 65,536 字符，独立 SSE 单帧和未消费缓冲上限为 1 MiB。超过预览大小的合法回复仍完整显示。

客服浮层补齐视口约束、移动键盘、拖拽清理、关闭后的未读和焦点管理、重置确认与待确认操作防重。

API 接入使用实际目录模型，示例包含本站地址、请求路径、鉴权和参数，去除第三方网站类比与硬编码模型。密钥仅在生成后展示一次，生成下一枚前需确认已保存。

## 评审与验证

使用 frontend-design、Taste、Hallmark 与 subagent-driven-development。code-review 的 Standards 与 Spec 独立只读评审覆盖本轮改动。Spec 补充发现异常 SSE 无终止缓冲和无效 JSON 响应不可检查，两项已修复并复审关闭。

npm run verify 通过。纯替身测试覆盖多轮、UTF-8 单字节分帧、CRLF、尾包 usage、终止符、停止、IME、重复提交、失败历史、坏 JSON、超大未终止帧和 70,000 字符合法回复。客服与接入另有 17 项替身 DOM 检查。

store 全套通过，47.851 秒。gateway handler、gateway middleware 和 billing admin 全套通过，分别 0.919、1.672、3.120 秒。目录定向 race 通过，2.952 秒，保留本机 SDK 版本链接警告。首次 store 运行因新测试固定上游名称与残留 fixture 冲突失败，已改为幂等创建并清理后重跑通过。

Hallmark 六文件、三个页面渲染为 0 FAIL、0 WARN。聊天浮层 21 项既有紧凑间距保留 waiver。浏览器 axe 检查接口调试、工作台和 API 接入均无违规。截图与原始日志位于 .tmp/console-refinement-20261110，展示数据来自本地替身。

本轮没有真实模型或 JEV 请求，未触发历史评测 scope。
