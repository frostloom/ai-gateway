# 线上 Linux 有界压测结果

2026-11-10，在 62.234.106.6 的 Ubuntu x86_64 服务器执行。发生器、HTTPS 入口、模拟上游和应用实例都运行在该 Linux 服务器。Mac 负责交叉编译 Linux ELF 工具和 SSH 控制。

## 环境与边界

- 当前线上镜像 aigateway:refinement-20261110，启动同镜像的隔离实例。共享线上 MySQL 与 Kafka，使用专用数据库、受限数据库用户、Topic 和消费组。Redis 使用与线上相同镜像的独立实例，余额键与生产隔离。
- 应用预算 1.5 CPU / 360 MiB，发生器与模拟上游合计 0.5 CPU / 160 MiB，测试 Nginx 为 0.25 CPU / 64 MiB，测试 Redis 为 0.25 CPU / 80 MiB、maxmemory 48 MiB、noeviction。这些是为共机 Myink 保留资源的测试限额，结果对应此配置。
- 64 个隔离测试租户，容量阶段限流设为每分钟 1,000,000。生产默认每租户每分钟 600。
- 非流式、小请求、max_tokens 16、0 ms 模拟上游，覆盖鉴权、限流、路由、预占、用量结算、Redis、MySQL 批量落账、Kafka 和审计消费者。

256 并发复测达到请求数上限，在约 24.87 秒完成 20,000 次请求，零失败。512 并发为新连接突发，3 次连接超时触发错误保护，剩余在途请求完成后停止，总计 611 次请求。测试入口存在 0.25 CPU 限额，因此此阶段记录的是该保护性配置的接入边界。

## 内存与保护动作

约每 0.5 秒读取 cgroup memory.current、memory.stat、memory.events，以及宿主机可用内存和 Swap。检查生产与 Myink 的容器身份、重启次数和健康状态。

- 宿主机可用内存低于 900 MiB、Swap 增长超过 64 MiB、磁盘不足 4 GiB 时停止。
- 测试实例不可回收工作集达到上限 75%、生产组件达到 85% 时停止。超过 93% 总用量且缺少干净可回收缓存时也停止。Redis 数据内存达到 36 MiB 时停止。
- 超过错误率阈值或 P95 1,500 ms 时停止加档。

| 组件 | 全过程工作集峰值 MiB | 容器内存限额 MiB |
|---|---:|---:|
| 隔离应用 | 209.14 | 360 |
| 发生器与模拟上游 | 69.59 | 160 |
| 隔离 Redis | 37.11 | 80 |
| 共享 MySQL | 403.98 | 450 |
| 共享 Kafka | 467.56 | 768 |

最低宿主机可用内存为 1530.81 MiB，约 1.49 GiB。所有监控周期的新增 oom 和 oom_kill 均为 0。

保护器在预检发现 Kafka 工作集超过旧 520 MiB 限额的 85%，尚未正式发压即暂停。Kafka 上限随后在线调整为 768 MiB，JVM 堆仍为 256 MiB，MemorySwap 总上限保留 1040 MiB，已写入 compose，容器身份和启动时间一致。

第一轮 32 并发因 MySQL 总用量含约 170 MiB 干净文件缓存而触发保守保护。核对 anon、dirty、writeback 和 inactive_file 后，监控改为仅扣除干净 inactive 缓存的工作集，同时保留真实工作集和整机保护，再从 32 并发复测。

最终在 256 并发复测完成后，MySQL 工作集达到约 404/450 MiB，保护器停止进一步加压。内存阈值未被绕过，未继续尝试更高并发。

## 账务与完整性

首轮保护中断的 32 次客户端取消单独保留。它们产生 10 笔未知执行状态的模拟 pending，未伪造退款或结算，后续以这 10 笔作为基线核对。

最终测试库共有 74,055 条预占、74,045 条结算及 10 条已归档模拟 pending，审计 148,100 条。Redis 余额、SQL 余额列和包含 pending 的账本公式一致。

重复 request_id/phase 为 0，outbox 未投为 0，消费者解码和处理错误均为 0。Kafka Reader 的 lag 字段返回 -1，审计完整性依据逐阶段源账单与消费记录数量对齐验证。

## 收尾与验证

测试 SQL 与 Redis 原件压缩归档后，四个临时容器、匿名 Redis 卷、测试库、受限用户及两个测试 Topic 已清理。测试中的虚拟余额与预扣只存在于隔离数据集。

线上网关与全部 Myink 容器的 ID、启动时间、重启次数及健康状态与基线相符，均在运行，HTTPS 用户入口返回 200。Kafka 的内存上限调整保留。

原始结果与内存汇总位于 .tmp/online-load-20261110/results。服务器完整逐样本内存、账务检查、测试数据快照及脚本位于 /home/ubuntu/aigateway/load-tests/online-20261110，权限限定当前用户。

本轮真实上游模型与 JEV 请求均为 0。
