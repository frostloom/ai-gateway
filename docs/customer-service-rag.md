# 客服知识检索

客服保留现有 JEV 策略。确认、取消、确定性的直接查询、高风险拦截和无关内容拒绝均先执行；只有进入 LLM 循环才进行知识检索。

进入 LLM 后，用当前问题预取最多三段公共知识，并将其作为不可信参考附在系统消息中。模型保留 `search_platform_knowledge` 只读工具，可以用更具体的问题补查。资料不能授权操作，也不能替代实时余额、账单、模型价格和订阅查询。

## 配置与维护

```sh
AGENT_KNOWLEDGE_ENABLED=1
AGENT_KNOWLEDGE_DIR=knowledge/platform
```

默认关闭，兼容既有评测入口。启用时校验语料清单及每份资料的原始字节 SHA-256，不通过就拒绝启动。更新 JSON 后执行以下命令，审核资料及 manifest 后一起提交并重启 agent：

```sh
go run ./cmd/knowledge-manifest -dir knowledge/platform
go run ./cmd/knowledge-manifest -dir knowledge/platform -check
```

公共资料不含用户数据或密钥。上线前须核对付款、订阅和计费规则是否与当前源码一致。

## 分词、召回和缓存

采用中文业务词、汉字二元组回退及英文/API 标识符分词，预建段落索引，按标题、别名和正文权重排序。最多返回三个段落，同时限制单段与整体结果大小；未命中明确返回 `no_match`。这是一套本地词法检索，不依赖外部 embedding 服务。

缓存只保存公共检索结果，按语料版本、检索版本与规范化查询的散列隔离，最多 256 项，五分钟过期。返回结果深复制，避免跨请求修改；不缓存模型回答或账户实时事实。稳定的系统指引可供上游自身的前缀缓存利用，但实际命中和费用取决于上游。

遥测记录检索次数、缓存命中、资料版本和发送给模型的来源。Langfuse 区分召回、纳入请求以及供应商响应/失败，不把检索命中当作模型正确采用资料的证明。资料正文记录继续遵守现有内容采集开关和脱敏规则。
