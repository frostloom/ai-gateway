## 当前数据不能证明高置信度降本提速

必须在相同优化代码、相同模型和样本下比较开关，不能把旧代码→优化代码的收益全部归到JEV。以下为取消修复前优化代码`1a7a729`的同条件单轮实测：

| 指标 | 无JEV | 有JEV |
|---|---:|---:|
| 正常请求数量 | 1200 | 1200 |
| 平均实际LLM请求次数 | 1.7433 | 1.7592 |
| 正常请求LLM调用总数 | 2092 | 2111 |
| JEV实际调用总数 | 0 | 1454 |
| 正常请求未调LLM的JEV短路数 | 0 | 0 |
| 平均单轮耗时（秒） | 2.229 | 2.554 |
| P95单轮耗时（秒） | 4.167 | 4.593 |
| 20条对抗的约束判定通过数 | 17 | 19 |
| 正常业务请求被拦数 | 0 | 2 |

开启JEV后平均耗时增加约325毫秒（14.58%），LLM请求总数没有下降。这是单次并行实验的观察，不能当作稳定因果收益或生产SLA。目前不能写“JEV已经降低成本、加快响应”。对抗约束结果15/20→19/20体现这批样本上的安全判定作用，样本小且存在漏判与误拦，不等于全面安全能力。

根因见`internal/agent/guard.go`和`internal/agent/chat.go`：正常高置信度意图目前仅生成提示交给LLM；直接省略LLM的JEV分支是前置安全拦截。正常业务没有高置信度直接执行读工具/返回结果的快路径。多轮确认/取消直接执行是独立的确定性状态机，无JEV也存在，不能把它省下的模型调用算作JEV收益。

现有遥测只记录调用次数和总体请求时间；没有保存意图置信度、JEV/LLM阶段耗时、上游token usage和实际费用。无法从旧数据补造“高置信度子集的真实成本收益”，也不能将1次调用当作相同token成本。实际费用还取决于输入输出、缓存、重试和JEV自己的计费。

## 聚焦JEV核心价值的下一轮验收设计

目标架构：高置信度且通过独立安全校验的单一明确请求走JEV直接路由；复杂、缺参数、低置信或不支持的请求回退LLM；写操作继续遵守参数校验和用户确认。首先限定安全的读取请求，返回来自实时工具的自然语言结果，不猜写参数，不吞掉复合任务。不用低置信度放宽来换短路率。

这属于待实现/待实测的升级设计，以下项目不是现有系统已经达成的指标：

| 价值维度 | 必须记录的指标 | 约束 |
|---|---|---|
| 置信度与分流 | 意图分值、阈值、候选/接受/回退原因、按区间的覆盖率与正确率 | 分值未校准前不称真实正确概率；保留回退和错误样本 |
| 节省模型调用 | 合法业务快路径率、未调用LLM的成功任务比例、匹配样本减少的实际LLM请求 | 安全拦截与正常业务快路径分开；确认/取消状态机收益单列 |
| 降低实际成本 | 逐次输入/输出token、缓存命中、重试、JEV用量与单价版本；每个成功任务的全部尝试成本 | 总成本 = JEV + LLM + 重试/失败，不把JEV视为免费；无价格/usage时明确不可评估 |
| 缩短响应时间 | JEV判定/LLM/工具阶段耗时、全链路P50/P95、同一高置信度子集的匹配耗时 | 不能用“所有有JEV快请求”对比“所有无JEV复杂请求”；计入JEV多一跳与回退开销 |
| 保住业务质量 | 独立状态任务完成率、必要追问覆盖及补槽后完成、误路由、正常误拦、对抗漏判 | 同数据集，同fixture，同执行守门；质量下降不能只展示节省比例 |

对照应为同代码下三组：无JEV、JEV仅提示/守门、JEV高置信快路径，区分判断本身与快路径实现的贡献。冻结原1,220例作回归，另冻结未用于开发的多轮盲测；交错多次运行并保存全部原始轮次。应同时展示全量净收益与快路径匹配子集收益：覆盖率太低时，即使命中请求很快，整体仍可能更慢或更贵。

面试叙述应建立在实际记录上：当前已验证安全判定与完整账务执行；项目接下来的核心升级是让JEV承担高置信请求的直接路由，再用正确率、覆盖率、净成本和全链路时间共同验收。当前不将该升级设计写成已完成成果。
