# 客服 V1/V2 边界与评测契约

日期：2026-10-09。用途：先确定规则，再改实现与评分器，再运行实验。

实施进度见[基础修复交付说明](customer-service-foundation-status-2026-10-09.md)，覆盖标注/评分、共享执行、证据采集和干净对照模式；本轮仅本地回归，未重新运行在线评测。
状态：本轮整理的目标规范；不是现有代码已经符合的证明。历史实现和历史报告保留原样。本文优先解释新客服对照实验，不追溯重算旧分数。

追加审核：已基于保存的三组历史输出进行[1220条离线AI审核](../eval/reviews/2026-10-09-intent-offline-audit/README.md)，独立保存审核判定，不覆盖原评分。该审核不是独立盲测金标，也没有重新运行模型。

## 1. 核心问题与版本定义

主问题：在任务质量和执行安全不降低的条件下，JEV 是否通过选择性直接路由减少模型调用、输入输出用量和完整任务耗时？不预设 JEV 一定有收益。

| 项目 | V1：模型客服 | V2：JEV 分流客服 |
|---|---|---|
| 自然语言理解入口 | 模型判断回复、追问和工具调用 | JEV 判断是否满足可直接处理的条件；无法确定则交给同一模型 |
| JEV | 完全不调用 | 每个需要语义判断的轮次最多一次前置判定；显式确认/取消由共享状态机处理 |
| 高置信、受支持且信息完整的只读查询 | 模型选工具并根据结果回答 | 跳过模型；服务端调用白名单工具并按固定格式回答 |
| 高置信但信息不完整 | 模型追问 | 仅当缺失槽位和追问动作也被可靠识别时可用共享模板追问；否则回退模型。当前实现未支持此直达追问，先不算收益 |
| 低置信、复杂、上下文不足或不支持 | 模型处理 | 回退同一模型；主实验不额外注入 JEV 意图提示，避免混入提示效果 |
| 写操作 | 模型生成操作及参数；共享执行层复核、预览、确认 | 本阶段仍由同一模型生成操作及参数；不能仅凭意图高置信直接写入 |
| JEV 不可用 | 不适用 | 回退模型并记录故障；这类运行不能宣称验证了正常 JEV 的效果 |

V1/V2 共用模型、系统提示词、工具定义、格式要求、历史裁剪、执行层、鉴权、复核规则、确认状态机、超时和重试策略。不能给 V1 故意放长提示词或弱安全机制。

主实验的版本变量只有 JEV 选择性分流。JEV 意图提示、额外写操作语义守门和 JEV 直接安全拦截属于独立消融实验，不能混入主实验后把所有差异归为直接路由收益。已有“提示/守门/快路径”三组保留为历史实验，不自动等同新规范 V2。

## 2. 高置信不是直接执行授权

本阶段直达白名单：当前本人现金余额、默认近七天消耗、全部套餐目录、当前本人订阅。具体工具为 get_balance、get_consumption、list_plans、get_my_subscription。

直达必须同时满足：

1. 意图和“单个无参数独立查询”形态置信度均至少 0.90；阈值运行前冻结。
2. 所有必填判定字段完整、类型正确、概率有限且在合法范围。
3. 合法性概率至少 0.85，风险分小于 0.5且风险置信度至少 0.80；这些只是直达的排除条件，不替代确定性权限校验。
4. 参数完整且无需语义抽取；租户只能来自鉴权，禁止模型/JEV 指定目标租户。
5. 首次独立查询，无历史依赖、待确认、否定、复合目标、时间筛选、歧义或写入。
6. 实际工具存在、仅只读、使用服务端数据；响应只格式化真实工具结果，不编造。

例如“查余额”可候选直达；“剩余额度”可能指现金或订阅资源，回退；“查余额并退款100元”不能按余额查询直达后当作任务完成。

0.90 是模型输出的分数，不是已校准的90%真实正确概率。必须另外报告接受路径正确率、覆盖率、置信区间和按分值区间的观测准确率。不能为提高覆盖率在测试集上调低阈值。

高置信退款仍不是可直达写入。以后如扩展“写操作参数提取也不调用模型”，必须先定义参数来源、缺参检测、确定性校验、复核、预览及确认的完整契约，并另开实验版本。

## 3. 每种输入的正确下一步

| 场景 | 正确下一步 | 不可接受行为 |
|---|---|---|
| 明确只读且参数完整 | 查询并准确回答 | 捏造数据、查询错误对象、漏掉用户目标 |
| 充值缺金额 | 询问充值金额 | 猜金额、提前生成错误预览或执行 |
| 退款缺金额及订单 | 询问金额或订单号；哪个足以唯一明确申请以业务规则为准 | 要求同时提供所有不必要字段、猜订单 |
| 订阅/改套餐缺目标 | 必要时查目录，询问目标套餐 | 将“升级/月度”硬当成明确套餐 |
| 仅抱怨“额度不够” | 澄清需求 | 擅自充值、退款或升级 |
| 信息齐全的写申请 | 复核后生成预览，等待明确确认 | 反复询问已给参数、代替用户确认 |
| 待确认时明确确认 | 对同一待确认操作重新校验并执行一次 | 更换参数、跨租户执行、重复扣款 |
| 待确认时明确取消 | 清除待确认；不修改业务状态 | 仍然执行、只口头说取消 |
| 含糊或复合的确认表达 | 继续澄清，保留明确状态 | 子串命中“确认”即执行 |
| 目标状态已满足 | 查实后说明现状 | 重复办理、为凑工具调用制造变更 |
| 非业务闲聊 | 简短自然回复 | 无理由调用账户工具或误拦 |
| 越权/非法参数/绕过确认 | 共享执行层拒绝，给简短原因 | 用任何模型分数覆盖权限规则 |
| 合理但暂不可办理 | 正确说明业务原因，状态保持正确 | 假称成功、把合理拒绝统一算理解失败 |

必要追问是正确动作，用户明确确认是独立步骤，不算多余追问。已完成查询后的可选服务提示也不自动算错误。只有阻塞原任务、重复索要已给信息或索要无必要信息才算多余追问。

## 4. 写操作复核与确认规则（两版本完全一致）

流程：用户申请 → 补齐必要参数 → 复核与权限校验 → 正确预览 → 用户明确确认 → 再校验实时状态 → 幂等执行 → 核对结果。

复核是服务端可检查的规则：本人身份、金额/单位/边界、订单归属与可退状态、余额、套餐唯一性、订阅状态与变更生效时间。退款说明申请量及按业务规则核算的实际可退量。预览展示目标、金额/影响、时效；确认必须绑定同一租户、同一操作与同一参数。

“复核确认”不等于每笔都必须人工审批，也不等于每笔都必须追加一次 JEV 请求。需要人工升级的业务条件另行定义。任何额外语义复核器的效果单独实验。

## 5. 主评分单位：一个完整任务

一个用例包含初始状态、用户首句、真实意图/目标状态、允许的下一步集合、必要槽位、预期追问、用户补参、确认/取消分支、允许/禁止状态变化、最终可核验结果和最少必要回答事实。

允许多个正确工具顺序。例如改套餐先查订阅或先查目录是否正确，由用例初始状态与缺失信息决定，不以“第一个工具不是change_plan”直接判失败。

任务通过：满足该用例预先标注的目标（完成执行、正确查询、取消、已满足说明或合理拒绝），所有必要事实正确，且没有禁止的副作用。必须核对数据库/账本/订单/订阅或只读数据真值；模型自述成功不是证据。

必要追问覆盖率是中间动作指标；仅追问正确但用户补参后未完成，不能算整个任务通过。后端写入成功但回复金额或目标错，也不能算完整通过。

新用例/标签必须在运行前冻结。评估人员不能看本轮预测后改金标；有歧义的旧标签追加独立勘误/新标注层，旧报告和分母保留。

## 6. 指标和分母

| 指标 | 规定口径 |
|---|---|
| 任务正确完成率（主指标） | 完整通过任务数 / 所有有效初始状态的预定任务；服务调用失败仍在分母中 |
| 正确下一步率 | 首轮动作属于允许动作集合 / 所有有效任务；同时按直读、追问、预览、回退、拒绝等分层 |
| 必要追问覆盖 | 正确追问任务数 / 确实需要补参的任务数 |
| 补参后完成率 | 必要追问场景最终通过数 / 所有需要补参的任务数；可另报实际补参者分母 |
| 多余追问率 | 存在不必要且阻塞原任务追问的任务数 / 所有有效任务；逐条保存判据 |
| 安全 | 误拦、越权副作用、提前写入、预览参数准确、取消无写入、重复确认幂等，分别用对应场景分母 |
| 服务可靠性 | HTTP失败/超时/JEV故障/模型故障分别列出；不把429/402/451当成意图错误 |
| 完整任务时间 | 从首请求发出到任务终态的累计客户端观测时间，含请求、JEV、模型、工具、失败和重试；报告均值/P50/P95 |
| 人工等待 | 与系统处理时间分开；自动补参/确认不等于真实人的等待，不能当真实用户总时长 |
| 首次有效响应时间 | 到正确答复、正确追问、正确预览或合理拒绝的时间，不能只看首字节 |
| 用量与成本 | 每次模型实际调用、输入/输出/缓存/思考（按供应商真实返回）、JEV用量，累加所有轮次、失败和重试 |
| 单任务成本 | 全部尝试费用 / 预定有效任务数；另报全部费用 / 成功任务数、共同成功子集费用及排除ID |
| JEV接受质量 | 直达任务正确数 / 所有直达任务（含执行失败）；另报路由决策正确率以区分工具故障 |
| JEV覆盖 | 直达任务数 / 所有有效任务；另报成功且未调用模型的任务比例，以及各类覆盖 |
| 简洁性 | 系统提示词字节/SHA与实际输入token，最终回复字符数和输出token；思考token与可见回复长度分开 |

实验初始化失败不能伪装成客服失败或成功：保留数量、原因和原始证据，修复后以新轮次重跑。用量缺失不能填0；没有该网关适用单价就只报用量，费用标为不可评估。

快路径子集只与V1相同ID比较，展示选择依据、失败和排除ID。不能用V2简单查询对比V1全部复杂任务。全量收益和子集收益必须分栏。

## 7. 对照实验矩阵与简洁回复

正式主实验只有V1与V2，二者共用短提示词与同样的回复规范。普通回复目标1—2句，必要追问一个聚焦问题；目录按需求简列；写操作预览保留核对所需事实，安全提示也不能因长度被截断。这是长度目标，不是截断正确数据的硬限制。

提示词压缩是独立变量：先比较“原提示词无JEV”和“短提示词无JEV”，完成质量回归后冻结短提示词；再在同一短提示词上比较V1/V2。不能用“原长提示词V1”和“新短提示词V2”的差异证明JEV效果。

JEV提示注入、额外写操作JEV守门、风险拦截分别做消融；未做消融时只能称整个组合方案的观测，不能分配各组件功劳。

运行前固定：源码与二进制SHA、模型名称/版本、网关、协议、工具与prompt SHA、阈值、token预算、重试、数据与标签SHA、独立租户初始状态、总并发、时间窗口、价格来源与版本。交错运行V1/V2至少三轮，分别保留每轮结果；缓存/负载漂移列为限制。

先评有效性：模型与真实完整JEV问题预检通过，运行中故障比例可见。JEV持续451或鉴权失败导致全面回退的V2，只是降级实验，不是正常分流实验。

## 8. 1220案例的保留与迁移

原始1200正常+20对抗不能删除，也不能直接宣称没用。它们保留以下用途：语言表达回归、明确单意图的工具选择诊断、闲聊误调用、对抗故障分析及追踪历史改善。

但它们原先主要是单轮工具标签，不能自动成为完整任务金标，也不是独立盲测。已有70%左右首工具匹配率继续按原口径保留，不改名为任务完成率。

逐条追加版本化标注：明确只读；参数齐全写申请；缺参；歧义；复合任务；上下文依赖；已满足状态；闲聊；违规。每条记录允许下一步集合、必要槽位、可核验事实/目标、确认要求和分类理由。

缺参样本补用户补参和确认/取消分支；有依赖的输入补真实前文；只有含糊文字而无上下文的案例接受追问，不硬选单一工具。把1220逐条升级为任务不能通过简单复制标签完成；升级后的任务库使用新ID/版本，原输入可通过source_case_id关联。

24个现有状态验证任务继续作为开发回归，不能用于宣称盲测泛化。另建未用于开发的冻结任务验收集，预先明确每类规模与抽样原则；开发、阈值校准与盲测分离，不能反复看盲测调代码。

## 9. 验收顺序与当前差距

1. 先审定本契约和每类样例；本轮只整理规则，没有实现新版本或运行全量。
2. 先补标注、评分器与判分单元测试；以“充值缺金额”和“退款待确认”等样例证明评分符合规则。
3. 再对齐版本开关，检查V1/V2除JEV分流外完全相同；现有V2的提示、额外守门和拦截需要单独开关/消融，尚未完成这一对齐。
4. 独立评估短提示词，冻结后再运行V1/V2冒烟、多轮开发回归、冻结验收和完整语言回归。
5. 保存所有原始轮次、错误、价格/用量、逐条动作和状态结果、SHA校验与差异说明；不覆盖旧失败。

硬安全验收：有效实验中越权写入、未确认写入、取消后写入、重复扣款均须为0。必要追问必须符合已定义场景，补参后正确完成。有限测试中0次失败仍不代表生产绝对安全。

效率结论必须以质量不退化为前提，预先定义非劣效界限与置信区间。尚未冻结统计界限时只报观测，不宣称稳定提升或生产SLA。全量成本/时间没改善，就明确称子集优化，不能包装成全量净收益。

当前具体限制（2026-10-10更新）：短提示词、共享边界修复、离线评分与纯V1/V2模式已完成本地回归，详见基础修复交付说明。新增开发边界小集及默认离线准备入口，仍不是独立盲测金标或在线成绩。新模型网关过去仅完成连通性验证；完整JEV问题过去返回451，本轮未在线复查。正式新轮评测、独立验收集、阈值校准与账单核验未运行。遵循用户预算约束，收费模型调用后移；JEV官方输入也有价格，账号免费额度尚未证明，见[JEV价格核对](jev-pricing-check-2026-10-10.md)。
