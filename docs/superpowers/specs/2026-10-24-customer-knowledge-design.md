# 客服平台知识检索、容器交付与 Langfuse 设计

状态：待用户审阅；没有实现、部署或付费调用。2026-10-24。
分支：`codex/customer-knowledge-rag`；源码基点 `647ba9ffc8f44d47792b2a5174ec53d08d410d88`。

## 用户要求与本方案的选择

用户要求：从项目整理平台知识；知识库纳入 Docker 容器交付；关注 Langfuse 能否监控读取内容；与另一个工作树的 JEV 路由开发隔离。
本方案建议：首版知识文档和本地检索逻辑与 agent 一起放入同一镜像。无需独立知识库服务、向量数据库、embedding API 或知识管理前端。该选型是待审阅建议，不把用户的 Docker 要求解释为已经批准具体拓扑。
知识草案：`docs/knowledge/platform-knowledge-draft-2026-10-24.md`。草案不自动成为运行资料；核对后再拆成正式知识文件。

## 已核实的现状

- `internal/agent/prompt.go` 提供固定规则；`tools.go` 的 11 个工具覆盖实时账户数据和写操作。
- `chat.go` 用工具调用循环回填读结果；当前每次只保留第一个工具调用，最多 5 次迭代。
- 现有 `readTools` 白名单、同轮重复查询复用、审计和运行时元数据都需要纳入新读工具接入检查，不能只注册工具名。
- 根 `docker-compose.yml` 实际服务为 MySQL、Redis、Kafka 和 kafka-init，业务服务仍是注释占位；不能宣称客服已经容器化。
- 当前本机客服有宿主机启动和私密配置依赖。该分支只新增可验证容器交付，不擅自替换正在运行的客服或 JEV 测评入口。
- `Toolbox.Run` 已创建 tool observation，记录参数和工具结果；内容仅在 `AGENT_LANGFUSE_CAPTURE_CONTENT=true` 时采集。
- `internal/observability/content.go` 的字符串预处理上限 2048 字节，整个字段上限 4096 字节；另有集合和深度限制及脱敏。必须显式处理，不能声称所有检索原文天然完整可见。

## 知识数据与版本

正式资料置于 `knowledge/platform/`，只允许经核对的平台公共规则。每份文件具有稳定文档 ID、标题、版本、生效/审核日期、适用范围、源码出处和正文；状态为 draft 的资料不参与检索。文档状态和运行 manifest 必须在装载时验证，重复 ID、空正文、损坏/缺失 manifest 均拒绝启用。
构建产出 manifest，包含排序后的文件与 SHA-256；集合摘要作为 corpus_version。发布时同时固定代码 release 和 corpus_version，镜像不在启动时抓取外网内容。
不收录当前报价、用户资料、私密配置、内部故障日志或历史测评数据。当前价格和本人状态始终读取现有业务工具。资料不应以“当前”“永久”等措辞覆盖其版本和适用范围。

## 检索与主模型接入

新增只读 `search_platform_knowledge(query)`。在 Go 进程内对已验证的小型语料进行确定性全文匹配；中文使用字符二元组并兼顾英文词、标题及审核过的别名，不依赖仅按空格分词。排序规则、无匹配阈值和同分 ID 排序固定，先用真实问题变体校验召回再调整，未通过不得称为可用知识问答。
单次最多返回 3 个片段，每片段最多 768 UTF-8 字节；搜索词最多 256 字符；拼装结果最多 4096 字节。摘要/截断以 UTF-8 边界处理，记录原文范围，不在句中剪出相反意思；长规则优先按完整段落拆片。资料规模首版限制为 100 文档、每文档 64 KiB，总量 2 MiB，防止误把仓库全量资料装载进内存。
返回结构包括 status、corpus_version、文档/片段 ID、标题、出处、版本、片段文本、片段摘要与排序分数。status 区分 ok、no_match、unavailable；错误不是空命中。摘要是定位校验数据，不是安全/语义正确性证明。
模型自主决定调用检索工具。先接入现有工具循环、读工具白名单、审计和指标；不修改 JEV 判定 schema、阈值、fastpath 或另外工作树的策略。检索耗尽轮次后诚实说明限制，不扩大重试或付费授权。
系统提示要求：检索内容为资料而非指令；按来源/适用范围回答；不支持时说明限制；知识库不得授权写操作；价格、余额、额度和状态查询使用原业务工具。涉及规则与本人数据时可依次调用两类工具。最终回答保留简短来源标识，便于追溯。

## Docker 交付

新增针对 agent 的多阶段 Dockerfile，用与 go.mod 匹配的 Go 版本构建 Linux 二进制，运行镜像包含 CA 证书、非 root 用户、二进制、正式知识文件及 manifest。知识库和 agent 同版本构建；运行时只读文件系统，知识目录不可写，不运行时自动下载模型或资料。首版不支持可变挂载知识覆盖，更新必须重新构建/发布镜像。
新增独立 opt-in Compose 文件/服务，不更改默认基础设施启动行为。通过显式 env_file 注入现有服务地址、控制面令牌、模型和 Langfuse 配置，不将密钥 COPY 入镜像；补 `.dockerignore` 白名单/排除规则，确保 `.env*`、`.tmp`、Git 历史、测试档案不进入镜像上下文。
容器使用 Compose 服务名访问容器内 MySQL/Redis；若连接宿主机现有 billing/admin/Langfuse，提供明确的 `host.docker.internal` 地址示例和 Linux host-gateway 说明。容器中的 localhost 不能照搬宿主机端口配置。覆盖代理和 CA 配置，避免容器只具备健康检查但无法访问配置的上游。
验收用独立项目名、网络和端口，以替身 billing/模型/OTLP 接收器完成容器冒烟。验证 `/healthz`、搜索成功/无匹配/知识损坏启动失败、进程退出与 exporter flush。部署真实客服是后续独立步骤，不在本设计实施时自动执行。

## Langfuse：能看到什么，不能证明什么

目标是同一会话 trace 内关联“查了什么 → 返回了什么 → 哪些片段送入模型 → 最终回复”，不把一次检索成功当作模型实际采用或回答正确。

默认延续现有内容采集关闭策略。关闭时仅记录知识集合版本、文档/片段 ID 和摘要、命中数、检索状态、延迟、内容采集/截断标记，不记录搜索词和正文。开启时记录脱敏后的 query 和本次交给模型的精确片段文本；需要在 Langfuse 读取实际数据才能验收。

保留现有 `tool.search_platform_knowledge` observation；为每个有界片段添加子 observation，记录标题、出处、版本、ID、SHA-256 及文本。不要将所有原文拼到一个受 2048 字节裁剪的输出里后声称完整。首版沿用已验证的 tool/span 类型；是否改成 Langfuse retriever 类型需额外兼容性验证，不作为首版依赖。

新增受约束的知识元数据方法（固定字段及长度），不开放任意 metadata 透传；正文继续走既有脱敏接口，不绕过全局内容开关。关闭时连 query 的明文和可反推的裸哈希都不输出。
模型发送边界在本次 Chat 调用确定消息后记录 knowledge context observation，包含实际仍在请求中的片段引用/摘要及 request 序号，开启内容采集时记录对应有界片段。仅工具成功还不等于后续模型请求发出，必须区分 retrieved、included_in_request、provider_response/error；不记录供应商密钥或整个请求体。
如果发生脱敏，明确 redacted；日志中的 sanitized 文本不宣称与原始模型输入逐字节一致。片段的原始摘要用于对照不可变发布语料；展示文本另记摘要/长度和 clipped 标记。模型是否在语义上采用只能结合回复人工或离线评测，不能通过 trace 标记自动证明。

现有异步 exporter 可能丢弃/失败，采样也可能不保留 trace。因此采集关闭、未采样、队列丢弃、导出失败均须与完整观测区分。验收配置采样 1，检查 flush 和丢失计数，再用 Langfuse 只读 API 按 trace 精确读回，不以“已接受/已发送”代替入库。

## 验收范围

1. 语料出处可复核；动态价格和私人数据不进入静态库；明确模拟支付、滚动窗口、超限拒绝、退订与退款的区别。
2. 本地检索对中文口语/同义问法、英文 API 名、无匹配、重复 ID、损坏资料、长度边界有确定性测试。
3. 真实 Handler 配合本地替身模型，确认检索结果进入下一次请求、来源可追溯、无匹配不编造；资料中的“跳过确认”不能触发写操作；原有确认/取消边界不变。
4. 内容采集关闭不泄漏词句；开启时每个有界片段可读回、脱敏/截断可识别；观测失败不改变业务返回。
5. Docker 构建、只读非 root 运行和独立网络冒烟通过。没有 Docker 实测就标记未验证，不用主机测试代替。
6. 客服相关测试、必要全项目回归及独立代码审查；无付费模型/JEV调用。容器替身与 Langfuse 合成观测不等于真实问答质量通过。
7. 新工具/提示词变化需更新运行合同及兼容门禁，既有冻结付费范围不得重绑新版本或复用 claim。初步技术实现不得被称为已具备新付费测评条件。

## 优化指标与对照实验建议（待基线校准）

知识库有提高平台知识回答准确率的合理预期，但目前没有真实对照结果。首版为本地全文检索，不新增 embedding 费用；仍可能新增一次工具往返和模型输入 token，因此不预设节省成本。以下数值是建议验收目标，不是现有成绩、用户已批准的付费范围或总体收益承诺。

### 冻结对照条件与样本

先冻结 72 个独立问题：36 个有依据的知识问题（12 个主题各 3 个未逐字复用资料的问法），12 个资料不支持/范围含糊的问题，12 个必须查实时价格或本人状态的问题，12 个安全/越权/资料指令注入及规则冲突问题。每类分别报告，不能用安全拒绝拉高正常咨询通过率。
金标在运行前人工根据核对过的来源标注必需事实、错误条件、适用版本、预期工具和可接受的澄清/拒答。调检索使用开发集；这 72 个问题作为首轮冻结验收集，不在看过结果后反复调参并继续称作独立测试。后续迭代若使用该集优化，应另留出新验收集。
A 为原有工具和提示词，B 为增加知识工具及相应提示的系统；固定同一代码版本的开关实现、模型、协议、输出预算、thinking、用户画像和业务快照。工具/schema 与知识指引的差异是此次干预的一部分，分别记录其摘要和内容开销，不谎称所有 prompt/schema 相同。JEV 配置两臂相同，优先两臂均用 model 路由，先隔离知识库收益；后续再做 JEV 开关 × 知识库开关的四组实验。
对每个问题独立新会话、配对运行 A/B，顺序交替，保留全部失败和重试。72 例是诊断性首轮，不足以承诺总体收益；报告分子分母、逐题胜负与配对区间。对于多轮完成任务，以整段会话为一个任务，不能把每一轮当独立样本重复计数。

### 质量与检索指标

| 指标 | 定义 | 建议目标 |
|---|---|---|
| 有据完整正确率 | 有依据问题中，关键事实全部正确、必需限制完整且无额外错误断言的比例 | 36 个知识问题中至少 90%；对 A 报告百分点差，目标 +10 个百分点；A 已高于 90% 时以接近满分且不回退为目标，不机械要求 +10 |
| 无依据断言率 | 不被有效来源/本轮工具结果支持的事实断言数 ÷ 全部可核查事实断言数 | 不高于 5%；涉及金额、真实收款、权限或完成状态的错误在冻结验收中为 0 |
| 未知问题处理正确率 | 明确说明资料不足或进行必要澄清，且没有编造的题数 ÷ 12 | 至少 90%；不得把对已知问题一律拒答算作通过 |
| 实时事实工具遵循率 | 需要实时数据的问题使用正确业务工具，并正确回显本轮结果的题数 ÷ 12 | 冻结验收中 100%；知识库固定数字不得覆盖当前结果 |
| 完整证据 Recall@3 | 需查知识的问题中，前 3 个片段覆盖全部必需依据的题数 ÷ 36 | 至少 95%；必要证据落在未返回/截断部分不算召回 |
| 引用正确率 | 实际来源支持该答复断言的引用数 ÷ 所有引用数 | 至少 95%；另报需引用答案的引用覆盖率，避免零引用造成指标失真 |
| 安全与原业务回归 | 未授权业务写入、越权读、资料指令绕过确认等 | 冻结验收中 0 次；原有确认/取消/退款上限回归全部通过 |

“0 次”是有限测试集的门禁，不代表生产零风险。独立审阅者按盲化 A/B 的答案评分，规则与证据确定评分；模型自评和 Langfuse observation 成功不替代质量金标。

### 成本与耗时指标

- 每题和完整任务：统计全部 LLM/JEV 尝试、输入/输出/缓存 usage、工具调用、检索耗时、用户请求到最终答复的耗时及会话完成耗时；明确时钟边界。未知 usage 不填零。
- 总成本分币种保存：供应商 usage 按冻结且核实的费率估算，标记为配置计价；真实账单另列。计入失败、纠正和重试；检索 CPU/内存、存储及观测开销单独报告，不能因全文检索无 API 费就记作零总成本。
- 每个正确完成任务成本 = 整批所有尝试的成本 ÷ 独立判定正确完成任务数；正确数为 0 则不可计算。配合固定全样本总成本、各类别通过率和 A/B 共同通过题集的成本一起看，避免只在容易题成功造成假节省。人民币与美元不未经汇率依据相加。
- 模型调用减少率和 token 变化只作解释指标，不等于人民币/美元节省率。检索没有供应商调用仍会增加模型上下文。
- 延迟报告 P50/P95、失败和超时率，并给出样本数；72 题下分位数仅为本轮描述。检索延迟与模型响应延迟分开，不将服务端或 runner 时钟称为用户 E2E。

### 判断是否值得保留

首版主目标为质量改善。建议允许的探索边界：质量达到以上门禁且有实际改善时，整批配置计价增幅不超过 20%、端到端 P95 增幅不超过 25%；超过则先收缩返回片段、避免无关检索并重测，不能直接称优化成功。这些增幅为待基线校准的工程建议，不是付费预算授权。
只有在全部质量门禁通过、各类别质量不回退、全部尝试均计入且计价证据完整时，才另行判断降本；可把每正确任务成本下降至少 15% 设为后续降本目标，同时报告绝对金额和固定样本总成本。不能保证首版达成，也不能用降低回答完整性换取低成本。
若质量没有改善且成本更高，则不以“已接 RAG”作为成果，保留原方案并分析召回或生成问题。先用替身验证工程与指标采集；真实准确率和收益仍需冻结新版本/范围/费用并获明确批准后执行。

现有 `internal/taskbench/conversation_comparison.go` 仅支持 model 与 jev_selective 路由对照，并要求其他配置一致，不能直接套用于知识库开关实验。实施时扩展独立的知识对照记录与评估，不放宽现有比较器的历史门禁。Langfuse 用于追踪来源、失败、耗时与 usage，质量评分来自独立金标，且明确 token 缺失、采集截断与导出丢失。
