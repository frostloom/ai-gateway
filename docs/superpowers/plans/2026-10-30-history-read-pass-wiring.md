# Explicit historical read-pass wiring

The constructor chain is V7 → V6 → V5 → V4 → V3 → V2 → first. Every original before/after predecessor call and all typed/semantic replay remain serial and present. Each legacy top-level constructor delegates to a Context wrapper which creates exactly one private pass, invokes a private WithPass constructor, and returns its value only after Finish; error returns the zero typed value. Nested constructors receive the same explicit pass. No pass is retained in typed history results. Background context preserves old signatures; new Context wrappers allow a future caller to supply its real deadline without creating a V9 entry or authority.

Explicit pass parameters continue through first pinned-file batches; V2 top-file batches, recording batches and payloads; V3–V6 top files, bundles, native verification and V4 quality candidate/cleanup sidecars. New pass batches own no outer global physical slot. Existing direct helper signatures retain their nil-pass compatibility behavior. Historical file/bytes/V7 kinds remain separate.

Original first fixed directory sets and every later bundle/native exact namespace check run at their original locations and register their exact expected sets for End. Seven original campaign locks retain epochs 1–7 and their original per-invocation callbacks; End reacquires all in epoch order. Canonical descriptors' small parent dirs, historical immutable epoch roots and the first historical claims dir are explicitly classified before descendants are read; earliest markers are never rebased.

Re-registering an already classified immutable root is idempotent inside the same pass. It does not rescan every previously registered descendant each time a predecessor is replayed. The first marker remains unchanged, newly encountered descendants inherit strict comparison, all original namespace walks still run, and End independently rechecks all registered directories. This avoids adding an accidental O(registered-directories × recursive-calls) metadata sweep to the new protocol.

Hidden dependencies are V6/V7 signed binary attestation's executable hash and both V7 direct inventory streams. Signature/binding validation remains unchanged; a private historical variant uses registered uncached executable streaming. V7's per-file direct inventory stream uses the pass's strong same-FD stream in new mode, preserving exact expected size/hash/link/metadata checks; its nil-pass branch retains the original reader. Inventory traversal and directory walks remain fresh on every original invocation; NoCacheWalk is not relabeled as cached.

TDD acceptance uses only owned temporary fixtures: native payload store/descriptors/body and returned clones, fixed namespace additions, direct inventory stream mutation including zero-byte entries, first pinned batches, V4 quality sidecars where fixtures permit, executable signature/stream registration, cancellation and zero-value top failure. It includes AST enforcement that private historical constructors/helpers forward explicit p and contain no accidental call to old nested constructors or uncaptured original byte readers. Existing targeted safe synthetic rejection tests and primitive normal/race remain required. Real original44 loading/performance is deliberately reserved for root after independent wiring review; no model/JEV/DB/claim operation is part of this change.

This is a new first+End disk protocol. It does not preserve 275,644 physical reads, does not provide atomic End snapshots, and does not reopen consumed scopes or establish paid readiness. Complete original-data coverage/resource acceptance and timing remain later gates.
