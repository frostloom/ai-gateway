# 客服模型配置与 JEV 正式接入 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** 管理员可配置客服 LLM、JEV 服务端密钥和模型，正式启用已有 JEV 规则。

**Architecture:** 单行版本化数据库配置，AES-GCM 加密密钥，独立部署主密钥。管理员接口只回已配置状态。Agent 每个请求选择不可变运行时，保存配置后新请求生效，进行中的请求保留原快照。复用已有 jev_selective 规则和工具校验。

**Tech Stack:** Go、GORM/MySQL、Vue3、TypeScript。

**Spec:** 用户已明确同意现有规则正式接入，简单查询直读、高置信高风险拒绝、无关闲聊拒绝，并新增管理员模型与密钥配置页面。Langfuse 是实验、数据、rubric 和评分的集中来源，本地空分数文件不证明未评分。

## 约束与决定

- 保留现有四类直读和置信度阈值、确认取消状态机、鉴权与财务后端约束。
- 正式模式为 model 或 jev_selective，用户启用 JEV 时必须有完整 JEV 配置。
- 密钥独立 AES-GCM 加密，主密钥持久置于服务器配置，API 不返回明文或密钥前后缀。
- 全量配置带 revision，更新冲突返回409，空 api_key 表示保留原值。端点主机改变时要求显式新密钥。
- Agent 按请求快照构建不可变 Handler，不并发修改共享 Handler 的策略、LLM 或 JEV。
- 请求前加载配置出错时返回配置服务不可用，避免静默切到失效旧密钥；初次无数据库配置时兼容环境配置。
- JEV 判断故障保留现有主模型回退行为，不改评测阈值、超时和题库。
- 按用户后续要求，仅更新本地网关、billing、agent 并同步 GitHub。线上此次不发布；准备期间创建的临时密钥材料已撤回。
