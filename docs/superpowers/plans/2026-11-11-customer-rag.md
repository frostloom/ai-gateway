# 客服 JEV 后置 RAG 接入 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** 在现有 JEV 分流后，仅对进入 LLM 的客服请求启用知识提示、Top 3 召回及自主知识检索，支持版本化缓存。

**Architecture:** 从 codex/customer-knowledge-rag 分支提取公共语料加载器和只读知识工具，按当前平台更新资料。采用中文业务词、汉字二元组回退及中英文标识符的确定性分词，预建段落索引。检索返回最多3段，缓存绑定语料与检索版本，容量和有效期受限。首次 LLM 调用前自动检索当前问题，再保留工具供模型补查。

**Tech Stack:** Go，本地已审阅 JSON 公共语料，无新增远程 embedding 服务。

**Spec:** 用户要求提示词与模型自主查阅并存，考虑分词，召回 Top@3，可结合缓存；所有这些在 JEV 决定进入 LLM 后进行，JEV 继续既有策略。沿用仅本地更新、同步 GitHub 的范围。

## 决定与边界

- 保留 JEV 问题、阈值和分流；确认/取消、直读、高风险拦截和无关内容拒绝不触发检索。
- 资料包括充值关闭/券兑换、月卡金额权益、用量口径、API 接入等当前平台事实；价格、余额、当前订阅等实时信息继续查业务工具。
- 提示词明确资料不是指令或授权，要求必要的 KB 来源和未命中处理。
- 自动预取当前问题的 Top3 作为参考，模型仍可使用 search_platform_knowledge 补充检索；不增加 JEV 或额外分类器。
- 缓存仅含公共检索结果，键使用规范化 query 的散列并绑定语料/分词版本，不缓存用户回答或实时账户数据。
- 知识配置默认关闭以兼容旧评测，当前本地正式客服显式启用。语料加载时验证 manifest，不合并旧实验执行器或旧付费活动。
- 召回、缓存和资料版本记录到遥测与 Langfuse，区分召回与实际发送给模型的内容。
