# Per-invocation historical reader primitive

This document records the initial private primitive delivery and its concentrated fix1. That delivery did not connect constructors or live authority. The subsequent explicit first/V2–V7 constructor candidate is described in `2026-10-30-history-read-pass-wiring.md` and requires its own review and complete-original-data acceptance. Frozen archives and consumed scopes remain unchanged; neither stage establishes paid readiness.

## Approved protocol

Each top-level invocation must eventually create a new `historyReadPass`, pass it explicitly through private historical constructors, defer `Abort`, and return a usable top baseline only after `Finish` succeeds. The pass must never be retained in that baseline. No global, goroutine-local, cross-invocation or cross-claim cache exists. The current primitive alone does not enforce the future constructor's zero-result-on-failure rule or provide an issuer.

`Read(historyReadSpec)` separates actual-file, bytes and V7-file keys by kind, canonical path, expected SHA and maximum size. Bytes reads may have an empty expected SHA; their actual first digest still becomes a closure dependency. `Stream(kind,path,sha,max)` separately records inventory and executable streams without retaining bytes. All streams and entries larger than 1 MiB are physically read on every reference and again at closure. Small retained entries are cloned on every return; callers cannot mutate retained evidence.

The new observed reader takes full identities from the same opened FD that supplies bytes, plus before/after canonical path checks. It records dev, inode, mode/type, uid, gid, nlink, size, mtime and ctime. Required platform identity support is mandatory; Darwin and Linux are supported, other platforms fail closed. New-mode files require nlink=1. The old no-pass readers are not refactored or altered in this primitive delivery.

Shared specification validation preserves the original V7 file and direct inventory 256 MiB upper bound before admission and in the physical reader. Executable streams remain bounded by the original 1 GiB ceiling. Actual-file/bytes kinds additionally use the new primitive's 1 GiB admission ceiling; their old wrappers have no such upper parameter bound and remain untouched. These checks apply even when the actual owned input is tiny.

All ancestors are canonical/noalias directories and retain device/inode/type/mode/ownership identity. Explicit immutable roots and their dependency subdirectories additionally retain full timestamps, size and nlink. Root upgrades compare the earliest captured full marker before enabling strict comparison. Shared ancestors above marked roots deliberately ignore timestamps: a shared ancestor renamed and restored between observations can remain undetected. Sibling writes outside registered exact namespaces are also allowed. This is not an atomic filesystem snapshot.

Original namespace and stopped-lock semantic callbacks run on every invocation, including callbacks that recursively read leaves. Namespace expected names are copied and compared; closure performs fresh exact namespace checks. Lock registration retains original identity and fixed epoch order; closure nonblockingly reacquires all registered locks, holds them through file/directory/namespace sweeps, and releases all acquired locks on every path. Only test-owned temporary locks are used by the new tests. No real historical lock has been touched by this delivery.

## Bounds and lifecycle

- Four logical leaf slots per pass cover physical reads, stream reads and clones. No slot wraps a semantic callback or constructor. `Batch` launches at most four readers and joins all of them; it does not wrap the old batch helper or acquire an outer physical slot.
- Each physical file/stream read uses the existing global four-slot semaphore. Cancellation and failure wake slot waiters. At most 64 active API calls are admitted; each batch remains admitted until its workers have joined, bounding outstanding batch workers at 256. Nested admission may fail closed at that limit.
- Retained cache payload is limited to 128 MiB, each retained entry to 1 MiB. Retained-budget exhaustion fails; it does not evict entries or silently fall back. Returned caller buffers, transient IO/clone allocations, maps and other process memory are not covered by a 128 MiB RSS claim.
- Transcript records are limited to 65,536 and charged bytes to 32 MiB; logical calls are limited to 1,048,576. The initial 16 MiB estimate was insufficient for the real original46 graph; the bounded metadata-capacity delta is recorded in `2026-10-30-history-read-pass-transcript-capacity-delta.md`. Charge per new record remains `512 + UTF8(key) + UTF8(path) + UTF8(SHA)` bytes, with namespace additions `24 + UTF8(name)` per expected name. Directory and lock records are charged. These are protocol charges, not exact Go heap accounting. Stats retain cumulative charges after cleanup and must not be interpreted as currently retained heap.
- First readers singleflight identical keys. Waiters receive failure before a failed first reader releases them. Any error/cancellation/quota failure seals the pass. `Finish` drains admitted calls, exclusively owns cleanup, and cannot race `Abort` into clearing an active sweep's maps. Repeated closure and post-closure reads are unavailable.
- A semantic callback must return normally. An abnormal callback exit failseals the pass while propagating its original panic and releasing active bookkeeping/lock leases. Closure separately requires a normally verified body and normally completed cleanup/final context check; a recovered body or final-context panic cannot leave `ClosedSuccess` or an active cleanup owner.
- Closure acquires old locks in epoch order, checks dirs/namespaces, freshly hashes every registered file/stream in sorted key order, checks final file identities and dirs/namespaces again, verifies locks, releases/closes all leases, checks the original context, then succeeds. No half-closed proof or background work is returned.

Each dependency has its own last successful comparison horizon. A writer ignoring advisory locks may alter a dependency after its last check; the protocol does not detect arbitrary later writes or provide a whole-End/return-instant atomic snapshot. Synchronous callbacks must return; the primitive does not spawn an abandoned goroutine to preempt a blocked callback.

## TDD and acceptance boundary

The initial two behavioral tests failed because a serial stub reread the same dependency and accepted a write/restore with restored mtime. They pass with first+End evidence. Further real tests found and repaired an Abort/Finish map-clear race, root-component classification for `/`, and failure not interrupting a physical-slot wait; their original RED artifacts remain separately preserved.

Focused tests cover caller clones and concurrent singleflight, separate kind/max keys, cache threshold and quota boundaries, transcript/logical admission, batch cancellation/join, real same-byte inode replacement, hardlinks/mode/body changes, bytes+mtime restoration with changed ctime, immutable directory ABA and root upgrade, shared ancestor limitations, callback recurrence, exact namespace extra/missing/type changes, stream-only dependencies, lock ordering/occupation/partial cleanup, and cancellation occurring only after lock cleanup. The existing seven batch4 tests are included in focused normal/race runs.

The first independent primitive review found two P2s: lost V7-kind maximum-parameter rejection and recovered semantic callback panic allowing closure. Concentrated fix1 adds a shared kind-bound validator and abnormal-exit failsealing, including closure cleanup. Owned tiny-file max/exact+1, namespace/lock panic-recover and Finish body/final-context panic counterexamples were run against the original candidate as assertion REDs, then rerun after the fix. The first candidate and its independent review remain preserved separately.

Before any future integration, independent review must verify this primitive. A separate explicit-reader wiring change must inventory every first/V2–V7 dependency, preserve each semantic/typed/namespace/lock validation and both original constructor passes, and register hidden executable/direct inventory streams without caching directory walks. Current auth, live authority, current claim, settings and keys must remain outside the pool. A zero-paid complete-original-data acceptance run must verify first/End coverage, unchanged original inputs and bounded resources, then separately measure performance. The earlier 275,644 physical-read-preservation claim does not apply to this new protocol. No new scope or readiness claim follows from primitive tests.
