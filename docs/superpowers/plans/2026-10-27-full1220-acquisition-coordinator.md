## Minimal coordinator

Use one process with a live campaign owner and explicit stdin operations, rather than a new network server. Starting the process must not send provider requests. One explicit operation may run only the expected current window with a maximum300second acquisition context. There is no automatic paid loop, replay, reopening or request retry. The process waits without inference between operations and retains the owner; losing it makes that consumed campaign audit-only. Root-agent orchestration checks each operation's actual receipt before submitting the next predetermined window. EOF, signal, invalid transition or failure stops the owner and flushes/closes resources. A successful window already permanently reserves the next predetermined cap; shutdown does not release it.

Commands contain no configurable provider URL, credentials, source path, cap or mutable execution options. Those are frozen once in the entry configuration. Commands identify the expected window and prior receipt digest. Status is read-only and cannot mint a permit. Output is a bounded summary with private artifact digests, never keys or raw payloads. The actual operation calls the existing private one-window collector, rather than a second execution implementation.

## Closed-session implementation boundary

The session retains the same live owner between operations. Use an owned loopback OTLP sink and labelled local artifacts, not the shared actual Langfuse project. Preserve failed and unrun rows and stop on failure. This API must be separately named and typed from a future actual session.

Closed accounting rates/usage are explicitly synthetic. It may predeclare per-window caps covering all synthetic maximum attempts (model five attempts per arm/turn, JEV one per selective turn); those synthetic fees never become verified real tariffs or actual budget consumption. Bodies and serialization are real protocol shapes, but injected usage is not token or billing evidence.
