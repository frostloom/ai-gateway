# Hindsight 同步写入排查（2026-10-21）

结论：本机 Hindsight 的 ai-gateway 库可以正常写入。此前客户端设置了 8–30 秒超时，连接断开后服务取消同步 retain，导致多次写入未获得成功确认。不能把这种情况仅解释成排队延迟，也不能仅凭 recall 没有命中就断定完全未入库。

## 证据

- 容器日志多次记录 `[RETAIN CANCELLED] bank=ai-gateway reason=client disconnected`，对应约 8、12、20、25、30 秒的请求时长。
- 运行中服务的 `/app/api/hindsight_api/api/http.py` 内，`run_task_cancellable_on_disconnect` 在断开连接时取消任务；同步 retain 调用此函数，且不创建后台 operation 记录。取消过程中可能保留已经提交的子批次，因此重试前需检查存储。
- 保持连接的验证请求使用 `async:false`、300 秒客户端超时，实际耗时 **239.825 秒**，返回 **HTTP 200**、`success:true`、`bank_id:ai-gateway`、`items_count:1`。
- 此次调用的 LLM 审计元数据表明 `retain_extract_facts` 成功，耗时 **239400 ms**，输入 188 tokens、输出 14573 tokens。主要耗时发生在模型提取阶段；这些数据不足以确定上游为何生成较长输出，也不足以保证后续耗时相同。
- `GET /memories/list?q=Superpowers&limit=10` 实际读回新增开发规则及其归纳记录；库文档数从 **4 增至 5**，节点数从 **32 增至 40**。
- 随后的统计中，最后写入时间为 **2026-10-21T12:30:28.091473Z**（北京时间 20:30:28），待处理和失败操作均为 0。这是入库响应和读回的补充证据，不能单独用于判断同步写入结果。

## 后续使用规则

1. 继续只维护 ai-gateway 库，使用约定的同步写入正文。
2. 保持请求连接，允许数分钟等待；300 秒是本次成功的设置，不是服务耗时上限。
3. 以成功响应和实际读回共同确认写入。recall 索引未命中时，可用 memories/list 和文档/统计信息辅助确认。
4. 超时后标记“未确认”，检查日志和存储再决定是否重试，避免重复写入。
5. 本次没有修改服务配置、切换模型、重启容器或读取其他记忆库。

本次仅调整项目使用约定和诊断文档；验证采用实际写入、直接读回和服务日志/审计元数据，没有重新运行与文档变更无关的 Go 回归。
