# 计费边界补充核查（2026-10-22）

本轮接续[账户只读复核](paired-account-readonly-2026-10-22.md)，仅补充官方 SDK 和管理页可见证据。没有发送模型或 JEV 推理请求，没有提交登录、接受协议、充值或修改账户设置。`allow_paid=false`、`ready_for_paid_run=false`，模型继续固定为 `jev-1.13.0`。

## 管理页可见范围

首次核查时，独立浏览器显示登录页；Safari 后续已加载出认证后的控制台首页，并显示 Billing 入口。该轮入口操作未取得账单内容，界面切换后停止操作；当时没有读到账户余额、实际费率或失败请求账单。认证首页也不能证明这个浏览器账户与项目现有 API 密钥属于同一账户。

随后经用户授权继续只读核查，Safari 实际打开了 Billing 与 Usage 页，更新上述首次核查的状态：

- Billing 显示有可用 credits，其中有带到期日的月度 credits；自动充值显示关闭。只归档这些状态，不记录余额、账单金额、账户身份或具体到期日。
- Usage 显示历史花费、token 和请求统计，并明确提示统计可能延迟；价格提示使用 `Estimated` 字样。页面估算与公开输入单价一致、输出免费，但这仍不是账户最终费率或未来优惠保证。
- 页面没有提供所需的失败请求扣费承诺；现有聚合统计也不足以将失败状态逐笔关联至扣费。项目密钥与当前浏览器账户的归属关系仍未核实，因此也不能宣称项目密钥余额已验证。
- 浏览器操作连续超时，恢复后当前页面已切换，停止进一步操作并仅关闭本轮创建的核查标签页。没有导出私人账单、显示完整密钥或进入付费执行。

## 后续密钥归属核对

同日继续只读打开官方控制台 API Keys 页面。页面显示密钥属于组织范围；在本机将项目现有 JEV 密钥与页面 Active 密钥的可见前后缀比较，得到唯一匹配。未显示完整密钥、未复制或创建密钥，也没有修改账户设置。归档只保留匹配结论，不保留密钥掩码、名称、创建者或日期。

这一证据增强项目密钥与当前控制台组织的对应判断，但短前后缀无法证明完整凭据相同；`project_key_account_mapping_verified` 仍为 false。也不能据此将此前看到的 credits 等同于该密钥可用余额，实际费率、失败扣费和收费 token 上界仍未确认。

尝试查看只读详情时控件失效，随后发现 Safari 已切回用户的其他页面，停止继续操作。仅尝试关闭本轮新建标签页，工具因用户正在改变界面而拒绝；未确认关闭，未继续抢占浏览器。没有重新读取私人账单或发起推理。

## 新增公开证据

- JEV Python SDK 的响应类型说明中，`Usage.input_tokens` 和 `output_tokens` 均可为 `None`，仅在 API 报告时提供。它们是调用后的可选用量，不是调用前的精确计数接口，也不证明账单金额。缺失用量应保持未知。
- 模型文档明确：默认每请求上下文为 64k，包含 state 与全部 questions；每问题为 32k，包含 state 与任一 question。长上下文默认关闭，需显式请求头开启。本轮没有开启；上下文限制不等于已核实的收费上限，也未解决失败请求扣费边界。
- SDK 异常说明区分 HTTP 错误、无响应连接失败、超时及成功 HTTP 响应的结构校验失败，没有说明这些情形的收费豁免。不能用客户端失败推断供应商没有处理或没有收费。
- 所查 JEV OpenAPI 仍仅列出 `/v1/models`、`/v1/systemone`；千问 Anthropic OpenAPI 仅列出 `/apps/anthropic/v1/messages`。在本轮资料范围内未找到非推理的精确 token 计数接口；未探测猜测路径。

[脱敏证据清单](../eval/paired-pilots/2026-10-22-billing-final-check/billing-boundaries.json)记录八份公开官方资料的来源、HTTP 状态、字节数和 SHA-256。原文只放本机临时目录；不归档账户身份、密钥标识、私人账单或截图。

## 当前结论

本地六批次演练的完成记录见[演练报告](paired-local-campaign-rehearsal-2026-10-22.md)。真实评测仍缺可审核的渠道 token 收费包络、项目密钥的账户归属、JEV 账户实际费率及失败扣费边界，以及明确的付费案例、次数和分币种预算授权。6 个案例、最多 24 次模型尝试与 6 次 JEV 尝试、¥1 / $0.02 均仍是提案，不是执行授权。账单页已能读取，其聚合信息和现有公开文档不足以消除其余未知项。

本次仅修改文档和证据清单，验证 JSON、公开原文哈希、相对链接、付费开关及差异范围；未重新运行 Go 回归。

## 后续状态与证据解读校正

用户此后已批准六案例、24 次模型 / 6 次 JEV、¥1 / $0.02 的既定范围；上述“仍是提案”仅是当时历史状态，当前授权见 `AGENTS.md`。同日新增的 `cmd/paired-live` 已提供首批入口；仍未发送真实评测请求。

SDK 可选 usage 不能直接推断 HTTP 契约允许缺失用量。已保存的官方 OpenAPI 中，`SystemOneResponse.required` 包含 `usage`，`Usage.required` 包含 `input_tokens` 与 `output_tokens`；输入字段明确表示 billable input tokens。规范哈希没有改变，校正的是先前解读。缺失或错误响应仍应停止，成功响应的事后用量也不证明调用前的收费上界或失败费用。

实际缺少的供应商确认项与本机未就绪证据位置见[首批入口记录](paired-live-entry-2026-10-22.md#收费依据补齐结果)。不再以重复本地演练或余额核查替代这些外部依据。
