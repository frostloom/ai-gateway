# 计费边界补充核查（2026-10-22）

本轮接续[账户只读复核](paired-account-readonly-2026-10-22.md)，仅补充官方 SDK 和管理页可见证据。没有发送模型或 JEV 推理请求，没有提交登录、接受协议、充值或修改账户设置。`allow_paid=false`、`ready_for_paid_run=false`，模型继续固定为 `jev-1.13.0`。

## 管理页可见范围

独立浏览器仍观察到登录页。Safari 后续已加载出认证后的控制台首页，并显示 Billing 入口，因此不能继续将 Safari 状态记作未登录或仅加载中。账单入口操作未取得账单内容；后续界面切到其他页面，停止操作以免干扰用户。没有读到账户余额、实际费率或失败请求账单，认证首页也不能证明这个浏览器账户与项目现有 API 密钥属于同一账户。

## 新增公开证据

- JEV Python SDK 的响应类型说明中，`Usage.input_tokens` 和 `output_tokens` 均可为 `None`，仅在 API 报告时提供。它们是调用后的可选用量，不是调用前的精确计数接口，也不证明账单金额。缺失用量应保持未知。
- 模型文档明确：默认每请求上下文为 64k，包含 state 与全部 questions；每问题为 32k，包含 state 与任一 question。长上下文默认关闭，需显式请求头开启。本轮没有开启；上下文限制不等于已核实的收费上限，也未解决失败请求扣费边界。
- SDK 异常说明区分 HTTP 错误、无响应连接失败、超时及成功 HTTP 响应的结构校验失败，没有说明这些情形的收费豁免。不能用客户端失败推断供应商没有处理或没有收费。
- 所查 JEV OpenAPI 仍仅列出 `/v1/models`、`/v1/systemone`；千问 Anthropic OpenAPI 仅列出 `/apps/anthropic/v1/messages`。在本轮资料范围内未找到非推理的精确 token 计数接口；未探测猜测路径。

[脱敏证据清单](../eval/paired-pilots/2026-10-22-billing-final-check/billing-boundaries.json)记录八份公开官方资料的来源、HTTP 状态、字节数和 SHA-256。原文只放本机临时目录；不归档账户身份、密钥标识、私人账单或截图。

## 当前结论

本地六批次演练的完成记录见[演练报告](paired-local-campaign-rehearsal-2026-10-22.md)。真实评测仍缺可审核的渠道 token 收费包络、JEV 账户实际费率及失败扣费边界，以及明确的付费案例、次数和分币种预算授权。6 个案例、最多 24 次模型尝试与 6 次 JEV 尝试、¥1 / $0.02 均仍是提案，不是执行授权。账户专属部分需要可稳定读取的管理页；现有公开文档不足以消除这些未知项。
