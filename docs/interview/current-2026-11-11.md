# 当前架构与面试学习指南（2026-11-11）

本文以当前工作区代码和已有运行记录为依据；旧里程碑材料保留历史上下文，不代表现在的实现。工作区含未提交修改，部署状态须另行核对。

## 一句话介绍

这是一个 Go 实现的多租户 OpenAI 兼容模型网关，提供鉴权、限流、上游路由与熔断、额度计费和流式转发，并提供带工具调用与确认流程的 AI 客服。

## 请求和计费主线

客户端 → gateway 鉴权、限流 → router 选上游 → billing 预扣 → 转发响应或 SSE → 记录用量、结算；异常状态按具体路径冲正或保留待核查。流式输出已经向客户端发送后不能简单重发上游。

当前 billing 启动入口默认 `BILLING_LEDGER_BATCH_SECONDS=5`，可设 0–60，0 为关闭批量。批量模式下 Redis 是实时余额的权威来源，预扣和余额调整通过 Redis 完成；请求明细及余额变动在进程内积攒，后台周期性批量写 MySQL。MySQL 用于持久账单与余额记录，但在刷账完成前可能落后。周期不是持久化时延的上限：调度、数据库故障或重试都可能造成更久延迟。

启用 Kafka 时，明细由后台异步发送，失败有重试及 outbox 路径；Kafka 不直接修改余额。`BILLING_LEDGER_VIA_KAFKA=1` 当前被 billing 启动入口拒绝，因此不要把 Kafka 消费者写 MySQL 描述为当前启用方案。非批量模式仍存在，不能把批量路径推广到所有配置。入口见 [billing main](../../cmd/billing/main.go)，批量数据结构和刷账见 [ledger_batch.go](../../internal/billing/store/ledger_batch.go)，资金路径见 [mysql.go](../../internal/billing/store/mysql.go)。

### 一致性和故障边界

- Redis 的原子操作用于并发余额控制；具体幂等和冲正还需看请求状态及对应代码，不能简化成单个 Lua 脚本解决所有跨系统问题。
- 账单尚未落盘时 MySQL 可能是旧值，不能无条件用它重建 Redis，否则可能覆盖已发生的扣款。兑换等路径有待处理变动或不一致时拒绝的保护。
- 进程内批次及待发送事件在落盘前存在故障窗口。不要承诺“任何崩溃都不丢账”、严格 5 秒落盘，或声称 Redis、MySQL 和 Kafka 之间是一个原子事务；具体恢复能力应按故障点与部署配置验证。
- 旧 M4 材料所说的 MySQL 权威账本和 Redis 投影，描述的是旧路径，不能直接用于解释当前默认批量模式。

## 客服和安全

Agent 接收对话并调用模型和业务工具。租户身份来自验证后的凭据；工具参数和权限由服务端校验，写操作先预览，再等待用户确认或取消。JEV 用于选择性判断与快速路径，复杂或判断失败的请求可回到主模型。控制台支持配置主模型和 JEV，密钥加密存储；具体行为参考 [chat.go](../../internal/agent/chat.go)、[tools.go](../../internal/agent/tools.go)、[customer_service_runtime.go](../../internal/agent/customer_service_runtime.go)。

## 性能数据怎么讲

[2026-11-10 有界线上环境压测](../online-load-test-2026-11-10.md)使用隔离实例、模拟上游和资源限制：64 并发约 772 请求/秒，256 并发复测约 804 请求/秒、20,000 请求零失败；512 并发突发触发连接超时保护。测试并非真实模型推理或生产容量保证。历史 212 请求/秒是旧版本结果，不应作为当前架构的吞吐上限。

## 面试复习顺序

应聘 Go 后端时，优先学习 [Gin、gRPC 与 Go 后端专项](go-backend-gin-grpc-2026-11-11.md)。

需要练习口头回答时，接着读[面试冲刺与追问](interview-practice-2026-11-11.md)，里面有一分钟介绍、逐步代码路径、常见追问和两小时练习。

1. 画出请求、预扣、上游调用、结算和异步落账链路。
2. 解释 Redis 并发扣款、MySQL 落后窗口、批次刷盘失败和旧值覆盖风险。
3. 解释熔断、故障切换及 SSE 已输出后的重试边界。
4. 解释客服的身份来源、工具参数校验、写操作二次确认与 JEV 作用。
5. 用具体运行的分母、失败数和证据说明评测，避免把采集完成说成任务全部通过。

建议练习回答：为什么要预扣？Redis 与 MySQL 暂时不一致怎么办？进程在刷账前退出有哪些风险？Kafka 在哪里、是否改余额？为什么模型不能决定租户？1220 条完成指的是哪一次运行的哪个阶段？
