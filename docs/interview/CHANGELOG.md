## 2026-10-09：重建客服评测边界（727284d）

问题：单轮首工具命中曾混用为任务完成率，必要追问与确认可能误算失败；V2提示、守门和直接路由混在一起，无法归因JEV收益。

处理：保存1220原文及三组历史输出，建立单独标注契约与离线判分；主V1=model、V2=jev_selective，共享短提示词、工具和确认状态机。只有高置信、首次独立无参数四读直达，其他交同一模型。记录完整工具参数、HTTP、usage、耗时、初末状态与运行哈希。

证据：相关五个Go包回归、52项Python测试与归档SHA校验通过。提示词1564→770字符是字符差异，不能当成实测token或账单节省。

局限：事后AI标注不是独立金标；1220条完整账户fixture仍未补齐；未重跑在线评测，无法给出新任务准确率、时延或成本收益。

## 2026-10-10：默认零扣费的实验准备（b857a95）

问题：旧实验脚本仍使用历史FastPath组合，容易误启动收费测试；运行配置和案例被修改后可能沿用旧准备。

证据：Go全项目、Python61项与旧归档校验通过；真实构建程序生成12任务准备清单，无模型/JEV请求。

局限：任务数量不是模型调用或费用预算；二进制声明的commit不是可复现构建证明。JEV官方输入收费，账号免费额度未核实。开发小集不是独立盲测。

## 2026-10-10：远程计费修复的二次审查（7c80493）

远程增加流式失败切换、预扣补偿、短欠结算、控制面令牌、限流/半开修复和CI。拉取后Go全项目与vet通过，但审查发现五个未覆盖边界：并发补偿退款、旧结算guard迁移、503响应体无限等待、部分重启令牌变化、切换成功上游归账错误。

这说明“现有测试全通过”只证明已有断言，不能证明新并发时序、迁移和进程间配置都正确。审查结论来自代码路径推演；实际复现与修复证据在下一条追加，不能混写成当时已经复现或修好。

## 2026-10-11：计费边界修复与离线测评门禁

范围为上述五项修复。原1220条档案、历史分数、必要追问口径均不变。

| 问题 | 修复机制 | 实际证据 |
|---|---|---|
| 同request并发补偿 | MySQL会话锁覆盖余额预占；插入失败重新取得健康锁并查账本，Redis调用所有权防止旧调用退款 | 原竞态余额1000而账本900；取消插入后余额900而应1000；这些先失败再通过。首次连接被KILL后的重放测试也通过，但未取得该场景修复前失败证据 |
| 旧结算guard | 新值为`v2:<applied>`，旧sentinel `1`按请求delta恢复，其他旧数值保留 | 旧值误读为1；±50/0重放及新版本实际扣1分重放回归 |
| SSE 503无限body | 立即关闭失败响应，继续切换或退款 | 本地上游保持body不结束，修复前超时、修复后两条路径通过 |
| 部分启动令牌 | 缺稳定token提前失败；M5三处路由请求带认证 | 真实启动脚本配合本地OS替身，6项行为回归先失败再通过 |
| 成功上游归属 | ReportUsage追加provider_id；锁行后首次记录用量和上游，同值重试，冲突拒绝 | 非流式/SSE真实usage/SSE估算三条路径；A失败B成功，B售价收入150分、上游成本400分；重复usage原错误NotFound已修复 |

追加审查：仅重新取得健康锁仍有恢复连接再次断开的窗口。新回归在“恢复查询账本为空”后KILL恢复连接，让重放先提交，实际复现余额1000而应900；因此增加每次调用独立随机owner，Redis重放原子接管owner而不重复扣款，旧调用只能补偿自己仍拥有的guard。该恢复失联回归具有修复前失败证据，与上一行首次失联的证据限制分别记录。

设计取舍：余额预占使用一条固定数据库连接，避免另借连接造成连接池耗尽；预占SQL独立15秒上限，取消调用仍有机会完成补偿；订阅路径不经过Redis扣款，保留原查询方式。恢复锁和Redis所有权解决本轮复现时序，但Redis与MySQL仍不是分布式事务，进程崩溃遗留孤儿guard问题没有因此消失。网关与计费服务的provider_id契约需同步升级；旧计费服务会忽略该新增字段。

迁移限制：旧sentinel `1` 与中间版本无前缀的实际扣1分无法从值本身区分。存在该中间版本未完成账单时需要结合账本和部署记录人工核对，不能宣称任意旧数据自动无损迁移。

验证结果：`AGENT_LIVE_JEV=0 go test ./... -count=1 -timeout 180s`通过；追加所有权修复后，主代理独立重跑全部store测试通过（70.461秒）。`go vet ./...`、Python67项（35.661秒）、三项归档校验和diff检查通过；独立审查无剩余阻塞发现。1220案例及3660历史判分SHA与重算数量一致。Windows环境未安装C编译器，未执行Go race检测；这轮本地替身不替代真实Kafka/生产故障测试。

证据限制：自动审批拒绝临时撤掉恢复保护来演示断连接失败；该操作没有执行，所以只记录断连接场景的修复后验证，不声称完整红绿链。

评测门禁：CI增加Windows/Python离线评分、契约、档案SHA和真实脚本替身流程；Go CI显式关闭AGENT_LIVE_JEV，不配置模型密钥或开启在线测评。新增CI配置需以远程Actions实际执行结果确认，不能把本机通过写成远程CI已通过。

后续面试数据：优先说明缺陷触发、原子性边界、幂等重试、升级兼容和证据保护。JEV质量/覆盖/调用节省、整任务P50/P95、真实费用仍需预算授权后的预冻结配对实验；当前不补造数值。
