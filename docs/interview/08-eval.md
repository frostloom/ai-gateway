# 08 AI 客服评测集：数据驱动的回归闭环

> 面试讲「我怎么保证客服改对了还很难改坏」：30 条用例 × 5 维度，离线假 LLM 确定性回归，
> 一次 2 秒跑完，通过率下降即回归。这是整个项目从「能 demo」到「可迭代」的关键一步。

## 一、为什么需要评测集

客服的本质 = prompt + 工具描述 + 校验逻辑 + 确认状态机。这类「规则性」工程最怕的是：

1. 改 prompt 提升 A 意图，顺手把 B 意图带偏（无回归基线）；
2. 安全边界（执行层不信任 LLM）只有几个孤立的单测，覆盖不足；
3. 真实的 DeepSeek 每次输出不同，光靠手点没法量化「变好了还是变坏了」。

评测集把「判断」从人眼挪到断言：**每条用例 = 输入场景 + 期望行为，机器判定 PASS/FAIL**。

## 二、两条腿：离线确定性 + 在线真实

| 模式 | LLM | 成本 | 用途 |
|---|---|---|---|
| `fake`（默认） | 脚本化 tool_call（把 DeepSeek 换成假 LLM） | 0 | 回归基线：确认状态机/安全纵深/参数校验/清洗器 |
| `http` | 真 DeepSeek | 真实 token | 上线前抽检：意图路由准确率、回复自然度 |

**只测真 LLM 测不稳，只测假 LLM 测不真。** 假 LLM 测的是「执行层的确定性逻辑」，
真 LLM 测的是「意图 → 工具的准确率」，两条腿分开才清晰。

## 三、用例长什么样（30 条 × 5 维度）

```json
{
  "id": "confirm-recharge-yes",
  "dimension": "confirm",
  "llm_script": [ { "tool_call": { "tool": "recharge", "args": "{\"amount_money\":100}" } } ],
  "turns": ["帮我充 100 块钱", "确认"],
  "expect": {
    "turn_pending": [true, false],
    "confirmed_tool": "recharge",
    "admin_posts": ["/admin/recharge", "/admin/recharge/pay"],
    "reply_contains": ["充值成功"]
  }
}
```

| 维度 | 覆盖 | 面试例句 |
|---|---|---|
| intent | 8 条：意图→工具路由、闲聊不触发工具 | 「一句口语怎么变成正确工具调用」 |
| confirm | 8 条：挂起→确认/取消/保留、关键字变体、跨请求持久化 | 「写操作为什么必须二次确认」 |
| security | 7 条：注入 tenant、编造工具、提示注入、负金额、错误 key | 「LLM 想害你怎么办：执行层不信任 LLM」 |
| purity | 4 条：⚙ 清洗、空行压缩、预览不含原始 JSON | 「回复为什么永远干净（prompt 规则 + sanitizer 双保险）」 |
| allowance | 3 条：订阅额度口径、无订阅、价格回复 | 「订阅额度怎么让客服看得懂」 |

## 四、纵深断言（这是评测集区别于「冒烟脚本」的点）

- `tenant_override`：假 billing admin 记录每次调用的 tenant_id，**注入 999 必须还是 key 派生的 42**；
- `admin_posts`：确认前必须 0 次写调用、确认后恰好 N 次——**把「执行层强制」变成可测试的契约**；
- `pending` 状态机逐轮断言：挂起 / 确认 / 取消 / 无关话语保留挂起。

## 五、迭代闭环

```
改 prompt / 工具描述 / 校验逻辑
        ↓
go run ./cmd/eval        （离线 2s）
        ↓
通过率下降 → 定位失败用例精修 → 回归
        ↓
全绿 → 报告归档 eval/reports/
```

## 六、面试 Q&A

- **为什么用假 LLM 而不是 mock 接口？** 假 LLM 注入的是「LLM 的输出」本身
  （脚本化 tool_call），测的是 agent 对 LLM 输出的处理逻辑；mock 接口只测 HTTP 层。
- **30 条够吗？** 覆盖了 5 个风险维度的代表性场景；新增边界靠「先写用例再改代码」驱动，
  用例即规格。
- **真 LLM 在线模式什么时候用？** 上线前抽检 + prompt 大改时对照；日常回归全走离线，
  零成本、可进 CI。
- **和单测的关系？** 单测验证原子行为（一个函数），评测集验证端到端行为（一条对话
  走完鉴权→会话→路由→确认→审计）。关键用例会反哺成单测防回归。
