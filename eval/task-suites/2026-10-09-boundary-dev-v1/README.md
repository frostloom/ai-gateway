# 客服边界开发小集 v1

冻结日期：2026-10-09。12个开发回归任务，按既定[客服契约](../../../docs/customer-service-evaluation-contract-2026-10-09.md)补标。此目录只有本地准备材料，没有模型预测、成绩、费用或在线实验结果；不能据此宣称独立盲测准确率、泛化能力或JEV收益。

`cases.json`仅使用`taskbench.Case`现有字段。`sources.json`逐条关联1220原案例库中的实际ID、文件与原文；首句原样保留，补参、状态与确认分支是新开发标注，不继承原单轮工具标签作为任务金标。原案例和历史结果不变。

## 合成fixture及可核验真值

以后显式在线运行时，每个任务、每个版本、每轮由`internal/taskbench/live.go`创建独立新租户和本租户密钥，先创建并支付5000元充值订单，得到权威账本和余额投影。这是合成隔离fixture，不是客户真实数据，也不是本轮已经创建的数据库对象。带`initial_subscription`的任务额外订购月度·标准；本集没有预先取消订阅的任务。订单、订阅、账本、余额和工具结果必须使用该任务自身fixture核对，不能跨任务复用。

套餐目录依赖运行时数据库：必须唯一匹配启用中的定期套餐`月度·标准`与`月度·旗舰`。套餐ID、价格、周期等不能猜测；准备文件不冻结数据库目录。未来运行前须保存并核对实际完整目录、价格和有效期，若套餐不唯一或初始状态不可用，记录初始化失败，不能当作客服通过或失败。5000元是充值金额，带订阅的余额必须依据实际初始快照核对，不能假设订购价格固定或扣款方式。

## 预定任务行为

| 任务ID | 首次正确动作与最终核验 |
| --- | --- |
| dev-recharge-missing | 问金额；补100元后准确预览，明确确认后增加10000分账本与一笔充值 |
| dev-refund-missing | 问金额或订单；补按金额100元后预览，确认后减少10000分并新增退款流水，充值订单保持原状 |
| dev-subscribe-missing | 问目标套餐；补标准套餐后预览并确认，新增正确标准订阅 |
| dev-change-missing | 问目标套餐；补旗舰后预览并确认，现有标准订阅仅设置下一期旗舰目标 |
| dev-recharge-ready | 已给50元，直接复核预览；确认后充值50元，不能重复索要金额 |
| dev-subscribe-ready | 已给标准套餐，复核预览；确认后新增正确标准订阅 |
| dev-recharge-cancel | 正确500元预览后用户取消；清除待确认，业务状态完全不变 |
| dev-change-cancel | 正确旗舰变更预览后取消；清除待确认，标准订阅及业务状态不变 |
| dev-recharge-repeat | 正确100元预览后确认、再次确认；只发生一次充值及一次账本增加 |
| dev-balance-read | 查本人余额并给出与工具及快照一致的金额；业务状态不变 |
| dev-subscription-read | 查询并正确说明本租户标准订阅身份与状态；业务状态不变 |
| dev-subscription-cancel | 退订预览后确认；原订阅取消自动续费并记录取消状态，保留其他业务状态 |

缺参任务第一轮不能写入或猜参数。所有写任务确认前不能修改业务状态；首轮必要追问本身正确但补参后未完成，不算整个任务通过。查询、预览与最终回答还需满足现有`internal/taskbench/score.go`保守文本规则和真实状态核验；文本规则不是语义人工金标，不能覆盖所有等价自然语言表达。

## 版本与校验

`manifest.json`记录版本、任务数、三个交付文件的SHA256。Go本地测试验证可加载、源ID及原文和冻结文件哈希。任何标注改动应创建新版本目录，不能在看到本轮预测后覆盖此冻结版本。fixture代码、完整源代码和将来使用的二进制另由prepare-only准备清单绑定；本目录manifest不声称已冻结数据库、服务配置或模型版本。

本轮仅运行本地测试和离线准备；正式在线V1/V2、未用于开发的冻结验收集、阈值校准及多轮统计实验留待后续独立批次执行。
