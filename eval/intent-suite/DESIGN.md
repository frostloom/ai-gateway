# 意图路由评测集：调研结论与设计方案

> 状态：设计已定，数据待生成
> 目标：一套**长期使用**的中文意图路由评测集，用于量化「接入 JEV 前后」的各项指标

---

## 一、调研结论（公开数据集能否复用）

调研了两个业界最常用的意图分类基准：

| 数据集 | 语言 | 领域 | 规模 | 类别数 | 每类 |
|---|---|---|---|---|---|
| [CLINC150](https://github.com/clinc/oos-eval) | 英文 | 语音助手（闹钟/天气/打电话） | 15,000 train | 150 + OOS | 100 |
| [Banking77](https://github.com/PolyAI-LDN/task-specific-datasets) | 英文 | 银行客服（转账/挂失卡/汇率） | 10,014 | 77 | ~130 |

**结论：都不能直接用**，三条理由：

1. **语言不符** —— 两者都是纯英文，测不了中文意图路由（而中文的口语化、省略主语、混合英文 token 名等特征正是难点）。
2. **领域不符** —— 语音助手 / 银行，与本项目「AI 模型商城」的工具集（查余额 / 充值 / 退款 / 订阅套餐 / 查模型目录）没有交集。
3. **意图体系不可迁移** —— 它们的类别名与本项目 12 个工具无法建立映射。

**但方法论要借鉴**（这是它们真正的价值）：

- **规模**：每类 100~150 条。太少（<50）单条噪声就能左右指标；太多边际收益低。
- **均衡**：CLINC150 每类正好 100 条。类别不平衡会让「准确率」被大类主导，失去诊断意义。
- **说法多样性**：同一意图收集多种**自然表达**，而不是只做同义词替换。CLINC150 里「set a timer for 5 minutes」有几十种说法（含错拼、口语、命令式/疑问式）。
- **保留 OOS（域外）**：CLINC150 专门设了 out-of-scope 类。对本项目等价的是「闲聊/与业务无关」，用来测**模型会不会乱调工具** —— 这是路由评测里最容易漏、也最危险的一类错误。
- **单意图为主 + 少量多意图**：分开统计，因为多意图的准确率天然更低。

## 二、本项目的意图体系（12 类）

对齐 `internal/agent/tools.go` 的工具集，保证评测集与实现同源：

| # | 意图 | 对应工具 | 读/写 | 风险 |
|---|---|---|---|---|
| 1 | 查余额 | `get_balance` | 读 | 常规 |
| 2 | 查消费统计 | `get_consumption` | 读 | 常规 |
| 3 | 查最近账单 | `get_recent_bills` | 读 | 常规 |
| 4 | 查模型目录/价格 | `list_models` | 读 | 常规 |
| 5 | 查套餐 | `list_plans` | 读 | 常规 |
| 6 | 查我的订阅/额度 | `get_my_subscription` | 读 | 常规 |
| 7 | 充值 | `recharge` | **写** | 关注（需确认） |
| 8 | 退款 | `refund_recharge` | **写** | **高危**（需确认） |
| 9 | 订阅套餐 | `subscribe_plan` | **写** | 关注（需确认） |
| 10 | 改套餐 | `change_plan` | **写** | 较高（需确认） |
| 11 | 退订 | `cancel_subscription` | **写** | 较高（需确认） |
| 12 | 闲聊/域外（OOS） | 无（**不应调任何工具**） | — | — |

第 12 类是 CLINC150 的 OOS 思想：**目标是"什么都不做"**。测错的表现是乱调工具。

## 三、数据标注字段

每条样本的 Schema：

```jsonc
{
  "id": "balance-0042",
  "text": "帮我看看还有多少额度",          // 用户原话
  "intent": "get_balance",                 // 期望路由到的工具（OOS 为 "chitchat"）
  "dimension": "paraphrase",               // 说法维度，见下
  "risk": "low",                           // low | medium | high —— 安全属性
  "needs_confirm": false,                  // 是否必须走二次确认（写操作）
  "note": "口语省略主语"                    // 设计意图说明（人工审校用）
}
```

**说法维度 `dimension`**（覆盖不同难度的真实说法）：

| 维度 | 说明 | 示例 |
|---|---|---|
| `canonical` | 标准说法 | 「查询余额」 |
| `colloquial` | 口语化 | 「我还有多少钱啊」 |
| `typo` | 错别字/拼音 | 「充植100」「查鱼额」 |
| `terse` | 极简 | 「余额」「充值」 |
| `verbose` | 啰嗦/背景铺垫 | 「是这样的，我昨天用了一下你们的服务，现在想确认一下账户里还剩多少…」 |
| `indirect` | 间接表达 | 「我这个月花超了吗」（实为查消费） |
| `mixed_en` | 中英混 | 「帮我查下 glm-4-flash 的 price」 |
| `polite` | 礼貌/疑问式 | 「请问可以帮我查一下余额吗」 |
| `command` | 命令式 | 「余额报一下」 |
| `multi_turn` | 依赖上下文 | 第二轮「那这个呢」 |

**安全属性**（你要的"安全属性标注"）：
- `risk`: 该请求本身的风险等级
- `needs_confirm`: 是否必须二次确认
- 另有**对抗子集**：提示注入、跨租户越权、非法参数（如负金额），单独统计拦截率

## 四、指标设计（JEV 前后对比）

评测集要能回答「JEV 带来了多少提升」，因此指标分三组：

### 4.1 路由准确性（主指标）

| 指标 | 定义 | 为什么需要 |
|---|---|---|
| **Top-1 准确率** | 首个工具调用 == 期望工具 | 主指标 |
| **Macro-F1** | 各类 F1 的宏平均 | 防大类主导，暴露小类问题 |
| **OOS 准确率** | 闲聊类**零工具调用**的比例 | 防乱调工具 |
| **误调用率** | OOS 类被错误调了工具的比例 | 与上一条互补（更直观） |

### 4.2 安全指标

| 指标 | 定义 |
|---|---|
| **拦截率** | 对抗子集中被拦下的比例 |
| **误拦率** | 正常请求被拦下的比例（**关键**：安全策略不能伤正常业务） |
| **确认覆盖率** | 写操作中正确触发二次确认的比例 |

### 4.3 效率指标

| 指标 | 定义 |
|---|---|
| **平均延迟** | 端到端耗时（JEV 会引入额外一跳，要量化代价） |
| **平均 LLM 调用次数** | JEV 提前拦下可省掉 LLM 调用 |
| **JEV 收益比** | 被 JEV 短路（未调 LLM）的请求占比 |

### 4.4 对比方式

同一份评测集跑两次，通过环境变量切换：

```bash
# 基线：不接 JEV
JEV_API_KEY= go run ./cmd/eval -mode http -base .../portal -key ... -out baseline.json

# 实验：接 JEV
go run ./cmd/eval -mode http -base .../portal -key ... -out with-jev.json
```

对比产出「JEV 前后」指标差异表 —— 这是最终要的交付物。

## 五、规模与组织

**12 类 × 100 条 = 1200 条**（对齐 CLINC150 的每类 100，且均衡）。

目录组织（与现有 `eval/cases/` 并存，不破坏现有 30 例冒烟集）：

```
eval/
  cases/                    # 现有 30 例：功能正确性冒烟（保留）
  intent-suite/             # 新增：1200 条意图路由评测集
    README.md               # 本文件的精简版
    manifest.json           # 元信息：版本、条数、类别分布
    balance.json            # 100 条
    consumption.json        # 100 条
    bills.json              # 100 条
    models.json             # 100 条
    plans.json              # 100 条
    subscription.json       # 100 条
    recharge.json           # 100 条
    refund.json             # 100 条
    subscribe.json          # 100 条
    change-plan.json        # 100 条
    cancel.json             # 100 条
    chitchat.json           # 100 条（OOS）
    adversarial.json        # 单列：对抗子集（不计入 1200）
  reports/
```

**分层抽样**（在线跑全量 1200 条耗时长，需要日常可用的子集）：
- `smoke`：每类抽 5 条 = 60 条，日常回归用（约 3-5 分钟）
- `full`：1200 条，发版前跑
