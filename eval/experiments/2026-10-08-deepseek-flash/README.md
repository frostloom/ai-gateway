# DeepSeek官网真实客服任务实验（2026-10-08）

新主指标是**经过独立状态核验的任务完成率**。首工具Top-1/F1/Reach继续保留作诊断，不充当业务完成率。必要追问是正常步骤：先问清金额或套餐，补全后完成原任务才算通过。所有尝试都进入分母，HTTP与fixture失败另列。

本轮使用官网`deepseek-flash`。旧实现源码为`b26642876e78255a89c87de3982888f14d6532d4`，最终优化实现为`d07e671f1ab4eaa7f1f8a5d3e3bc3711f129094b`；每组24个相同固定案例、96个不同模拟租户、同一评测器二进制与用例哈希，开关状态由实际响应遥测核验。二进制、数据集、评测器SHA256均见[机器可读对照](task-comparison.json)。旧控制二进制来源是本次会话保存的旧代码构建；源码标记由执行者记录，并非外部供应链证明。

## 追问统计核对

必要追问四类分别为充值金额、退款金额/订单、订阅套餐、改套餐目标。四组均真正追问、补槽、预览并完成；没有把首轮未调用写工具记成任务失败。旧文本规则还命中了9条“正确回答后询问要不要其他服务”的冗余追问候选，逐条复核均为已完成读取后的可选服务提示，不是阻塞当前任务的必要追问或错误。原始候选字段保留，详情见[追问复核](clarification-review.json)，不把候选数作为确认的错误数。复核者是编码代理，不冒充外部人工金标。

## 评分版本与证据保护

- 9月历史V1/V2、原401失败实验、初版诊断全部保持原字节；本目录只追加新证据。用户授权的是模拟业务数据，凭证不入归档。
- 两案例task pilot有一次失败是外部JSON用例加载复用了默认案例字段，属于评测器错误。已用红绿测试修复；保留该探针，不能把它的1/2称作客服任务能力。
- 首轮四组24案例采用`taskbench.v1`。订阅读取返回正确的套餐ID，却因规则只接受套餐名称而误判部分样本。原报告全部保留；修正规则为核验实际目录ID或名称、排除冲突后升级`taskbench.v2`，对四组完整重跑，最终表只使用这同一规则的新结果。
- 评分版本与客服版本是不同维度：用户定义无JEV为V1、有JEV为V2；这里的`taskbench.v2`只是评分规则编号，不能混称客服V2。
- 24例是开发与故障回归集，包含必要追问、完整槽位、复合读取与写入、订单退款、余额上限、下期改套餐、已满足状态、取消和重复确认。它不是未见说法的泛化测试，24/24不代表所有用户请求100%正确；某一类别的1例通过也不足以证明全面能力。
- 后续扩展应新增冻结的独立盲测集，覆盖口语、错别字、中英文混合、任务中改金额/套餐、歧义与冲突、网络失败恢复和更多对抗；多次重复实测后再报告置信区间与时间稳定性。不要用本轮修复样本代替盲测。
