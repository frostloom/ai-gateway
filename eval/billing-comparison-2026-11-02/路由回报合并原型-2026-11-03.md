# 路由回报合并原型（仅测试）

尝试方向：对于同一 provider，只合并队列中连续、互相重叠的成功回报；遇到失败回报时划分批次，逐批顺序执行数据库写，所有合并的调用只有在对应写入返回后才得到结果。它仍对数据库执行清零，不仅依赖某个路由实例内存，因此避免了“本实例跳过清零但其他实例写入失败”的已测反例。这里仅实现单 provider 的测试队列和 SQL，不含真实 router、熔断、AutoBan 或 HTTP。

`router_batch_test.go` 预先向有界队列放入 32 个成功、1 个失败、1 个成功，再启动单 worker 并在第一次 DB 写入前阻塞：阻塞期间成功和后续失败均未返回；放行后顺序执行 3 次 SQL，最终数据库失败计数为 0。删除测试表模拟 SQL 错误时，16 个成功等待者均得到错误而非成功。`bash eval/billing-comparison-2026-11-02/run-router-batch.sh` 在随机隔离 MySQL/Redis 和 race 下各跑三次通过；原始 `router-batch-final.txt`。初始 stub 未实现而产生的预期失败保留 `router-batch-red.txt`。

这只证明预先排队的受控顺序，**不是并发流量性能结果**：真实流量能否在同一批次相遇未知。原型队列满时阻塞，没有请求取消、关闭与排空、超时、数据库重连、跨实例顺序、部分提交、进程崩溃、状态丢失、熔断/半开/AutoBan、多个 provider 公平性或过载保护。特别是它不能替代当前 `Registry.Report`，也未验证成功与失败回报跨实例的实际时序；现有接口记录数据库错误但仍返回 HTTP 成功，测试原型显式返回错误，语义不同。需要先定义这些语义并使用真实 router 的故障与性能对照，不能据此上线或声称提升。

## 补充：持续并发 SQL 局部负载和背压

`bash eval/billing-comparison-2026-11-02/run-router-batch-load.sh` 在隔离 MySQL 中按 32、128 worker、每组 2 秒闭环并排空，三轮且第二轮反转顺序，比较单互斥锁串行执行每次清零与该单 worker 合并原型。所有请求均为同一 provider 的成功回报；这是 SQL 局部请求次数，不是网关请求/秒，也没有网络、熔断、AutoBan、真实 provider 或故障处理。完整 JSON 在 `router-batch-load-output.txt`；性能运行未启用 race，使用共享本机，所有组报告错误 0，但未单独采集超时数、CPU 或 I/O。

| worker | 逐次 SQL 成功/秒（三轮） | 合并成功/秒（三轮） | 逐次 P95 ms（三轮） | 合并 P95 ms（三轮） |
|---:|---|---|---|---|
| 32 | 485、514、606 | 8911、10381、9452 | 127.0、126.7、85.1 | 6.85、4.43、5.82 |
| 128 | 516、597、512 | 46122、44248、46024 | 369.1、250.3、518.9 | 5.27、5.85、5.47 |

例如第一轮 128 worker 合并 92397 个回报为 1106 次 SQL；这是在持续全成功、同一记录且闭环堆积的极端条件下观察到的，不可解读为生产容量或整网关收益。样本短、合成场景偏向批量，失败回报、provider 分散和队列延迟可能显著改变效果。

`TestBatchedReportFullQueueBlocksUntilDrained` 另确认测试队列填满后下一次入队会阻塞，直到 worker 开始排空；race 模式三轮与原有顺序/数据库失败测试一同通过，输出 `router-batch-backpressure.txt`。这说明当前候选没有可取消或限时的过载处理，数据库长时间故障可能堆积阻塞请求；测试通过是对现状的观察，不代表可上线。关闭竞态、取消后的结果不确定、跨实例、半开探测及持久化语义均仍待设计和验证。

## 补充：非阻塞准入、关闭与结果未知

测试专用 `router_batch_bounded_test.go` 在原 worker 外加 mutex 保护的非阻塞准入：队列满返回 `errBatchFull` 且不接收，关闭后返回 `errBatchClosed`；已接收任务的调用方等待超时时返回 context 错误及 unknown 标志，任务仍由 worker 执行，不能因此自动重试。关闭只阻止新提交并让已接收任务排空。先以 stub 获得预期失败 `router-bounded-red.txt`，然后 `bash eval/billing-comparison-2026-11-02/run-router-bounded.sh` 在随机隔离 MySQL/Redis 下以 race 执行三轮，队列满、超时后排空和重复关闭通过；64 个并发提交与关闭竞争时，三轮分别有 63、4、24 个提交被接收，全部接收任务完成，其他被明确拒绝，日志 `router-bounded-final.txt`。

这是进程内可控关闭，不是进程崩溃后的持久队列；没有验证已接收但未写入的任务在崩溃后恢复，也没有数据库卡住、提交结果不明、取消与发送同时发生、失败回报的饱和策略或实际 HTTP 返回/重试策略。候选仍未集成真实熔断和网关，非生产就绪方案。之前的 SQL 局部性能数值测的是旧版阻塞准入原型，并不自动适用于本非阻塞准入版本。
