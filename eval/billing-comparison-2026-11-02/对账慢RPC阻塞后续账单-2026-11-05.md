# 对账单笔 RPC 阻塞后续账单

当前 `SweepOnce` 按账单 ID 串行等待每次结算 RPC；常驻进程 `Run` 使用信号取消的长生命周期 context，调用本身没有独立期限。隔离 MySQL 中插入两笔过期、有 usage 的合成 pending，第一笔 Settle 测试替身在收到调用后阻塞，观察 500ms；三轮均只有第一笔到达替身、扫描未返回。释放后第二笔才被调用，扫描退出。测试替身返回合成成功，不执行真正结算；PASS 表示指定阻塞得到复现，不表示账单已恢复。

日志 `reconciler-stalled-rpc-20261105.txt`（SHA-256 `4feea4f83fa2beb4bfe6e7cf8ab8a723c130e2288d9e08b23de6c4d2922bffa`），隔离 MySQL/Redis、Go race 三轮。复现：

```sh
TEST_USAGE_RACE_PATTERN='^TestReconcilerBlockedRPCDelaysLaterBill$' \
 bash eval/billing-comparison-2026-11-02/run-reconciler-usage-scan-race.sh
```

这不模拟真实 gRPC 网络分区或数据库故障，也不测卡住的发生概率。超时只能限制等待，不能证明账务没有提交；若加入期限，必须保留相同账单身份的幂等重试和提交结果未知语义，并验证取消、批量积压、竞争与恢复。逐笔期限也不能单独保证大积压的整轮完成时间；此处未修改生产扫描器。测试与正在进行的独立完整网关用量确认丢失实验使用各自隔离容器。
