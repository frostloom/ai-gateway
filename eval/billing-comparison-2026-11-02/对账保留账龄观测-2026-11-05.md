# 对账保留账龄观测

当前工作树的 `reconciler` `/status` 新增两个字段：`last_observed_at` 为 `RecordStats` 保存最近一次状态的 UTC 时间，尚未保存时为 null；`last_held_oldest_created_at` 为该次扫描实际计入 `Held` 的无 usage pending 中最早创建时间，没有计入时为 null。读取时两个字段与 `last_held` 在同一互斥锁下复制。计算复用扫描中已读取的时间，不增加数据库查询或账务写入。

它们不是实时全库统计：扫描分页期间账单可能变化，部分扫描失败可能仅有部分结果，服务重启后内存状态丢失；`last_observed_at` 是状态记录时刻，不保证 sweep 开启、成功或刚完成。必须同时检查 `last_sweep_attempted`、`last_sweep_error`、每项错误及时间；零 held 或 null 最早时间不证明没有未知账单，也不能用于自动退款。当前没有唯一积压数量、金额、持久告警、人工处置或授权检查。`/status` 已有的网络访问控制和部署策略未在此修改，新增时间字段不含请求 ID 或租户 ID。

隔离 MySQL/Redis 使用真实 `SweepOnce`、`RecordStats`、HTTP handler recorder，插入两笔超过宽限的不同账龄合成账单及一笔未到期账单：修复前因缺失 `last_observed_at` 三轮失败；修复后三轮 race 验证初始 null、held=2、最早时间、记录时间和下一次空状态清除。单独新容器中，已有默认保留和仅结算测试各三轮通过，已报用量账单 settled、未知账单 pending、余额和账本 860。上述分别在隔离容器运行，HTTP 为进程内 recorder；没有验证真实 HTTP 进程、生产监控、部分扫描失败或大积压时性能。`go test -race -count=1 ./internal/billing/reconciler ./cmd/reconciler` 两包无测试文件，只确认编译；未执行全仓测试。
