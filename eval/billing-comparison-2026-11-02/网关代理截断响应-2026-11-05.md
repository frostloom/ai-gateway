# 网关代理截断响应验证

受控测试发现，`internal/gateway/handler/admin.go` 的共享 `proxy` 曾忽略 `io.ReadAll` 错误，并在读取正文前转发 Cookie。上游声明 Content-Length 后提前结束时，真实 `/portal/me` 网关路由三轮均返回 200、部分 JSON 与 Cookie（见 `portal-proxy-truncated-red-20261105.txt`）。该路由经真实 API Key 中间件及隔离 billing gRPC 鉴权；HTTP 上游是人为截断响应的本地模拟服务。

现在代理先完整读取正文，出错时记录错误并返回 502，不发送上游正文或 Cookie；完整响应保留原状态、正文和 Cookie。`portal_proxy_truncated_response_test.go` 在隔离 MySQL 8.0.40、Redis 7 和 loopback 服务上以 race 运行三轮，截断、正常 200 和完整 500 场景均通过（`portal-proxy-truncated-green-20261105.txt`）。网关 handler、middleware、client 包 race 通过，日志为 `portal-proxy-gateway-race-20261105.txt`，有 macOS 链接器警告。`git diff --check` 通过。

本次记录的 HEAD 为 `457dbfc3fee2e7b1575a29eab033439833985ce6`，测试包含工作树未提交修改，不等同该提交的干净源码。模拟截断不能证明此前自然 502 的根因；本测试也不覆盖流式聊天、上游超时的所有时序或整体容量。`RegisterAdmin` 的独立 chat 代理使用另一段代码，不在此次修复范围。

## 管理聊天独立代理补充

随后检查 `RegisterAdminChat`，发现同样忽略响应正文读取错误。`admin_chat_truncated_test.go` 使用本地模拟 Agent，通过真实管理聊天路由复现：三轮截断都错误地返回 200 和部分 JSON，原始输出 `admin-chat-truncated-red-20261105.txt`。该测试直接注册路由，没有运行管理员 session 中间件，不证明鉴权中间件的行为。

修复读取错误后，三轮 race 测试均通过：截断返回 502、正常 200 和完整 503 原样转发，且本地 Agent 检查了内部凭证及租户 ID 头（`admin-chat-truncated-green-20261105.txt`）。相关三个网关包 race 回归通过（`admin-chat-gateway-race-20261105.txt`；其中 middleware 与 client 使用 Go 测试缓存），链接器警告保留。测试未调用真实模型，也不覆盖流式接口、Agent 侧操作是否已完成或重试幂等性。以上补充覆盖管理聊天代理，前段“不在此次修复范围”仅描述最初门户测试时的状态。
