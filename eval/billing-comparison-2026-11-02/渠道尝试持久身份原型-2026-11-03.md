# 渠道尝试持久身份与结果事件原型（测试专用）

`router_attempt_state_test.go` 在独立测试表中定义尝试记录：按 `(tenant_id, request_id, ordinal)` 唯一，首次生成随机 attempt ID 并持久化；同 scope 同 provider 重试读取原 ID、不同 provider 冲突。`prepared→sending` 使用条件更新，只允许一个调用者取得发送许可；sending 意味着上游结果可能未知，不自动再次发包。已知结果时在同一 MySQL 事务将状态推进为 completed 并插入以 attempt ID 为键的测试 Outbox；重复同结果不重复写，不同结果冲突。这里的 Outbox 只有测试字段，不是项目正式消息协议。

`bash eval/billing-comparison-2026-11-02/run-router-attempt.sh` 在新建 MySQL/Redis 和 race 模式下三轮通过（`router-attempt-final.txt`）：16 个并发准备得到同一 ID；不同账户/ordinal 得到不同 ID；16 个并发发送许可仅一人成功；16 个并发完成仅一次创建事件。故意让 Outbox 插入报错，状态和事件同事务回滚，再重试成功。随后从测试 Outbox 手工读取同一事件并两次调用独立的 `applyReportEventsBulk` 接收原型，失败计数只加一次；此为函数级重复投递模拟，不是 Kafka/relay 投递测试。

真实子测试进程分别在 sending 已提交和 completed+Outbox 已提交后输出信号，父进程强制杀死并回收子进程。前者保留结果未知、拒绝再次发送且没有结果事件；后者保留 completed 和一条事件，重复完成不再写入。两个切点各三次通过；没有真实模型请求，也未杀数据库或网络。初始 stub 的预期失败保留 `router-attempt-red.txt`，早期结果保留 `router-attempt-green.txt`、`router-attempt-process.txt`。容器已清理。

**未集成和重要限制：**准备/发送尚未与已有请求 gate、余额预占、自动冲正、router、gateway 或 Kafka relay 协调。外部调用可绕过状态机，调用者也可能换 ordinal 绕过未知 sending；`request_id` 尚无业务参数指纹绑定或历史迁移，provider/tenant 权限未校验。sending 在真正发包前崩溃也会被保守地留作未知，不能推断供应商是否执行或自动释放/重发。未知结果查询、可靠 outbox claim/重投、批处理、失联恢复、多实例、订单/订阅、时钟、事件清理和性能均未覆盖。此原型不能部署，也不是端到端恰好一次证明。

## 补充：父请求指纹、顺序与安全重试条件

测试专用 `router_attempt_guard_test.go` 以父请求行锁绑定预存 fingerprint，串行创建 ordinal：重复同一 ordinal/provider 读取原 ID；不同 fingerprint 或已尝试过的 provider 冲突；前一个尝试未完成、序号跳跃、前一个成功均禁止创建下一尝试。16 个并发创建下一尝试只得到一个持久 ID；不同 tenant 分开。最初绕过父守卫的测试先在 fingerprint 冲突处失败（`router-attempt-guard-red.txt`），初版又暴露同 provider 可重复使用（`router-attempt-provider-red.txt`）。

更重要的是，初版仅凭 `outcome=false` 允许下一尝试；`router-attempt-ambiguous-red.txt` 证明未验证的普通失败也会被允许。现有测试候选将其收紧：必须同时存在 `retry_safe=true` 才可继续。测试使用**直接 SQL 人为设置**该标志，作为“外部已有可信证据”的替身；此项目和该原型尚未实现产生、认证或验证该证据的机制，因此这不是自动判定上游未执行的方案。`bash eval/billing-comparison-2026-11-02/run-router-attempt-guard.sh` 在隔离 MySQL/Redis 下 race 三轮通过，输出 `router-attempt-guard-safe-final.txt`；原尝试状态/Outbox/子进程回归另三轮通过 `router-attempt-with-safe-final.txt`。

父表创建和 fingerprint 生成仍由测试直接写入，不是实际请求体的完整、可信绑定；旧代码仍可直接调用未受约束的 `prepareAttempt` 或 Store。状态机未与发送、收费、失败类型、路由排除、租约所有权、人工核查和 Outbox relay 集成。这里不能声称任何已有失败安全重试，也不能部署。
