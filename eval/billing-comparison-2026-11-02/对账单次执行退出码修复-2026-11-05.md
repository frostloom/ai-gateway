# 对账器单次执行退出码

当前工作树 `cmd/reconciler/main.go` 的 `-once` 原来对扫描、单笔 RPC 和重建错误仅记录日志，仍以退出码 0 结束。依赖退出码的调用方可能误认为处理成功。使用隔离 MySQL/Redis、模拟账单和关闭的本地 billing 端点执行真实编译的 reconciler：修复前三轮均报告 `recon settle` 连接失败却退出 0，安全断言失败；原日志 `reconciler-once-exit-red-20261105.txt` 保留。

现工作树中 `-once` 对扫描或重建顶层错误、逐笔结算/冲正 RPC 错误和逐租户重建 RPC 错误返回退出码 1，结束日志附错误计数。默认将无用量账单保留 pending 是策略结果，本身不算执行错误；退出码 0 因而不能证明没有待处理账单。常驻 `Run` 行为不变，也没有增加自动修复或告警。

隔离实进程验证三轮：有 usage 的账单遇到不可连接 billing 时退出 1 且仍 pending；无 usage 默认保留并退出 0；显式打开旧自动冲正时 RPC 失败退出 1；重建 RPC 失败退出 1；禁用两种操作退出 0。测试 harness 开启 Go race，子进程使用普通 `go build`，不是子进程 race 构建。只注入了本地连接拒绝，未覆盖顶层扫描查询出错、真实网络分区、服务响应不确定、单次成功结算、操作超时或生产调度器行为；未验证整仓测试。独立编译检查 `go test -race ./cmd/reconciler ./internal/billing/reconciler` 通过，但两个包没有测试文件。
