# 网关鉴权错误分类修复

`internal/gateway/middleware/apikey.go` 原来把 billing 验证返回错误和无效密钥均映射为 HTTP 401。隔离压测日志显示真实有效测试密钥的部分验证 SQL context 超时；不能据此判定每个 401 的原因，但该错误映射确实把服务异常呈现为凭据无效。

修复后：无凭据及验证成功但无效继续返回 401；验证 RPC 错误或异常空响应返回 503、通用 `api_error`，不回传底层错误或明文密钥；有效身份保持透传。中间件参数改为只含 ValidateAPIKey 的接口以便隔离测试，实际 gateway 仍传原 Billing 客户端；浏览器会话分支原有逻辑未改，legacy API Key 分支复用此修复。此修复是可观察语义变化，并非降低真实错误率的性能优化。客户端如果针对 401/503 采取不同重试或告警，应在上线前验证，避免无界重试加剧拥塞。

`TestAPIKeyDistinguishesAuthenticationOutage` 测试有效、无效、服务错误和空响应，验证身份与不泄露上下文；`TestPortalSessionBoundary` 一并运行。命令：

```sh
SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk GOPROXY=off GOTOOLCHAIN=local \
  go test -race ./internal/gateway/middleware -run '^(TestAPIKeyDistinguishesAuthenticationOutage|TestPortalSessionBoundary)$' -count=1 -v
SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk GOPROXY=off GOTOOLCHAIN=local \
  go test ./cmd/gateway ./internal/gateway/handler -run '^$'
```

定向及构建检查通过；未运行全部 gateway 集成测试（部分已有测试硬编码 Redis 地址，不可连接既有环境）。尚未部署或提交。
