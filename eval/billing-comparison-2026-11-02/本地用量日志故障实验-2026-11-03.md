# 本地用量日志：隔离故障实验

## 原型和目的

此前 MySQL 在用量收件箱写入前崩溃时，测试 handler 已收到模拟上游结果但没有可恢复的用量。本实验仅在测试目录探索单节点补救：`local_usage_journal_test.go` 将合成用量写到测试临时目录，文件名为 request ID 的 SHA-256；临时文件限制 0600、写入并 `Sync`，以硬链接不覆盖已有目标，随后同步目录。同请求相同参数可重试，不同参数冲突。该代码不是生产 WAL，无调度、索引或删除流程。

`go test -race ./eval/billing-comparison-2026-11-02 -run '^TestLocalUsageJournalSurvivesProcessDeath$' -count=3 -v` 三轮：子进程确认写入完成后实际杀死并回收，父进程从同一本地目录读取；16 个 goroutine 并发重写相同内容均返回成功，不同用量被拒。日志 `local-usage-journal-green.txt`；未实现时预期失败 `local-usage-journal-red.txt`。这只测试进程死亡，未断电、重启机器或破坏磁盘；调用文件/目录 Sync 不等于证明底层硬件掉电持久性。

## 真实 MySQL 容器中断组合

`TEST_HANDLER_INBOX=1 TEST_HANDLER_INBOX_DB_KILL=1 TEST_HANDLER_LOCAL_JOURNAL=1 bash eval/billing-comparison-2026-11-02/run-execution-gateway-test.sh --candidate`：V4 测试 Store、真实 handler、本地模拟上游、测试 bridge/状态服务、隔离 Redis 和 MySQL。测试在收件箱 INSERT 前杀死本次专用 MySQL，测试 bridge 在收件箱写失败后写本地日志；MySQL 重启后，测试人工将本地记录写入收件箱并调用恢复器。测试人为改旧账单和租约以触发对账，不是真实等待 600 秒。流和非流各三轮 race：每次上游调用 1 次、handler 记录器为 200、账单最终 settled、reserve/usage/settle 三条指定事件、无 reverse，Redis/账本流式为 958、非流式为 960。输出 `local-usage-mysql-crash-recovery.txt`，日志中的 unexpected EOF 是主动终止数据库。

反例 `TEST_HANDLER_INBOX=1 TEST_HANDLER_INBOX_WRITE_FAIL=1 TEST_HANDLER_LOCAL_JOURNAL=1 TEST_HANDLER_LOCAL_FAIL=1 bash eval/billing-comparison-2026-11-02/run-execution-gateway-test.sh --candidate`：使用应用回调拒绝收件箱写入，并将本地日志目录设为不存在；流/非流三轮均无持久用量，测试状态机保留 pending，记录器仍为 200。日志 `local-usage-dual-failure.txt`；通过表示**重现双写失败的未解决状态**，不是安全通过。该反例不模拟真实磁盘满、权限变化或断电。

## 不可上线的原因

- 本地目录仅用于 `t.TempDir`；节点或磁盘永久丢失、容器更换节点、多个节点写同一请求、持久卷挂载和数据迁移均未解决。未测试机器断电、磁盘写入顺序或损坏。
- 仅在测试进程发现 MySQL 写失败后才写日志；上游响应到日志同步之间进程死亡仍丢失用量。无可靠的系统级事务保证或可信供应商用量来源。
- 没有正式身份、租户/attempt 授权、加密、限额、清理、审计、监控、重放调度或操作隔离。最初测试 bridge 对任意 MySQL 写错误都尝试落本地文件，包括参数冲突；见下方补充的测试候选修正。生产协议仍必须严谨区分永久冲突和未知提交并校验来源。
- 旧网关、旧对账器及直接调用仍可绕过 forwarding 状态；测试依赖人为介入恢复，不能自动保证不冲正未知请求。日志文件始终保留，未实现清理及冲突处置。
- 没有测试真实 gRPC、端到端响应网络语义、持久消息投递、订阅/充值、并发性能和长期容量；`httptest.ResponseRecorder` 的 200 并非网络客户端证据。

结果仅说明，在被测的 MySQL 提交前故障和可用本机磁盘条件下，已同步的合成用量可由测试程序人工重放；它不构成安全可部署方案。

更改后不启用实验变量的原 handler 五模式 race 回归三轮通过，见 `local-usage-gateway-regression.txt`；不代表全仓库回归。

## 补充：参数冲突不能当作连接故障

在隔离 MySQL 中先保存一条用量，再经测试 bridge 对相同 request ID 提交不同 completion token。旧逻辑将冲突内容写成本地日志，安全断言三轮预期失败，见 `local-conflict-red.txt`。测试 bridge 现仅对 `DeadlineExceeded`、数据库驱动的连接失效、EOF 和 `net.Error` 尝试本地回退；冲突、取消、找不到记录和未知错误不回退。真实数据库冲突测试及三个进程中断后的原恢复断言三轮通过，见 `local-conflict-green.txt`；类型分类和本地文件进程死亡测试 race 三轮见 `local-conflict-classification.txt`。

限制分类后重新真实终止/重启隔离 MySQL，流和非流各三轮仍写入本地日志并经测试人工重放结算（`local-conflict-mysql-regression.txt`）。另用测试 EOF 注入配合不存在的本地目录，三轮确认双失败仍保留 pending 而非虚报已保存（`local-conflict-dual-regression.txt`）。这些测试不覆盖全部驱动错误或网络错误类型；`net.Error` 并不必然意味着可安全重试，连接错误也可能发生在数据库已提交之后。真实系统还需通过持久请求身份核对未知提交、隔离冲突并验证权限，不能把类型分类当成正确性或生产恢复保证；上文不可部署的限制保持不变。

## 补充：MySQL 已提交但调用方看到 EOF

`TEST_INBOX_ACK_UNKNOWN=1 TEST_LOCAL_CONFLICT_GUARD=1 bash eval/billing-comparison-2026-11-02/run-usage-inbox-test.sh --candidate` 使用测试 SQL 驱动包装器：先调用真实 MySQL `Commit` 并等待成功，再向测试 bridge 返回 `io.EOF`。三轮 race 发现收件箱和本地日志均存在相同用量；随后直接以本地数据再次写入收件箱只保留一行，不同用量被冲突拒绝，接着执行原有三个子进程终止及并发重放，最终账务事件、余额和账本核对通过。日志 `inbox-ack-unknown-green.txt`。原测试包装器只返回自定义错误、不满足 EOF 注入预期，故先得到 `inbox-ack-unknown-red.txt`；那是测试注入能力缺失，不是产品 bug。修改共用注入器后，原完成事件恢复测试的提交错误、数据库断连及重试 race 三轮回归通过，见 `inbox-ack-shared-helper-regression.txt`。

这是在驱动包装层模拟“提交成功后调用方看到 EOF”，不是实际 TCP 连接在提交确认期间断开；测试的重放由调用者手工执行，未实现自动扫描、并发冲突隔离或日志清理，也没有证明不同节点/不可信用量/订阅/网络分区的安全性。本地日志与数据库一致仅覆盖合成测试记录；遇到冲突仍需人工处置和正式授权。原型不能部署。

## 补充：测试扫描器对坏记录的隔离

`local_usage_recovery_test.go` 新增测试扫描函数：逐个读取目录内 `.json` 记录，检查普通文件、大小及文件名与 request ID 的哈希对应，调用测试收件箱的身份与参数检查，再调用现有测试重放；任何单条错误计入失败并继续下一条，**所有文件均留在原位**，没有真正的隔离目录或删除流程。函数只返回本轮成功/失败计数，不返回错误明细；重复扫描的成功数不是新增结算数。

`TEST_LOCAL_RECOVERY_SCAN=1 TEST_LOCAL_SCAN_CONCURRENT=1 bash eval/billing-comparison-2026-11-02/run-usage-inbox-test.sh --candidate` 在隔离 MySQL/Redis、V4 Store overlay 和 race 下三轮：准备一条有效记录、一条与数据库已有用量冲突的记录和一条损坏 JSON；四个同进程扫描者并发执行后再扫描两次。每次扫描各观察一条成功、两条失败；有效账单最终 settled 且一条 settle，冲突账单仍 pending/无 usage，指定事件及余额/账本 358 一致，损坏和冲突文件均保留。输出 `local-scan-concurrent-final.txt`；未实现时预期失败保留在 `local-scan-red.txt`。四个成功计数不能相加当作四笔结算，测试实际核对的是一条 settle。

这只是测试扫描函数，无自动运行、分页、公平性、退避、错误详情、告警、权限、隔离目录或清理；文件检查和读取之间有竞态，不可用于不可信目录。未覆盖真正多进程扫描、节点磁盘丢失、篡改文件、进程在本地写入前死亡、生产混版、真实服务授权及网络故障。先前“未实现自动扫描”的限制对生产仍然成立；该实验不构成自动恢复上线能力。

## 补充：真实 handler 子进程在本地日志同步后死亡

`bash eval/billing-comparison-2026-11-02/run-handler-journal-process.sh --candidate` 在独立 MySQL/Redis 中运行 V4 Store 和真实 handler；handler 位于独立测试子进程，通过测试 gRPC capability 取得 forwarding 后向父进程的本地模拟上游发送一次请求。测试 bridge 在拿到合成用量后终止本次专用 MySQL，使用本地日志回退并完成文件与目录同步，发出测试标记后由父进程实际杀死并回收 handler 子进程。此时 handler 没有完成对客户端的响应，不能称客户端收到 200。父进程重启 MySQL，确认账单 pending 且无 usage，调用测试扫描函数两次，再核对账单、结算记录、事件及余额。

race 三轮均通过：模拟上游各一次，首次和重复扫描均处理同一条已保存记录；最终账单 settled、settle 行一条、reserve/usage/settle 指定事件各一条且 reverse 事件零条，Redis 与账本均 458。原始输出 `handler-journal-process-final.txt`，早期通过输出 `handler-journal-process-green.txt`。未实现日志的首次测试 `handler-journal-process-red.txt` 首轮未收到同步标记；其后两轮因测试数据库重启尚未就绪而提前失败，不能解释成业务结果。数据库错误日志是主动终止测试容器导致。

这是 **handler 所在测试进程**在日志已成功同步后被杀，恢复在父测试进程人工调用；真实上游为本地替身，handler 使用 `ResponseRecorder`，没有对外 HTTP 响应或生产 RPC。并未验证日志同步前崩溃、节点/磁盘丢失、自动调度、实际对账期间进程死亡、真实租户授权、旧实例绕过或消息投递。测试证明特定单机切点可以保留用量并幂等补结算，不证明模型调用恰好一次或原型可部署。

## 补充：上游已响应、本地日志写入前进程死亡

`TEST_KILL_BEFORE_LOCAL=1 bash eval/billing-comparison-2026-11-02/run-handler-journal-process.sh --candidate`：真实 handler 的测试子进程先收到父进程本地模拟上游的完整合成用量，测试 bridge 终止专用 MySQL 后，在尝试写收件箱或本地日志**之前**发出标记；父进程立即杀死并回收该 handler 子进程、重启数据库。三轮 race 均观察到：模拟上游收到一次；本地日志和 MySQL 收件箱均无用量；扫描器无可恢复记录。测试人为将账单及 lease 改到过去后，真实 `SweepOnce` 经测试 bridge 不冲正，测试 capability 同样不授予重新发送或退款许可；账单保持 forwarding/pending、无 usage，指定事件仅 reserve，Redis 与账本均为 499。最终输出 `handler-before-journal-guards-final.txt`。这是**保守保留未知**，不是结算或恢复成功；进程终止前 handler 未完成向客户端响应。

首次 `handler-before-journal-red.txt` 因尚未实现测试切点而收到同步后标记；其后两轮测试数据库重启未就绪，不能当业务结果。首次实现后的 `handler-before-journal-green.txt` 因测试误把合成短请求的 1 分预占当作 100 分，且没有及时恢复上一轮人为改旧时间而失败；修正测试预期和每轮清理后得到 `handler-before-journal-final.txt`，再加入拒绝重发/退款及 reserve 事件断言后得到最终输出。同步**之后**的原进程死亡场景另外 race 三轮复验通过，见 `handler-after-journal-regression.txt`。

此测试明确证明：本地日志无法挽救写入前的进程死亡；测试状态机只避免猜测性重发和退款，无法知道真实供应商是否收费，也没有可信方式恢复已丢失的用量。账单时间、lease 被人工修改，测试 bridge/权限和旧实例绕过仍非生产安全保障；真实配置的自动化人工核查、监控和外部对账机制尚未实现。

## 与当前完成观察候选组合时的身份缺口

## 测试专用携带完成尝试 ID 的记录

## 测试 bridge 自动捕获及本地目录不可用
