# 用量确认后才结算

工作树 `internal/gateway/handler/chat.go` 的 `settleAndLog` 先调用 `ReportUsage`，原来只检查 RPC error，忽略返回的 `accepted` 和空回复；若调用方收到 `accepted=false` 且无错误，仍调用 Settle。真实当前 billing 服务只在 Store 成功后返回 `accepted=true`，此处不是宣称当前服务会正常返回 false；这是对其他实现、异常桥接或未来协议变化的防御。当前 Store 自身对无用量结算也有检查，本报告不声称已发生错误收费。

现只有非空且 `accepted=true` 才调用 Settle，错误、空回复或 false 都记录错误并保留后续处理。该修改不增加用量持久化，不保证消息送达，也没有改变返回客户端的 HTTP 行为。特别是流式正文已经发送后，可能仍为 200，而账单没有 usage 且 pending；默认对账器保留它，无法自动还原实际用量。
