# 预占 Redis 扣减后中断

## 方法和结果

`reserve_redis_kill_after_lua_test.go` 使用当前真实 `Store.ReserveWithReplaySignal`、隔离 MySQL/Redis：账户初始 500 分，请求预占 100 分。GORM 测试回调在 Redis 扣减已成功、MySQL reserve 行 INSERT 前暂停；独立读取 Redis 确认余额 400，然后对脚本创建的隔离 Redis 容器发送 `docker kill`。这是 Lua 返回后和 INSERT 前的切点，**不是杀在 Lua 执行期间**。

分别测试两种顺序，各三轮 Go race：

1. Redis 保持停止，释放 INSERT，观察账单提交成功，再启动 Redis。
2. INSERT 仍暂停时先启动 Redis，再释放 INSERT 并观察账单提交成功。

两种顺序中，每轮重启后的余额键均确认缺失；随后同请求以严格重放接口重试返回 `RESERVE_DUPLICATE`、同一 bill ID，Redis 余额与 MySQL 账本均为 400，一条 reserve 账单和一条 reserve Outbox。此测试直接调用 Store，未发送模型请求或执行 usage/结算；Redis 进程停止期间仍能提交账单是该受控时序下的观察，不代表 Redis 停机期间新请求可服务。

GORM 回调是应用层同步点；没有杀死 billing 进程、打断 MySQL COMMIT、模拟 Redis 主从和恢复旧 RDB、跨进程并发、重复请求竞争、订阅、充值或消息投递。脚本使用固定 loopback 端口且核验自建容器名称/映射后才 kill。三轮通过不能证明其他时序的账务安全。
