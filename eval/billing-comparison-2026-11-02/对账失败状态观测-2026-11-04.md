# 对账失败状态观测

`SweepOnce` 原本逐笔 RPC 报错后继续扫描，仅记录日志；`Run` 在扫描 SQL 报错时记录日志并发布零值快照。原 `/status` 无字段区分未运行、扫描失败和逐笔失败，不能单凭其零计数判断没有待处理工作。

当前工作树在 `/status` 增加 `last_sweep_attempted`、`last_sweep_error`、`last_settle_errors`、`last_reverse_errors`、`last_rebuild_attempted`、`last_rebuild_error` 和 `last_rebuild_errors`：SQL 失败标志与逐 RPC 错误次数分开；禁用任务时 attempted 为 false；扫描中途 SQL 出错保留已得到的部分统计。失败账单的业务处理、重试周期与余额规则未改。字段表示**最近一轮**，不是累计错误或唯一账单数；`ok` 和 `/healthz` 仍是存活信息，不因逐笔失败变为 false。状态没有时间戳、进程重启即丢失，卡住的当前轮不能更新，尚需持久指标、延迟监控与告警，不能作为账务已恢复证明。

隔离 MySQL/Redis、真实 Store 和对账器测试中：创建已报用量账单并人为将创建时间调旧；模拟 billing 结算 RPC 失败，状态报告一次失败；显式启用旧自动冲正并模拟冲正和租户重建 RPC 失败，状态报告相应次数；随后关闭测试专用数据库连接，状态报告扫描 SQL 失败。禁用扫描和重建时两个 attempted 字段均为 false。最终 `reconciler-status-verified-20261104.txt` 三轮 race 通过；账单时间人为调整，不代表真实宽限期、真实 RPC 断网、数据库服务器宕机或多实例。另一个独立容器中 `reconciler-status-retention-20261104.txt` 对现有默认保留未知、已报用量补结算测试三轮通过，发生在最后一次仅移除 nil 响应分支之前，不代表当前全部回归。

原始失败保留：`reconciler-status-red-20261104.txt` 为修复前字段缺失；首次应用脚本断言失败后产生的 `reconciler-status-green-20261104.txt` 不是绿灯；`reconciler-status-fixed-20261104.txt` 与 `reconciler-status-all-20261104.txt` 因同一数据库多轮遗留账单或租户导致精确计数失败；`reconciler-status-regression-20261104.txt` 在多个测试共享数据库时被其他测试留存的 unknown 账单和活跃租户影响，不能作为通过结果。最终验证将不同测试放进独立临时容器，每轮清理该测试账单并停用其合成租户。
