# 高并发、安全与稳定性验证计划

目标是在现有分支用可复核证据选择方案；不以短时本机吞吐代替容量。用户选择鉴权缓存安全标准“按照newapi”：以已核实 New API `45746eee4de25ab1eb75d4b7fbb8de2199483ea3` 的有限期围栏和失效为参考；需明确该策略在围栏到期、Redis 失效及在途查询时不保证严格立即吊销，不把参考解释成这些风险不存在，也不得放宽计费正确性。

1. 鉴权：梳理所有 Key、浏览器 session、用户及租户修改路径，确定缓存一致性边界。比较直接权威查询、弱一致缓存及可证明的候选；测试过期、并发变更、故障、多个实例和过载降级。准确区分不可证明的立即吊销与性能收益。
2. 计费：针对实际现金路径，测量账户锁、事务、连接池、余额重建随历史账单量变化；只在测试隔离环境构建候选，复核订阅、充值、冲正、Outbox、同请求参数冲突及重启恢复，未覆盖不得称等价。
3. 网关：以同一模拟上游和多账户、多请求分布进行阶梯、持续和故障注入；记录有效成功、错误率、P95/P99、客户端饱和及账务状态，配置/数据/源与日志均保存。优先完成正确性再比较性能。
4. 按可测数据撰写方案、收益、风险、前提、上线前待测事项；未达到安全或稳定性边界时不建议切换生产。

本机与其他工作负载共享，所有观察受影响；机器负载严重时只作诊断并保留失败，不将其作为生产容量。禁止生产数据、生产配置、付费调用、部署和提交。独立测试目录内产物可复现，禁止清理其他既有服务。
