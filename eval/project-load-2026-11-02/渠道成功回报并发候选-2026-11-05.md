# 渠道成功回报并发：隔离候选

测试 overlay `../billing-comparison-2026-11-02/build_router_success_parallel_overlay.py` 将单渠道回报锁从 Mutex 改为 RWMutex：成功回报获取读锁、可同时执行持久化；失败获取写锁，等待同实例此前持锁成功回报完成。状态本身仍受 `r.mu` 保护，每条成功仍更新 MySQL；没有队列、事件 ID 或重试。不同实例及提交结果未知的语义仍未解决。此方案只是候选，**未修改正式 Registry**。

受控隔离 MySQL 测试人为将两次成功写入前暂停：基线三轮只能有一次进入回调，断言按预期失败；候选三轮均两次进入，失败回报在释放成功前未进入数据库，释放后最终计数 1。既有同渠道成功后失败顺序、不同渠道独立、阈值持久化、写失败 503 等选定测试各三轮 race 通过。回调屏障在 SQL 实际执行前，不能证明 MySQL 行锁可并行，也不能覆盖全部乱序、半开、迟到成功或跨实例。失败回报 100ms 未进入的断言还受调度限制。
