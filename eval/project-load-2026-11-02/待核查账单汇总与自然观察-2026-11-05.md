# 待核查账单汇总与自然观察

## 管理员只读汇总

为避免把对账器单轮 `last_held` 当作全库积压，当前工作树新增 `Store.PendingReserveSummary` 和受控制面令牌保护的 billing `GET /admin/pending-summary`；网关管理员组代理相同路径，沿用现有 `AdminSession` 和控制面令牌。一个 MySQL 语句统计全部 `phase=reserve,status=pending` 行，按 `usage_reported_at` 是否为 NULL 分组，返回总数、两组数量及各自最早 `created_at`，`observed_at` 是 SQL 返回后的网关所属 billing 进程时钟。它不读 Redis、不更新账单、不触发结算、冲正或重试，JSON 不含账户、请求或金额。无待处理记录时计数为 0，最早时间为 null。

**注意语义：**标记存在不保证 token 字段完整、金额正确、事务可结算或已对账；没有标记也不证明上游没有执行。新记录及状态可能在查询返回后立即变化，这是单次语句快照而非持续一致视图；数据库不可用返回 500，不回退为零。接口按需执行全量聚合，即使有 `idx_recon`，大积压下仍可能产生数据库扫描和连接压力；尚无大表 EXPLAIN、限流、并发采样成本或超时专项验证，不建议高频自动抓取，也不等于告警或恢复机制。

`TestPendingSummaryAdminSnapshot` 使用隔离 MySQL/Redis 三轮 race：现金与订阅、两个租户的 3 个 pending、已结算和非 reserve 行、空集，以及标记存在但 token 为空的账单均按**标记**分类；检查最早时间、控制面无令牌 401、非 GET 405、DB 连接关闭 500。真实 billing admin handler 在本机 httptest server，真实 gateway admin group 经现有中间件和代理验证未授权 401、测试用静态管理员令牌 200；静态测试令牌不是生产授权配置。未验证真实登录 cookie、线上权限部署或多实例。`go test -race -count=1 ./internal/billing/store ./internal/billing/admin ./internal/gateway/handler ./internal/gateway/middleware` 通过；日志保留系统链接器警告。
