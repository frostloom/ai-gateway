# 路由回报事务候选：隔离验证

此候选仅在 `../billing-comparison-2026-11-02/router_event_candidate_test.go`，没有接入真实 router、gateway 或协议，不是可部署方案。它探索一种明确的假设：以 MySQL 获取 provider 行锁后的事务顺序定义全局连续失败；回报带全局唯一事件 ID，同一 ID 同一 provider/结果为幂等重放，不同内容冲突。事务先写唯一事件，再锁 provider 行并更新连续失败计数；失败累计达到 20 时将 active 改为 banned；成功清零计数但不自动解除 banned。事件和 provider 更新同事务提交，注入失败整体回滚。这个假设不同于现有每个 Registry 的内存计数，并未决定是否采用为产品语义。

隔离 MySQL 8.0.40、Redis 7，HEAD `63b9d1ed4d64bb583d15fa884c37468e5c53044c` 加未提交工作树。测试对单 provider 的 20 个不同失败事件各并发提交两次，共 40 次；三轮 race 均得到 20 个事件、计数 20、status banned。同 ID 不同结果被拒绝；事务更新后注入错误时事件不落库、provider 状态不改变。测试代码是直接调用、单进程 goroutine，不是真实客户端或独立进程。红灯 `router-transactional-events-red-20261104.txt` 为未实现时三轮预期失败；绿灯 `router-transactional-events-green-20261104.txt` SHA-256 `e7798aae0178744b960dd37615a9b939f65eeb76231174794c8f01e3b92c29f4`；最终代码 SHA-256 `23d366971b4473c2f5f074ad8f8fd9ca95caeab3d296ec6baf387894b5adcf82`。

复现 `bash eval/billing-comparison-2026-11-02/run-router-transactional-events.sh`；脚本创建并清理随机隔离容器，不访问生产或付费服务。

仍需定义和验证：稳定事件 ID 的生成与信任边界、事件保存/清理、实际发送顺序与提交顺序区别、成功和失败乱序、已经禁用或删除的 provider、跨实例缓存失效、原有 OPEN/半开/探测和 AutoBan、DB 故障/提交确认未知与重试、多个独立进程、可靠回报投递和内存状态协调。事件表无清理或容量上限；没有真实网络故障、网关或负载性能测试。行锁可能成为单渠道热点，不能假设这会提升吞吐。必须在完整语义和恢复路径下与基线比较后再考虑生产改造。

## 提交后进程终止与重试

`TestRouterEventRetryAfterProcessKill` 在独立子进程调用测试候选，子进程从数据库事务成功返回后向测试父进程输出标记并等待；父进程收到标记后强制终止并回收子进程，再以相同事件 ID 重试。隔离 MySQL/Redis、三轮 race 均为事件一条、provider 失败计数一次、状态 active。复现 `bash eval/billing-comparison-2026-11-02/run-router-event-process.sh`；原始输出 `../billing-comparison-2026-11-02/router-event-process-20261104.txt` SHA-256 `6c4e9bf402eed904b27967d3417e4b342ab8296fdab1487b3126d590939c10e9`，测试文件 SHA-256 `b40b7700c6115f81d4775e4241bbf5376458686e20e486eedc9f3cdbbef17d0a`。

子进程已收到数据库提交成功，标记由测试管道传给父进程；这不是数据库网络提交确认丢失、也不代表真实 router/gateway 已集成稳定事件 ID。没有覆盖进程在事务内部死亡、不同 provider 的相同 ID、真实网络分区、缓存和熔断恢复或吞吐。候选仍仅用于测试。

## 禁用渠道与迟到回报

当前真实 `registry.go` 的三种数据库更新均附 `status=0` 条件。测试候选原先没有保持这条数据库规则：隔离测试对 status=1、计数 7 的渠道提交失败回报，三轮都变成 8，红灯 `router-event-disabled-red-20261104.txt`。测试候选现改为锁定 provider 后，非 active 时保留事件但不更新 provider；该事件重放在重新启用后也不再应用。这是测试假设，尤其“禁用期间回报永久不应用”尚需业务确认；也不能据此声称与现有内存 breaker 等价。

修正后，禁用状态下成功和失败回报均不改变计数 7，重新启用后旧失败事件重放不改变计数；三轮通过，`router-event-disabled-green-20261104.txt` SHA-256 `810f9423e30836c7812764d6940191f969057dc091d6642f0503691fe155434a`。首次回归原并发用例 `router-transactional-events-regression-20261104.txt` 三轮失败，因为旧测试在已封禁渠道上要求注入更新失败，修改后该路径不再更新；保留此失败。将回滚断言改到独立 active 渠道后，并发去重与回滚三轮通过，`router-transactional-events-final-20261104.txt` SHA-256 `58a7e93a5eb667ce8c172a39ba90317e0f383daaf42c2da862f1694bfbf9837a`；提交前杀进程回归也三轮通过，`router-event-before-commit-regression-20261104.txt`。当前候选/测试文件 SHA-256 `f2d9af2175841939c916abe9376e7b2e61e4df47c0ba21ec95258c0c1d33aae4`，上文旧 SHA 对应当时版本。
