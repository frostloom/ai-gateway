# 新版路由缩锁核验：故障优先

## 先前性能数据的修正

历史 `router_registry_lock_scope_current_20261105.go.txt` 比当前 `internal/router/registry.go` 旧：触发 OPEN 的失败没有调用 `persistFail`，也没有 `router_persistence_errors_total` 的 increment/reset/ban 记录。使用该旧 overlay 的性能结果只能描述当时测试二进制，不能作为当前工作树等价改动的性能证据。真实隔离 MySQL 中，旧 overlay 的阈值测试三轮都在第 3 次失败时观察到数据库计数仅 2，持久化错误指标测试三类增量均为 0；`router-lockscope-stale-red-20261105.txt` 保留预期失败。

测试专用 `build_router_fresh_scope_overlay.py` 从当前源码生成新候选：为同一 provider 的报告串行化，内存熔断状态仍在全局锁内更新，数据库写移出全局锁；触发阈值时也写失败计数，保留 increment/reset/ban 错误指标。它没有修改正式 router；按 provider 的 `sync.Map` 生命周期没有解决。测试 overlay 不是完整可靠回报协议。

新候选七项隔离测试各三轮 race：阈值计数、三类持久化错误指标、被阻塞回报期间缓存路由推进、指定同渠道顺序、不同渠道独立回报、数据库写失败现象及两个 Registry 本地计数边界。**其中写失败回报仍为 HTTP 200、两 Registry 计数不聚合等测试通过表示成功复现风险，不是安全验收。** 新候选下 `internal/router` 和 `internal/gateway/client` 包 race 测试通过。真实隔离 MySQL kill/restart 三轮均观察故障中的报告返回 200、错误指标 +1；恢复后第二次报告，内存失败数 2、数据库 1。测试人为杀停本次脚本创建的 MySQL，不等同网络确认丢失或所有故障；旧写者、进程崩溃、事件身份、回报去重、跨实例和半开时序仍未解决。**候选不可部署。**
