# 网关路由回报观测

`internal/gateway/client/router.go` 的 `Report` 原来忽略请求构造错误、传输错误、HTTP 非 200 与响应读取错误；原注释称“只记日志”，实际没有记录。现工作树新增低基数 Prometheus 计数器 `gateway_router_report_total{result=...}`：`http_200`、`http_error`、`transport_error`、`body_error`、`invalid_request`。每次调用记录一个结果，不含账户、请求或渠道标签；非 200 与响应读取同时失败时归为 `http_error`。响应体仍读取并关闭，以保留原有连接复用行为。

**指标只描述 gateway 的 HTTP 观察。** 当前真实 router 可能在 MySQL 写失败时仍返回 200，因此 `http_200` 不能证明持久化或成功恢复；传输错误也可能发生在对方已处理请求之后。没有新增重试、持久队列、事件 ID、告警规则或成功保障，也没有改变用户响应或路由状态。相关数据库中断复现见 `当前路由锁范围复测-2026-11-05.md`。

先写测试，原实现对 200、503、取消请求三项均因计数器不存在而预期失败，原始输出 `router-report-metrics-red-20261105.txt`。工作树实现后，`go test -race ./internal/gateway/client ./internal/pkg/metrics` 通过；该测试覆盖 200、503、取消、非法 URL 和模拟响应体读取错误。追加测试期间曾因测试代码错误产生一次编译失败，保留 `router-report-metrics-test-build-failure-20261105.txt`；修正后重新运行输出 `router-report-metrics-final-20261105.txt`。macOS 链接器关于 `LC_DYSYMTAB` 的警告保留在日志。
