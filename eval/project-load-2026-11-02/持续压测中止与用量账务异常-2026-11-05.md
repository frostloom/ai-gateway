## 优先问题

第一轮 120 请求/秒持续 60 秒的逐请求快照中，有 **11 个有效 HTTP 200 对应 pending**：10 笔已持久化 usage、无 settle，gateway 同 ID 日志为结算 RPC `DeadlineExceeded`；1 笔无 usage、无 settle，同 ID 日志为用量上报未确认且 `DeadlineExceeded`。`handler.settleAndLog` 在用量未确认或结算失败时记录错误并返回，非流式调用者随后仍返回模型响应。已报 usage 的 pending 有既定对账路径，但本轮**没有等待或验证恢复**；对无 usage 的那笔，单靠账单快照不能按实际用量补结算。不能根据该快照判断用量 RPC 是否曾提交、晚到结果或真实供应商费用。
