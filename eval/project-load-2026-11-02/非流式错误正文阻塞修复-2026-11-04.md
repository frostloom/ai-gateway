# 非流式保守模式错误正文阻塞修复

基于 HEAD `63b9d1ed4d64bb583d15fa884c37468e5c53044c` 加未提交工作树。当前 `cmd/gateway` 默认启用 `GATEWAY_HOLD_UNKNOWN`；此前非流式 handler 即使拿到非 2xx 状态，也先 `io.ReadAll` 错误正文，再进入保守模式返回 502 并保留待核查账单。上游发送状态和响应头后一直不结束正文时，handler 会一直等待读取，直到上游关闭、请求取消或 HTTP 客户端总超时；此处不是声称流式和其他请求均有相同限制。

在真实 handler 和本地 HTTP 模拟服务、fake billing/router 下，分别返回 400 和 503 响应头并阻塞正文。修复前三轮两种状态均等待超过 500ms，红灯 `nonstream-error-body-red-20261104.txt`。工作树 `internal/gateway/handler/chat.go` 现对保守模式非 2xx 在读取正文之前关闭响应体、上报渠道状态、返回 502 并保留账单；不重试上游，不上报用量、不结算也不冲正。原正文读取错误发生时此前不会执行渠道 Report，修正后非 2xx 收到响应头即会 Report，这是有意保留既有完整错误响应的分类行为，但需要注意它改变了截断错误正文的渠道回报时机。非保守模式仍走原逻辑；2xx 仍需完整读取并检查。

`python3 eval/project-load-2026-11-02/run-nonstream-error-body.py` 三轮通过，输出 `nonstream-error-body-green-20261104.txt` SHA-256 `18bb280ecef562b8ecf6c114d864f5c371c75ca008f85140715fe531ffed55ed`；测试文件 `nonstream_error_body_test.go.txt` SHA-256 `291d2421195933d8cc1c84b2a6614c18aa8acb3b3ed2c8db201bc4f5646af1d5`。`bash eval/project-load-2026-11-02/run-gateway-isolated-suite.sh` 的 gateway client、middleware、handler、controlplane 包 race 测试通过，输出 `nonstream-error-body-suite-20261104.txt`。当前 handler SHA-256 `c8174a35387658ef644d6a099b50e4844e4e3a546217d1dbcc0d39ef0e2378e1`。两项均使用模拟服务或隔离容器，没有生产数据或模型调用。

本修复只消除保守模式下等待错误正文的路径，不限制成功正文大小，也不能保证同步 `router.Report` 自身不会阻塞。测试未连接真实账务 RPC，不能证明 pending 在所有进程、旧实例和直接冲正入口中安全恢复；对账和未知上游结果的剩余问题仍适用。没有做整网关性能复测、部署或提交。
