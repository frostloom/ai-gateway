# 真实路由回报合并候选（隔离构建）

候选 `router_registry_batch_candidate.go.txt` 通过 Go overlay 编译实际 router：原 `Report` 逻辑作为单 worker 的处理函数，同一 provider 连续且同时排队的成功回报合并为一次处理；遇到失败或不同 provider 则保序分批；调用方等待该批处理返回。队列上限 1024、满时阻塞。此文件只供实验，不覆盖生产源码；没有 worker 停止、取消、过载拒绝或持久队列实现。

## 正确性初测

`run-router-real-batch-test.sh` 在测试构建中用隔离 MySQL 阻塞第一笔成功写入，32 个并发回报排队后释放：原实现写 32 次（预期失败 `router-real-batch-red.txt`），候选写 2 次且全部返回（`router-real-batch-green.txt`）。另对 candidate overlay 跑 `go test -race ./internal/router`，现有 7 个熔断、AutoBan、半开探测及 HTTP 测试通过，见 `router-real-batch-circuit.txt`。这些测试未覆盖回报的故障语义、真实并行多实例和所有顺序交错，不能证明功能完全等价。

## 整网关短时对照

`python3 eval/project-load-2026-11-02/run_router_batch_paired.py`：同一随机隔离 MySQL/Redis、64 合成账户、模拟模型 15 ms，基线与候选各一套 router/gateway/billing 同时常驻；两套 gateway、billing 二进制哈希分别相同，router 不同。每组闭环 3 秒加排空，两轮反转顺序、使用不同账户组；MySQL max_connections=500，relay 关闭。原始目录 `router-batch-paired-runs/20261103-192234/`，候选源码 SHA `e599271499a9dd693e1292494a830401a6cc2241a007421d49877cb3e2953cd5`。吞吐是有效完整 HTTP 请求/秒，P95 包含失败请求。

## 阻止上线的限制

候选没有 worker 生命周期和安全关闭，队列满会阻塞且不响应取消；worker 退出/进程崩溃、DB 卡死或提交结果不确定时的排队回报和调用方行为未定义。批内成功回报合并后的线性化边界、失败插入、不同 provider、公平性、多实例、半开探测时序、AutoBan/DB 失败与重启需要完整验证。与已有非阻塞入口原型尚未整合，也不解决账务在途冲正或旧版本混部问题。**不要部署该候选**；下一步先把队列生命周期、过载和失败语义落到真实路由候选并补充并发/故障测试，再做长时开放到达率整网关压测。

## 补充：有界队列与反馈丢失反例

测试候选 `router_registry_bounded_candidate.go.txt` 增加非阻塞入队、满/关闭拒绝、接受后 context 超时、显式关闭及排空。`TestRealRouterBoundedLifecycle` 在隔离 MySQL 中阻塞首笔 DB 操作，填满 1024 个位置，验证队列满与关闭不再接受、等待超时不等同未执行、解除阻塞后已接收任务排空；race 通过（`router-real-bounded-green.txt`、`router-real-bounded-final2.txt`）。候选的 DB 处理仍沿用原 `reportOne`：写失败只记日志，调用方不能获得 DB 持久化结果；上下文超时后排队任务仍可能执行。

但现有 HTTP handler 调用的是无返回值 `Report`。在 `TestRealRouterFullQueueCanAcknowledgeLostFailure` 中，故意阻塞 DB 并填满候选队列后，向真实 handler 发送一次失败回报：候选拒绝入队、旧 handler 仍返回 HTTP 200，队列排空后 breaker 的失败计数仍为 0。测试通过表示**问题被复现**，不表示候选安全。网关真实 `client.Router.Report` 同样没有返回值、没有检查响应状态；`TestGatewayReportDoesNotRetryHTTP503` 使用本地 HTTP 503 运行三次，确认每次只发送一次（`router-report-503-characterization.txt`），源码还表明调用方无法从该接口获得错误。

复现候选测试：`ROUTER_CANDIDATE=1 bash eval/project-load-2026-11-02/run-router-real-bounded-test.sh`。另用 overlay 运行现有 router race 测试见 `router-real-bounded-circuit.txt`。候选未改生产代码；仅日志记录拒绝而返回 200 会丢失熔断反馈，**明确不能部署**。必须连同 HTTP 协议、调用方、失败回报的过载/重试与去重、DB 故障和进程退出语义一起设计；仅给队列增加容量或丢弃失败事件不能解决问题。先前性能测试使用的是无生命周期的另一版本，不可套用到本候选。

## 补充：HTTP 准入与未知结果实验

测试专用 `router_http_bounded_candidate.go.txt` 调用候选 `ReportContext`：明确队列满/关闭时返回 503 和测试标记 `not-accepted`；已接收后等待超时等情况保守标记 `unknown`。原 handler 面对满队列返回 200 的反例仍在 `router-real-http-red.txt`。`ROUTER_CANDIDATE=1 HTTP_CANDIDATE=1 bash eval/project-load-2026-11-02/run-router-real-http-test.sh` 使用真实路由 HTTP handler、隔离 MySQL 和 race 三轮，验证满队列返回明确未接收；另阻塞前一个 DB 写入，让失败回报已入队后请求 context 超时，测试 handler 返回 unknown，解除阻塞后该失败仍被应用一次。结果见 `router-real-http-db-failure.txt`。httptest 直接调用 handler，真实网络断连时调用方可能根本收不到标记；不能凭没有收到响应判断未接收。

同轮 `TestRealRouterCandidateAcknowledgesDatabaseWriteFailure` 故意删除隔离测试表，让失败回报的 MySQL 写入报错；候选仍返回 HTTP 200，内存计数为 1。测试通过表示复现原 `reportOne` 只记持久化错误、无错误返回的行为，而非持久化成功。因此上述 200 至多表示 worker 已处理，不能当持久化证明；对失败回报盲目重试又可能重复计数。当前网关客户端不检查回报状态（另见 `router-report-503-characterization.txt`），此协议只供实验。还需明确可见状态、幂等事件身份、持久化失败和提交结果不明、跨实例顺序、过载与宕机恢复，再做完整系统测试；不能部署。

## 补充：开放到达率及账务反例

使用原始**无关闭语义的批量成功回报原型** `router_registry_batch_candidate.go.txt`，不是上节有界队列/HTTP 候选：`OPEN_LOAD_ROUTER_BATCH=1 OPEN_LOAD_RATES=140,180,200 OPEN_LOAD_SECONDS=30 OPEN_LOAD_REPETITIONS=2 OPEN_LOAD_MAX_INFLIGHT=2000 python3 eval/project-load-2026-11-02/run_gateway_open_load.py`。64 合成账户、本地模拟上游 15 ms、各档两轮，每轮 30 秒；测试栈独立 MySQL/Redis，relay 和余额重建关闭。基线为另一独立运行 `gateway-open-load-runs/20261103-224641/`，原型为 `gateway-open-load-runs/20261103-225339/`；两者 gateway、billing、reconciler、模拟上游和发压器二进制及镜像哈希相同，仅 router 二进制不同。两个运行顺序固定、时间和数据库历史不同、主机共享，不能把差异完全归因到 router。原型 hash 与完整配置见各运行 `config.json`。本表延迟包含所有结果，发压丢弃各轮均 0。

| 计划/秒 | 实现 | 两轮 HTTP 错误率 | 两轮 P95 ms | 两轮峰值在途 | 两轮排空后有效/秒 |
|---:|---|---|---|---|---|
| 140 | 基线 | 0%、0% | 935、1536 | 147、231 | 139.5、137.7 |
| 140 | 原型 | 0%、0% | 354、479 | 70、142 | 139.3、139.0 |
| 180 | 基线 | 13.37%、13.74% | 5582、6001 | 804、897 | 137.3、135.5 |

| 200 | 原型 | 3.20%、27.22% | 5205、9867 | 827、1113 | 177.9、130.7 |

原型在本次 180 档短测下有明显潜力，但 200 档结果波动大，且开始出现鉴权和计费不可用，说明瓶颈可能转移；没有指定延迟 SLO，不能据此宣称容量或上线达标。

**账务结果优先：**原型 200 档第一轮 3 个 HTTP 503 对应 pending、无 usage；第二轮 63 个有效 HTTP 200 对应 pending，其中 62 已报 usage、1 未报，另有 19 个 503 对应 pending、无 usage。最终累计 pending 85、settled 29317（有效 HTTP 含 smoke 共 29380），Redis 与账本公式无差异；对账 grace 600 秒尚未到即清理容器，**未观察这些账单最终恢复**。不能把余额一致当作已完成结算，也不能将该现象单独归因于 router；日志中有结算 DeadlineExceeded。其余 140/180 档逐请求均 settled。全部 88098 条 Outbox 未发送，因 relay 关闭，未验证投递。MySQL 累计最大连接 106/151、上限错误 0、InnoDB 行锁等待 14 次共 232 ms；Redis 操作和资源等在原始目录。

此性能试验只说明值得研究可靠的减写与背压协议。原型仍有无生命周期、处理失败可能被确认、跨进程及关闭恢复未验证等前述缺陷，且账务异常未恢复观测，**不可部署或当作安全方案**。应先统一事件身份、失败反馈、持久化与调用方过载语义，再在同配置、反转顺序及长期故障恢复下重新对比。

## 补充：高负载后自然等待 600 秒对账

为了观察同类高负载产生的 pending 如何收敛，执行 `OPEN_LOAD_ROUTER_BATCH=1 OPEN_LOAD_RATES=240 OPEN_LOAD_SECONDS=45 OPEN_LOAD_REPETITIONS=2 OPEN_LOAD_MAX_INFLIGHT=2000 OPEN_LOAD_RECOVERY_WAIT=620 python3 eval/project-load-2026-11-02/run_gateway_open_load.py`。真实 gateway/billing/router/reconciler、隔离 MySQL/Redis、64 合成账户及本地模拟上游；对账 grace 保持 600 秒，测试没有修改账单时间，实际在负载和即时核对后等待 **620.006 秒**。原始证据 `gateway-open-load-runs/20261103-230422/`，包括 `trace-audit-*.json`、`recovered-trace-*.json`、前后全局审计、等待时长、配置及日志。脚本成功退出并清理自身容器；relay 关闭。

两轮各发出 10800 请求、发压丢弃均为 0，第一轮 9799 个有效 200 / 1001 个 503，第二轮 8209 / 2591；分别 P95 6882 / 9237 ms。负载后即时快照有 **155 笔 pending**：116 笔对应有效 200（111 已上报 usage、5 无 usage），39 笔对应 503 且无 usage。等待后逐请求分组显示这 111 笔有 usage 的 200 已 settled；44 笔无 usage 转为 reversed，**其中 5 笔此前是有效 HTTP 200，39 笔此前是 503**。最终 pending 0、settled 18008、reversed 44，Redis 与账本公式无差异；Outbox 54112 条均未发送。

这是真实配置下的自然对账观察，暴露了**合成请求获得有效响应但最终冲正、没有正常结算**的风险；所有上游是免费本地替身，不证明真实供应商已执行或收费。相关网关日志有 usage 上报 DeadlineExceeded，但本报告没有对每一笔关联日志作逐条归因。余额一致只证明该公式一致，不证明外部用量记账完整。此结果不能只归因于 router 原型：已有 handler/对账策略本身会在无 usage 时冲正；更高吞吐可能改变负载与故障分布。不可将 pending 变为 0 当作账务正确性通过。未验证正式上游、真实供应商账单、Kafka 投递、完整故障空间或生产容量。

另一次 `gateway-open-load-runs/20261103-230133/` 用 200 次/秒两轮未产生 pending；因没有恢复对象，在等待期内主动终止（退出 143，未等待 620 秒、未生成最终恢复快照），仅保留即时输出 `open-load-natural-recovery.txt`，不作为恢复通过。更低负载的两秒等待烟测为 `gateway-open-load-runs/20261103-230033/`，不代表 600 秒自然对账。
