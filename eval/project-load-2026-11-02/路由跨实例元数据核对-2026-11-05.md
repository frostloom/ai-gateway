# 路由跨实例元数据核对：测试候选

在上一轮逐请求 MySQL 状态检查的测试 overlay 上，扩展为按缓存里的 provider ID 查询当前状态、名称、地址、上游密钥、权重和模型列表，并按当前模型过滤；不输出真实密钥，测试均使用合成值。数据库出错或 nil 时返回错误。实际 router 生产源码没有接入此方案。

真实隔离 MySQL/Redis、race 各三轮：先预热缓存，再更新地址、密钥、权重，候选下一次选路取得新值；移除模型后不再选择该 provider。之前状态检查候选三轮仍返回旧值，红灯 `router-authority-metadata-red-20261105.txt`。已提交 ban 在随后查询中被过滤；查询读取 active 之后才发生 ban 的受控交错，已在途请求仍可选择该渠道，之后的新查询拒绝。关闭数据库连接、nil 数据库时拒绝；并非真实网络分区或复制延迟。

该方案仅检查**缓存中已有 ID**。缓存中没有可用渠道时，之后插入新渠道，已预热的 Registry 仍返回空，新 Registry 能查到；`TestRouterAuthorityCannotDiscoverNewProviderFromEmptyCache` PASS 是复现这一可用性缺口，不是正确性通过。读后更新仍有竞态，增加渠道或扩展模型可能等原缓存 TTL 后才可见；未证明 30 秒为故障条件下严格上界。没有验证多进程、旧写者、权限、不同数据库隔离级别、模型/密钥迁移或完整半开状态。

候选整包 race 回归：gateway client 包通过；router 包依赖 `New(nil)` 的 `TestHalfOpenRouteAllowsOneProbe` 与 `TestRouteHidesUpstreamKeyWithoutToken` 因候选拒绝无数据库返回错误而失败，日志 `../billing-comparison-2026-11-02/router-authority-metadata-packages-20261105.txt`。未更改原测试、未称包回归通过。隔离定向组合测试包括上述状态/元数据、冷缓存、取消和封禁交错、阈值计数，各三轮通过；其中读后竞态和空缓存测试的 PASS 表示缺陷已复现。日志 `router-authority-metadata-verified-20261105.txt`。
