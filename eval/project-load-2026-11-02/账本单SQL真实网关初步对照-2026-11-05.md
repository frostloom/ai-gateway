# 账本单 SQL 候选的真实网关初步对照

候选通过 `build_ledger_single_overlay.py` 将现有四次账本查询改成一条带四个标量子查询的 SELECT，继续使用 Redis、账户锁、余额重建与现有账务流程；它不是纯 MySQL 计费，也没有修改正式生产源码。runner 新增 `OPEN_LOAD_LEDGER_SINGLE=1`，只在隔离 billing 构建使用 overlay，并拒绝与同文件的投影子步骤 overlay 冲突。既有现金 Store 定向正确性结果及快照、故障覆盖不足见[账本单 SQL 成对负载](../billing-comparison-2026-11-02/账本单SQL成对负载-2026-11-04.md)。

两次分别新建隔离 MySQL/Redis，真实 gateway/billing/router/reconciler，64 合成账户、同账户可并发、50% 浏览器、非流式、本地 15ms mock，严格 V2/unknown hold，Kafka relay、Agent 和周期重建关闭。每次 40 请求/秒、15 秒两轮，启用相同预占阶段、池采样、mock 追踪及逐请求账务异常停轮。运行次序固定为基线两轮后候选两轮，机器共享，数据库和历史不共享，因此不是随机交叉试验，不能将差异归因于 SQL 改动。
