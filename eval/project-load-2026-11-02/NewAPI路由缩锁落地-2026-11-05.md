# 路由缓存刷新缩锁落地

参考 New API 在锁外构建渠道快照的方式，当前分支 `internal/router/registry.go` 已将缓存未命中时的 MySQL 查询和列表构建移出全局状态锁；使用可取消的单刷新许可避免同进程刷新风暴，发布时检查本实例缓存失效代次，期间发生封禁会丢弃过期查询结果。半开探测选择与占位仍在原状态锁中。不同模型的缓存未命中仍串行刷新；状态锁等待本身、回报持锁写库和多实例状态同步未解决。原测试 overlay 生成器以旧实现为锚点，此次正式修改后旧的 `TEST_ROUTER_REFRESH_SCOPE=1` / `OPEN_LOAD_ROUTER_REFRESH_SCOPE=1` 复现命令不再适用于当前源码；下述命令直接测试工作树。

隔离 MySQL/Redis，原实现三轮分别复现缓存命中被无关刷新阻塞、封禁与刷新竞争、等待者取消失效（`router-main-refresh-red-20261105.txt`）；修改后相关三例与取消半开探测、取消刷新、熔断阈值各三轮 race 通过（`router-main-refresh-green-20261105.txt`）。router 与 gateway/client 包 `-race -count=1` 通过（`router-main-package-race-20261105.txt`，保留 macOS 链接器警告）。源码 SHA-256 `d4072bc427069995bbd1086164836d431cc0bf5adf8e8c28f8e62b4261b8bd88`，`git diff --check` 通过。
