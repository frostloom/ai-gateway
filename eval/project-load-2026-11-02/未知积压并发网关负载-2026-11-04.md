# 未知账单积压与网关并发负载

## 方法

当前 HEAD `63b9d1ed4d64bb583d15fa884c37468e5c53044c` 加未提交工作树，对账器分页实现 SHA256 `1c4dd1a858ba8490b5ede1ea865a76ad3fb923381d227001f0af4cc6726b4e2a`。Apple M1 Pro 8 逻辑 CPU、16 GiB；独立本地 MySQL 8.0.40 / Redis 7，真实 gateway、billing、router、reconciler 与发压共机，单 mock provider 15ms；64 账户、非流式。使用当前可执行程序的保守默认值、强制 v2、对账周期 5 秒和 grace 600 秒，关闭 rebuild、Kafka/Outbox relay 和 Agent；gateway 有诊断 overlay。

测试通过 SQL 在新建隔离库插入分布于 64 账户的 0 或 10000 条**零金额、无 usage 的合成订阅 reserve 行**，其创建时间被人为提前一小时，且不创建 Outbox 或真实订阅，因此不是等价的生产账务历史；另通过真实 billing gRPC 创建一笔有 usage 和一笔无 usage 的现金预占，将其创建时间人为提前，观察前者补结算、后者保留。无真实模型调用。各组 100 / 140 计划请求每秒，各 10 秒两轮，发压上限 1000 在途。有效吞吐包含排空时间，延迟包含失败。三组按下列顺序执行并各自重建容器，非交叉随机，不能根据差值断言积压使服务变快或变慢：

| 合成积压 | 原始目录 | 100 次/秒两轮成功/发出 | 两轮 P95 ms | 140 次/秒两轮成功/发出 | 两轮 P95 ms |

|10000|`gateway-open-load-runs/20261104-052614/`|1000/1000、1000/1000|272、303|1400/1400、1400/1400|394、518|

所有组发压丢弃 0、HTTP 错误 0。第二行只能确定测试期间对账器最终扫描了积压，未记录扫描与发压是否重叠；第三行额外将对账器日志设为 info 并采集 `/status`，日志和资源采样时间显示各负载档期间有扫描完成，第一档期间扫描了 10002 条并补结算 1 条、保留 10001 条。状态采样及 info 日志本身有额外开销，不能当同一二进制的严格 A/B。每档仅两轮、10 秒，共机及组次、缓存、历史数据不同，结果不构成性能因果结论或生产容量。

## 核对和限制

最后一组结束时，人工构造的真实账务 fixture 中，有 usage 的 reserve 为 settled 且有 settle 行；无 usage 的为 pending。最终总计 10001 pending（10000 条人工零金额行加一笔真实未知预占）、4806 settled（4800 成功 HTTP、5 烟测和 1 fixture），reversed 0，64 账户 Redis 与账本无差异。Outbox 14419 条均未发送；合成 SQL 行本来不产生 Outbox，不得用于证明账务事件完整性。

最后一组 MySQL 最大连接 80/151、连接上限错误 0、InnoDB 行锁等待 2 次共 8ms，不包括命名锁；Redis 全过程命令 154217、峰值内存 4.22 MiB，包含初始化、烟测及核对。资源采样含发压和对账结束时间，不支持归因单次请求。没有验证百万级积压、长时间稳定、真实有金额积压、持续故障、SSE 或 Outbox 消费；分页仍会在每轮遍历全部未知账单，真实业务何时核查和释放尚未解决。

首次烟测 `gateway-backlog-smoke.txt` 因脚本给 `subprocess.run` 重复传 `text` 参数在发压前失败，已修正；`gateway-backlog-smoke-retry.txt` 在 20 条积压下成功，原始失败保留。

## 复现

```bash
OPEN_LOAD_RATES=100,140 OPEN_LOAD_SECONDS=10 OPEN_LOAD_REPETITIONS=2 \
 OPEN_LOAD_REQUIRE_V2=1 TEST_SYNTHETIC_BACKLOG=0 \
 python3 eval/project-load-2026-11-02/run_gateway_backlog_load.py
OPEN_LOAD_RATES=100,140 OPEN_LOAD_SECONDS=10 OPEN_LOAD_REPETITIONS=2 \
 OPEN_LOAD_REQUIRE_V2=1 TEST_SYNTHETIC_BACKLOG=10000 \
 python3 eval/project-load-2026-11-02/run_gateway_backlog_load.py
```

当前脚本在两组均开启对账器 info 与状态采样；上表第一、二组是在添加采样前运行，runner hash 记录在各自 config。脚本只创建和清理自身随机命名的本地隔离容器和进程。
