# 路由诊断端点鉴权

## 问题与修复

真实 router 的 `/providers` 返回渠道名称、上游 URL、模型和状态，`/breakers` 返回熔断状态与失败计数；修复前二者没有控制面令牌校验。隔离真实 MySQL/HTTP 测试中，空令牌和错误令牌都返回 200 并暴露合成记录，三轮一致（`../billing-comparison-2026-11-02/router-observation-auth-red-fixed-20261105.txt`）。输出类型没有上游密钥；不能据此推断实际部署对外暴露，默认监听 127.0.0.1，可配置为其他地址。

现改用与 `/route`、`/report` 一致的控制面令牌校验，拒绝空值和错误值；`/healthz` 保持原行为，`/metrics` 未改。gateway 管理代理已经附带控制面令牌，且入口由管理员中间件保护。已将项目 M5 脚本的两个 `/breakers` 请求和隔离故障测试调用更新为携带令牌。外部监控或脚本直接访问这两个端点时也须更新；项目无法枚举仓库外调用方，部署前应核对其兼容性。未修改生产配置或部署。

## 测试

隔离 MySQL 的真实 router HTTP handler 测试三轮：空和错误令牌返回 401，正确令牌可读取状态；`/healthz` 无令牌仍可读。真实 gateway 管理中间件和代理使用测试管理员令牌经 loopback 调 router：无管理员令牌 401，有管理员令牌 200 并读取合成 provider。测试不是完整部署的跨主机网络或浏览器登录。日志 `../billing-comparison-2026-11-02/router-observation-auth-green-20261105.txt`。最初测试因合成 models 非法 JSON 未进入鉴权，错误保留在 `router-observation-auth-red-20261105.txt`，不当作行为红灯。

`go test -race -count=1 ./internal/router ./internal/gateway/handler ./internal/gateway/client` 使用 SDK 26.5 三包通过（链接器 warning 保留在 `../billing-comparison-2026-11-02/router-observation-auth-packages-20261105.txt`）；`bash -n scripts/m5/scenario.sh` 与 `git diff --check` 通过。M5 脚本只做语法检查，没有启动其外部服务。Router 回报仍有先前记录的 MySQL 中断时 200 与持久状态不一致问题；本修复不处理回报可靠性、锁竞争或多实例一致性，也不表示高并发目标完成。
