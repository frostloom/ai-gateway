# 可选鉴权缓存验证

参考 New API 的 Redis 鉴权缓存思路，本工作树新增普通 API Key 正向缓存，**默认关闭**。`BILLING_AUTH_CACHE_TTL_SECONDS` 可设 1–60，0 为关闭，非法值拒绝启动；本次未修改任何部署配置。浏览器会话和无效 Key 不缓存；缓存命中检查 Key 状态、过期时间、缓存记录时间和 TTL；Redis 读取有 30ms 预算，失败回退 MySQL 权威查询；查询失败不授权。填充使用 `SET NX`，以权威查询开始时间计算截止，慢查询超过 TTL 不再填充，TTL 缩短时旧记录不会超过新 TTL 被接受。只存哈希和身份元数据，不存明文 Key。

**安全边界：当前没有 Key 或租户状态变更的主动失效或 New API 的围栏。** 普通 Key 或租户禁用后，已缓存权限可能继续有效；并发变更、Redis 状态恢复、跨实例时钟偏差、旧读回填和直接数据库修改均影响精确边界，不能承诺严格立即吊销或严格 60 秒上限。浏览器会话仍实时查询。缓存命中时 MySQL 不可用也可能继续授权，Redis 不可用时并发请求回退 MySQL 可能放大负载。该方案不是 New API 的完整等价实现，**保持默认关闭，不建议直接启用生产**；需要覆盖所有权限变更入口、Redis 故障及跨实例安全后再决定。

隔离 MySQL/Redis 的真实 `Store.ValidateAPIKey`：普通 Key 缓存及 TTL 后禁用、缩短 TTL、浏览器会话禁用、Key 过期、Redis 不可用回退、双依赖不可用和取消均在三轮 race 通过；单查询鉴权相关回归同次通过（`auth-store-cache-final-v2-20261105.txt`）。gateway middleware race 通过，billing server 和 cmd/billing 无测试文件（`auth-store-cache-packages-20261105.txt`）；包日志的链接器警告保留。未覆盖主动失效、真实 Redis failover、权限同时更新、多进程、缓存命中统计或完整安全验收。

## Redis 旧快照恢复反例

`TestStoreAuthCacheRedisOldSnapshot` 使用脚本新建的独立 Redis 容器与真实 Store：先缓存普通 Key 并显式 `SAVE`，kill Redis 后在隔离 MySQL 禁用 Key，停机时回退权威查询正确拒绝；重启同一 Redis 并加载旧 RDB 后，三轮均再次从缓存接受该 Key（TTL 60 秒）。`auth-cache-old-redis-snapshot-stable-20261105.txt` 的 PASS 表示成功复现安全缺口，**不是恢复通过**；未自然等待 TTL、未测试 Redis 主从故障切换或多实例。测试只会 kill 名称和随机回环端口与 runner 匹配的临时容器。

首次 `auth-cache-old-redis-snapshot-20261105.txt` 失败：容器随机映射端口在重启后变化，客户端仍访问旧端口，后两轮端口校验失败；没有得到可用于判断缓存内容的结果。随后使用脚本 `TEST_REDIS_STABLE_PORT=1` 固定本次临时容器的随机回环端口取得上述三轮结果；临时容器均已清理。这个反例进一步说明不能将 Redis 可用性恢复或短期 TTL 当作禁用即时生效的证明，缓存继续默认关闭。

### 已观察故障的 Store 暂时回退

为缩小上述窗口，工作树现在让**观察到 Redis 读写错误的同一个 Store 实例**从错误时起至少一个本地 TTL 不读写鉴权缓存、直接查询 MySQL；缓存正常命中前也再次检查本地绕过状态。使用进程内单调时间，指标新增 `bypass`。调用方自己已经取消的请求不触发绕过。此保护是局部降级，不是共享失效协议；在途读与错误观察之间仍有竞态，TTL 期间 MySQL 负载会增加。

更新后的同一故障测试三轮：观察到故障的 Store 在 Redis 重启并恢复旧快照后拒绝禁用 Key；**新建 Store 无故障记忆，仍接受该旧 Key**。修复前同一断言三轮失败（`auth-cache-local-recovery-red-20261105.txt`），修复后三轮通过并同时复现新 Store 的缺口（`auth-cache-local-recovery-green-20261105.txt`）。常规缓存、慢查询和鉴权回归三轮通过（`auth-cache-local-recovery-regression-20261105.txt`），相关 metrics/middleware 包 race 通过、server 和 cmd/billing 无测试文件（`auth-cache-local-recovery-packages-20261105.txt`）。旧快照、未观察故障的实例、进程重启、Redis failover/时钟差、绕过期间权限写入及负载风暴仍未全面解决，缓存仍默认关闭，不应将本次保护称为全局可靠失效。

## 慢查询旧值回填

`TestStoreAuthCacheSlowReadDoesNotRefill` 对真实 Store 的数据库读使用 GORM 回调，在读到旧状态后阻塞；另一连接提交禁用，等待超过测试 TTL 后释放旧读。三轮 race 均观察旧的在途读取仍可返回，但 Redis 没有被旧值回填，后续权威读取拒绝；日志 `auth-store-cache-slow-read-20261105.txt`。这是受控同进程时序，不是 Redis 故障、跨机时钟或实际长事务。若旧读在 TTL 内完成，仍可能缓存旧权限；直接数据库状态变更没有围栏或主动失效，原安全限制不变。

## 真实缓存读取指标

工作树新增 `billing_auth_cache_read_total{result=...}`，固定标签为 `hit`、`miss`、`invalid`、`error`，无 Key 或租户标签；缓存关闭时不计数。`miss` 是 Redis 键不存在，包含浏览器会话（会话不写缓存）；`invalid` 是存在但未通过有效性检查；`error` 是 Redis 读错误；后三者进入权威查询，但不代表权威查询最终成功。指标不统计写入或真正的吊销延迟。真实 Store 的命中、未命中、损坏值回退和 Redis 连接失败的指标各三轮 race 通过（`auth-cache-metrics-final-20261105.txt`）；原指标缺失红灯为 `auth-cache-metrics-red-20261105.txt`。

独立真实网关 80 请求/秒、两轮各 10 秒、缓存 TTL 60 秒，64 合成账户/50% 浏览器、本地 mock，严格 V2 和 unknown hold；两轮各 800 有效 200、0 错误，P95 为 253/202ms，峰值在途 29/21，无发压丢弃。最终含 5 次 smoke 为 1605 settled、0 pending/reversed、余额无差异；4815 Outbox 未发送（relay 关闭）。billing 抓取为累计值：第一轮末 `hit=371, miss=434`（含 smoke），第二轮末 `hit=771, miss=834`，因此第二轮增量为各 400；无 `invalid/error` 序列。指标证明该次有实际命中，但不证明严格吊销或这些延迟来自缓存。原始[运行目录](gateway-open-load-runs/20261105-153952/)保存每轮 `billing-metrics-*.prom`、trace、审计和配置；无同期无缓存对照、短测和共享宿主限制性能结论。缓存继续默认关闭。
