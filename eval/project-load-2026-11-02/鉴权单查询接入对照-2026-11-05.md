# 鉴权单查询接入对照：暂不作为默认

将测试候选暂时接入本地工作树 `Store.ValidateAPIKey`：普通 API key 与浏览器会话均由单条 SQL 读取，浏览器会话的有效用户、租户和 session count 使用同一条语句的读视图。`BINARY` 名称比较保持原 Go 字节比较方式，不引入 Redis 缓存。隔离 MySQL/Redis 上验证了实际 Store 单次鉴权的 SQL 次数、身份状态、大小写名称、32 goroutine 混合会话、禁用提交后拒绝、已取消 context 与关闭连接时拒绝。各三轮 race 通过，日志 `../billing-comparison-2026-11-02/auth-production-one-query-verified-20261105.txt`。GORM `Scan` 走 Row 回调：首个验证版本仅监听 Query 回调误报 0 条，原失败保留 `auth-production-one-query-green-20261105.txt`；最终版本监听 Query 和 Row。原两查询实现测试一开始实际测得两条，见 `auth-production-one-query-red-20261105.txt`。接入之后的对照测试中测试候选与 Store 使用相同实现，不能把它称为独立功能对照；接入前独立对照和其限制见 `../billing-comparison-2026-11-02/鉴权单查询候选-2026-11-05.md`。`internal/billing/store` race 测试通过，`server` 包无测试。

## 完整网关对照

连续运行两个独立本地环境：先旧两查询 overlay，再单查询工作树。真实 gateway/router/billing/reconciler、隔离 MySQL/Redis，64 合成账户、50% 浏览器会话、同账户允许多个请求；模拟模型 15ms，严格预占 V2 与 unknown hold，Kafka relay、Agent 和周期余额重建关闭。每档 15 秒、两轮，按 80 再 120 请求/秒顺序；每轮零发压丢弃。表中 P95 计算包含所有 HTTP 请求及错误；吞吐按有效 200 数除以发压及排空时长。两组均共机、固定先后、无独立宿主、无长期预热，不能将差异归因于单项改动。

旧两查询有一轮 80 达到零错误，其余各轮均超过 1%；单查询所有轮均超过 1%。均有大量 routing unavailable，单查询也有鉴权和计费不可用。单查询最终有 28 个 503 对应无 usage 的 pending（21+1+0+6），两查询本次为 0；两组有效 200 在各自逐请求审计中均对应一条 settled、usage 已记录及一个结算行，余额差异为空。只反映采样时状态；没有等待默认 600 秒或验证 pending 的后续恢复。每组 Outbox 均未发送，因 relay 关闭。不能仅以计数或余额相等证明实际供应商没有收费。
