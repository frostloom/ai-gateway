# 用量异常出现后停止后续负载：隔离实验

## 测试目的和结果

原压测出现 HTTP 200 但账单 pending、usage 未持久化后，脚本增加了每轮逐请求审计并在发现异常时停止后续负载。此前异常触发路径未经过实测。本次用真实本地 gateway、billing、router、reconciler、随机隔离 MySQL/Redis 和模拟模型，针对指定测试 ID 的第一次 `ReportUsage` 在进入 Store **之前**注入一次 `Unavailable`。仅使用测试 overlay；生产服务代码未改。

三次独立运行各计划 5 和 10 请求/秒、每档两轮，每轮两秒，严格 V2、unknown hold。每次只完成第一档第一轮：10 个有效 200 中，9 个有 usage 且 settled，1 个 usage 缺失、pending、无 settle；审计识别 1 个异常，写出 `stopped-on-anomaly.json`，随后不再执行后续三轮。包括每次 5 个 smoke 请求的全局快照均为 settled 14、pending 1、reversed 0、余额与账本一致。等待实际约 1 秒后，同一请求仍 pending 且无 usage；这不是 600 秒宽限后的恢复测试。所有 43 条 Outbox 未发送，测试关闭 Kafka。三次进程退出 0 并产生 completed；completed 仅表示停轮后的观察流程完成，并不表示所有计划负载完成或账务恢复成功。

原始目录：[第一次](gateway-open-load-runs/20261105-114019/)、[第二次](gateway-open-load-runs/20261105-114137/)、[第三次](gateway-open-load-runs/20261105-114222/)。每个目录保留逐请求 trace、前后审计、配置、二进制与镜像指纹、指标和 runner 输出。各次异常 ID 含 `idem:stop-test-`；`gateway_billing_completion_total{result="usage_unacknowledged"}` 为 1，仅代表 gateway 观察到未确认。测试还核对了只有一条结果记录、无后续 trace、无余额差异及无自动冲正。

## 局限

故障是发送前确定失败，不是数据库提交后响应丢失、真实网络分区、进程崩溃或磁盘故障。它证实该指定故障下停轮动作有效，同时再次证实成功响应与无用量 pending 可以共存；**没有解决用量持久化或自动恢复**。脚本在每轮结束后审计，因此当前轮的其他请求仍会执行，不能当作实时熔断或生产安全措施。短测不提供容量估计。没有连接生产数据、调用付费模型、部署或提交。
