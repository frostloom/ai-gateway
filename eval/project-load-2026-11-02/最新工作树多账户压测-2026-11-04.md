## 错误、资源及核对

180 第二轮 95 个、220 两轮 472 和 808 个错误均为 HTTP 503 `routing unavailable`；本轮 gateway 诊断共记录 1375 条路由 3 秒 deadline，与错误总数一致，未记录客户端超时类别。它表明请求在路由调用阶段超时，不足以单独证明路由内部锁、MySQL 或 CPU 的具体根因。MySQL 本轮 `Max_used_connections=103`、`max_connections=151`、连接上限错误 0、InnoDB 行锁等待 4 次/总 59 ms；这些不覆盖 MySQL 命名锁。Docker CPU 是间歇采样，不是独占机器或周期平均：MySQL 样本最大约 268%（多个核心合计）、Redis 最大约 16%；每阶段样本及块 I/O 原始值见 `resources.jsonl`，无法可靠归因单次请求的 CPU/I/O。Redis 最终 INFO：累计命令 576839、内存峰值 11.18 MiB；累计值包含初始化、烟测、核对和全部场景，不能当某一档 TPS。

逐轮核对 `audits.jsonl`：pending 和余额差异均为 0，累计 settled 与有效 HTTP 200 相等；最终 17660 settled（含 5 条烟测）、0 pending、0 reverse、0 余额差异。Outbox 52980 条全部未发送，因为 relay 明确关闭；不能把账务事件写入当成投递或消费成功。逐请求 trace 和 trace-audit 在同目录，未覆盖流式、故障恢复、长时间稳定、真实收费、消息 relay 或全部管理功能。

## 复现

```bash
OPEN_LOAD_RATES=100,140,180,220 OPEN_LOAD_SECONDS=15 OPEN_LOAD_REPETITIONS=2 \
  OPEN_LOAD_HOLD_UNKNOWN=1 OPEN_LOAD_REQUIRE_V2=1 \
  python3 eval/project-load-2026-11-02/run_gateway_v2_open_load.py
```

测试只创建和清理自身命名的本地进程与容器。运行时应保证本机有足够资源，避免和其他压测并行；参数及主机状态不同会产生不同结果。
