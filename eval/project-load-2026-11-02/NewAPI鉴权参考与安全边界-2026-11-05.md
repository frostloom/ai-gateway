# New API 鉴权参考与本项目边界

用户对“密钥禁用后新请求是否必须立即拒绝”的回答是“按照 newapi”。本次将其作为选择 New API 的缓存/失效权衡方向，而非将其解释为承诺立即吊销。参考版本固定为 QuantumNous/new-api `45746eee4de25ab1eb75d4b7fbb8de2199483ea3`；以下是读取的源码行为，并非对 New API 运行结果或其最新版本的声明。

- [`GetTokenByKey`](https://github.com/QuantumNous/new-api/blob/45746eee4de25ab1eb75d4b7fbb8de2199483ea3/model/token.go#L282) 先读 Redis，未命中或出错回查数据库；命中缓存即返回。缓存初始化失败不影响当次读取。
- [`token_cache.go`](https://github.com/QuantumNous/new-api/blob/45746eee4de25ab1eb75d4b7fbb8de2199483ea3/model/token_cache.go) 在元数据变更前先设置 10 秒围栏，再删除 Token 缓存；回填 Lua 检查围栏。读取缓存本身不检查围栏。TTL 使用 `RedisKeyCacheSeconds()`，该版本取 `SYNC_FREQUENCY`；[`common/init.go`](https://github.com/QuantumNous/new-api/blob/45746eee4de25ab1eb75d4b7fbb8de2199483ea3/common/init.go#L112) 默认 60 秒，配置无效时 `tokenCacheTTLSeconds` 回退 60 秒。缓存初始化遇到已有 hash 会刷新 TTL，因此不能仅以一次设置 TTL 推断任何情况下的最大陈旧时间。
- [`Token.Update` / `SelectUpdate` / `Delete`](https://github.com/QuantumNous/new-api/blob/45746eee4de25ab1eb75d4b7fbb8de2199483ea3/model/token.go#L312) 失效报错只记日志，随后仍写数据库。围栏、缓存删除和数据库更新不在同一事务。

本项目此前通过测试模型复现：失效部分失败、围栏丢失、长写入跨越围栏、多个密钥的租户状态失效都可留下旧权限；见 [鉴权短期围栏测试](../billing-comparison-2026-11-02/鉴权短期围栏测试-2026-11-03.md)、[鉴权原子围栏候选](../billing-comparison-2026-11-02/原子围栏候选-2026-11-03.md) 和 [查询耗时与 TTL](../billing-comparison-2026-11-02/鉴权缓存查询耗时与TTL-2026-11-05.md)。这些是本项目隔离测试，不是运行 New API。不能由参考实现的默认 60 秒和 10 秒围栏推导出本项目有 60 秒的严格撤销上限。

当前代码已接入可选的 Redis 正向鉴权缓存，默认 TTL 为 0（关闭），浏览器会话始终查询数据库；缓存读写故障时，该 Store 实例在一个 TTL 内绕过缓存。它没有实现 New API 的主动失效和围栏：密钥或租户变更后，已有缓存可能在有效期内继续被接受；未观察到 Redis 故障的其他实例或新实例也可能读取恢复的旧快照。旧快照仍受缓存条目的原始时间和 TTL 检查约束，但不能称为即时吊销。故障与实际网关短测见 [可选鉴权缓存验证](可选鉴权缓存验证-2026-11-05.md)。在多实例和故障边界得到满足前，维持默认关闭；没有改生产配置、部署或调用付费模型。
