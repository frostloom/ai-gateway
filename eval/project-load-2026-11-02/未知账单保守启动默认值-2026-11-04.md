# 未知账单的保守启动默认值

## 变化与范围

此前网关默认会在上游结果未知时尝试切换/退款，对账器默认会对超期且无 usage 的 pending 退款。即便仅开启网关保守模式，对账器重启时漏传参数仍会退款。现在两个**可执行程序启动默认值**调整为保守：

- `cmd/gateway/main.go`：未设置或无效的 `GATEWAY_HOLD_UNKNOWN` 时保留未知结果，不主动换渠道/退款；显式 `0` 保留旧行为。
- `cmd/reconciler/main.go`：未传参数时启用 `-no-auto-reverse`，无 usage 的超期账单保留；已有 usage 仍执行补结算。显式 `-no-auto-reverse=false` 保留旧行为。

这不修改生产配置，不自动部署。可执行入口默认值变化会改变旧部署的业务行为：普通上游错误、未确认执行的请求或无用量流可能长期占用预扣，需提供对账、人工处理和监控；不能仅凭等待时间推断可退。`reconciler.New` 库的默认选项本次未改变，任何直接使用库、旧进程、显式关闭保护或调用账务 Reverse 的路径仍可绕过；没有权威状态协议和混版屏障，不可将此称作完整安全修复。

## 真实进程验证

本地随机独立 MySQL 8.0.40 / Redis 7，真实 gateway/billing/router/reconciler 和读取请求后返回 503 的 mock，上游无实际收费。测试脚本不传上述两个安全选项（对账周期 1 秒、grace 5 秒仅用于测试、禁用 rebuild/relay）：

- 修复前 `unknown-safe-default-red.txt` 失败，原始 `unknown-safe-default-runs/20261104-045833/` 显示调用一次后账单立即 reversed，并写 reverse Outbox。
- 修复后 `unknown-safe-default-green-1.txt` / `-2.txt`：各一次上游调用、HTTP 502，宽限后和对账器干净重启后均为 pending，无 usage/settle/reverse；状态报告自动冲正已禁用，Redis/账本核对无差异。原始目录分别为 `unknown-safe-default-runs/20261104-045957/` 和 `20261104-050039/`。5 秒不是生产默认宽限。
- `unknown-explicit-legacy-restart.txt`：先显式安全启动，再以 `-no-auto-reverse=false` 重启对账器，账单被冲正，证明兼容入口仍有风险；`unknown-explicit-gateway-legacy.txt`：显式 `GATEWAY_HOLD_UNKNOWN=0` 的网关在 mock 503 后立即冲正，证明旧行为仍可选。测试通过是复现这些显式配置的行为，不是安全证明。
- `unknown-safe-default-normal-load.txt`：未传安全开关，64 账户、非流式 60/100 请求每秒各 8 秒一轮，480/480 和 800/800 成功，累计 1285 settled 含 5 烟测，pending 0、余额差异 0；原数据 `gateway-open-load-runs/20261104-050149/`。每档只有一轮，不作为性能或容量结论。Outbox relay 关闭，事件未投递。
- `go test -race ./cmd/gateway ./cmd/reconciler ./internal/gateway/handler ./internal/billing/reconciler` 通过；三个包无测试文件，handler 测试通过。所有测试为合成数据，未部署或调用付费服务。

测试仅覆盖一个 mock 上游、正常的对账器 SIGTERM 重启及短时正常请求；未覆盖多实例混版、实际供应商费用、DB/Redis 故障、幂等恢复、长时间积压或正式恢复流程。已有流式断连测试及竞态风险需继续验证；本次没有实现永久安全的退款许可、通知或余额解冻。
