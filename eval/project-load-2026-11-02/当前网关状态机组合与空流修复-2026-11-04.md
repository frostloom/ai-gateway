# 当前网关状态机组合与空流修复

## 空流缺陷和修复

当前 `relayStream` 在读取 SSE 数据前设置响应头；上游正常返回 200 但 body 为零字节时，既没有向客户端输出内容，也没有显式设为错误，HTTP 最终表现为空的 200。真实 handler 独立测试 `empty-stream-red.txt` 复现该行为。现有代码无法确认上游是否执行，不能因此退款。

`internal/gateway/handler/chat.go` 记录实际成功写出的字节；循环结束时如果一个字节也未写出，返回 JSON 502 并保留 pending，不上报用量、不结算、不冲正。如果已经写出任何 SSE 字节，则保持流原有行为，不尝试改写已经承诺的 HTTP 状态。该修复不解决 pending 自动恢复或供应商实际收费确认。当前 handler 包加新测试完整 race 回归通过，见 `empty-stream-portable-final.txt`；新测试断言 502、JSON 类型和账务无副作用。测试模拟 loopback 空 body，不是生产上游。

复现：`bash eval/project-load-2026-11-02/run-empty-stream-regression.sh`。脚本在临时目录生成 Go overlay，仅添加测试文件；Mac SDK 路径按本机环境设置。

## 当前代码上的实验性端到端组合

此前实验用完整旧网关文件会回退后续内容校验及保守模式，现 `build-current-gateway-attempt-candidate.py` 以当前 handler 为基础，仅加入测试用 attempt begin/finish 钩子；与 `billing_execution_state_current_candidate.go.txt` 配套通过 Go overlay 测试，未将该协议接入正式代码。HEAD `63b9d1ed4d64bb583d15fa884c37468e5c53044c`；测试时 Store 原文件 SHA256 `ec3891028d86e7bda3ee4b0fe1ad1dc67fbbfa432b8002ca9e6738d723e1c567`、Store overlay `443d26c7ad72ad466786a87379fe68d17cff6429f27d203d7b6ca88e71ceef7b`；空流修复后的 handler SHA256 `68963d65a00062da1d8a878f3155e158ad7e69e22abd16c4503139bfb57b6cf1`、handler overlay `c52f7b82f96a79d7430a28df2367a2cf98b345222fa8e7d78a2d9d1ebdfdd1be`。

隔离 Docker MySQL 8.0.40、Redis 7，真实 handler、本地模拟上游及测试专用 bridge，每项流式/非流式 race 三轮：

- `current-handler-inflight-final.txt`：上游读完请求尚未响应时人为使账单变旧并触发一次对账；没有冲正，后续返回用量并结算，余额/账本 960，指定账务与 attempt 事件核对通过。
- `current-handler-inflight-unknown-after-fix.txt`：相同在途扫描后上游返回 500；只发送第一个上游，返回 502、账单 pending、测试 attempt 保持 sending、余额/账本 999。
- `current-handler-other-after-empty-fix.txt`：完整与截断响应、完整/部分/空 SSE、attempt Outbox 应用回调注入失败等测试通过。该测试使用默认兼容行为，部分 SSE 以估算结算；这不是供应商真实用量证明。attempt Outbox 失败时账单仍可结算，但 attempt 继续 sending，需要额外恢复。

修复前 `current-handler-other-final.txt` 因空 SSE 期望 502 实际 200 失败，原日志保留。测试 bridge 中 request fingerprint、owner、认证及状态入口是合成实现；当前正式服务不具备完整此协议。测试不覆盖正式混版、历史数据迁移、所有旧入口、实际供应商执行、长期资源占用、跨机器故障、Outbox 投递或收费核对。不可将结果视为生产安全/容量证明，也不能用来撤销对旧入口组合失败的记录。
