# 上游读完请求后的故障压力

基准 HEAD `63b9d1ed4d64bb583d15fa884c37468e5c53044c` 加未提交工作树。独立本机真实 gateway/billing/router/reconciler、MySQL 8.0.40、Redis 7、64 合成账户、单个模拟上游；启用 `GATEWAY_HOLD_UNKNOWN=1` 与 `-no-auto-reverse`。测试上游先解析 JSON 并读取请求体余量，按 25% 概率返回 500，否则返回模拟成功和用量；这模拟已接收，不证明真实执行、计费或供应商行为。测试用对账 grace 5 秒、周期 5 秒，关闭 rebuild 和 Outbox relay。40、80 次/秒各 10 秒两轮，四轮依次运行、状态累积，结束后额外等待 10 秒。

全部 2400 个计划请求均启动、发压丢弃 0。对合成请求 ID 联合模服务 body-read 日志与客户端 trace：1598 个 200 和 529 个 502 各恰有一次本地模拟上游读取；273 个 503 均无上游读取，body-read ID 无重复。结束后对账审计逐轮的 1598 个成功请求均为 settled、有 usage、恰一条 settle；529 个 502 为 pending、无 usage、无 settle；273 个 503 未预占。最终余额与账本无差异，Outbox 有 5323 条但全部未投递。关联结果 `gateway-open-load-runs/20261104-022329/body-read-analysis.json`，重跑分析 `python3 eval/project-load-2026-11-02/analyze_readbody_hold.py eval/project-load-2026-11-02/gateway-open-load-runs/20261104-022329`。
