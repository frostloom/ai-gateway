# 跨账户幂等键范围核查

当前 API Key / Portal 鉴权在幂等中间件之前设置 `tenant_id`，但 `internal/gateway/middleware/idempotency.go` 的 Redis 键是 `idem:` 加客户端键，没有账户范围；下游 request ID 也直接使用同一值。`scripts/schema.sql` 的账单唯一索引为 `(request_id, phase)`，同样是全局范围。

隔离的中间件行为测试 `idem_tenant_scope_test.go` 使用 miniredis 和两个注入的不同 tenant：依次提交相同客户端键，第一个到达处理器并产生 `idem:shared-client-key`，第二个返回 409。命令：

```sh
GOPROXY=off GOTOOLCHAIN=local go test ./eval/project-load-2026-11-02 -run '^TestCurrentIdempotencyKeyConflictsAcrossTenants$' -count=1 -v
```

结果：通过；这是对现状的表征，未经过完整鉴权、真实 Redis 或数据库。首次运行因测试包名不匹配而在编译前失败，改为已有包名后通过。

这会造成不同账户之间的可用性干扰，不能只修改 Redis 前缀：账单唯一键及 Outbox 也依赖全局 request ID，必须同时设计确定性的账户隔离标识、长度限制和历史请求兼容。新旧版本混跑、旧键 TTL 内的重试及既有 pending 账单都需要迁移测试，否则改名可能绕过旧记录导致重复转发。尚未修改生产逻辑，也不能认为已解决幂等键残留问题。
