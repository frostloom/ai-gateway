# 用量与冲正请求锁候选的多账户网关对照

## 安全边界先于性能

本候选不是可部署方案。它仅在 `Reason=recon:no_usage` 时禁止冲正已记录用量的账单，`Reason` 是调用者可提供的自由文本，其他原因可以绕过；没有解决上游结果未知时能否退款、旧版本写入、身份分权和混版屏障。详细反例和受控故障见 [最新 Store 用量与冲正竞争候选](最新代码用量冲正竞争候选-2026-11-04.md)。本次压测不能证明这些安全问题已经解决，也不代表应让调用者自行声明退款依据。

测试前重新以当前 `mysql.go` SHA `e4a53b0eaca810e385a7336c0ace3b05723313b362342b6094b822bee0d8f98c` 生成 overlay SHA `095480cd590d6dcfd8ae7895e0b1aee28b06c1aa4a665acf0c85f70104f5fc84`。`usage-reverse-current-preload-20261104.txt` 保留故意失败的基线反例及候选通过的选定 race 回归；候选仅对一次具体对账竞争提供保障。

## 环境和方法

隔离 MySQL 8.0.40、Redis 7、真实 gateway/billing/router/reconciler、本地 15ms 模拟模型、64 个账户，允许账户并发请求；Agent 和 Kafka relay 关闭，reconciler 保守且 grace 600 秒。以开放到达率 100、140、180 请求/秒各跑两轮，每轮 10 秒；发压器最多 1000 在途。两组先后运行而非交错，工作负载不随机，机器共享、时间和数据库状态不同。两组源码、镜像、发压器及其余可执行文件 SHA 相同，只有 billing 二进制不同。完整配置、每请求追踪、MySQL/Redis 指标及日志：

- 基线 `gateway-open-load-runs/20261104-060908/`
- 请求锁 overlay `gateway-open-load-runs/20261104-061108/`

## 结果

每格依次为第 1/2 轮；延迟含所有请求，毫秒。两组各档发压器均未丢请求、HTTP 错误均为 0。有效完成吞吐分母含发压结束后的排空时间。

| 提供请求/秒 | 组别 | 有效完成/秒 | 平均 ms | P95 ms | P99 ms |
|---:|---|---|---|---|---|
| 100 | 基线 | 99.3 / 98.8 | 164 / 159 | 325 / 293 | 436 / 354 |
| 100 | 候选 | 99.2 / 99.1 | 256 / 164 | 481 / 261 | 549 / 284 |
| 140 | 基线 | 134.5 / 135.2 | 249 / 297 | 484 / 491 | 536 / 546 |
| 140 | 候选 | 131.8 / 135.3 | 476 / 340 | 932 / 520 | 984 / 559 |
| 180 | 基线 | 142.6 / 138.6 | 1543 / 1975 | 3282 / 3521 | 3838 / 4154 |
| 180 | 候选 | 138.0 / 135.2 | 1796 / 2271 | 3491 / 4403 | 4177 / 5159 |

逐请求核对中每组 8400 次压测请求均为有效 200、reserve 已 settled、usage 已记录且只有一条 settle；另各有 5 次 smoke。最终各 8405 settled、0 pending、0 reversed、余额一致。Outbox 各 25215 条未发送，因为 relay 明确关闭；不能从此测试推断 Kafka 交付。请求产生、结算和 Redis/账本核对均在本地模拟环境进行。

MySQL 两组最大使用连接数均 103/151，上限连接错误均 0；基线 InnoDB 行锁等待累计 5 次共 37ms，候选 0 次。它们是整次运行累计值，**不包含也不能替代 MySQL advisory lock 的等待指标**，不能由此认定锁无开销。资源采样和 Redis INFO 见原始目录。180 档即使零错误 P95 也超过 3 秒，本测试不设用户未指定的 P95 SLO，不能称生产可用并发上限。

本次候选在 140 和 180 档的延迟多数较高，但重复数少且运行时间不同时，不能将差异完全归因请求锁；也没有测同一账户热点、长稳或未知状态真实恢复。当前数据足以说明：增加安全协调需要测量代价，不支持仅凭这轮判断其必然不可用或足以解决安全问题。
