# 当前代码与状态机实验候选的组合验证

## 范围和结论

旧 V5 是旧版 Store 的完整副本，不能覆盖当前 Store：会丢失 v2 指纹、禁用租户检查、订阅预占、金额溢出检查和缺失余额恢复等后来修改。这里使用 `build-current-state-candidate.py` 在当前 Store 上按锚点添加 V5 实验字段与行为，输出仅供 Go overlay 使用，未修改生产 Store。当前 HEAD `63b9d1ed4d64bb583d15fa884c37468e5c53044c`，输入 Store SHA256 `ec3891028d86e7bda3ee4b0fe1ad1dc67fbbfa432b8002ca9e6738d723e1c567`，最终候选 SHA256 `443d26c7ad72ad466786a87379fe68d17cff6429f27d203d7b6ca88e71ceef7b`。生成器对每个锚点要求唯一匹配；差异应在运行前后人工审查。

**这不是生产修复。** 实验状态转换、完成证据、协调入口仍由测试 bridge 提供，旧入口、混版、授权、迁移和历史账单未闭合；未知上游结果不能安全自动退款的问题仍存在。现有通过结果也不证明全部现有修复与候选组合正确，不构成性能或部署结论。

## 执行和结果

隔离 Docker MySQL 8.0.40 与 Redis 7，每项新建容器，使用当前网关代码和当前其他工作树文件，Go race，各 3 轮。涉及的数据均为合成数据。

- `completion-current-final-coordinated.txt`：完成观察持有账单协调锁时，竞争失败转换被拒；三轮通过。测试通过回调与有限等待构造竞争，不证明每次竞争者已进入锁等待。
- `completion-current-final-failure-first.txt`：失败先提交时，完成观察被拒且失败事件唯一；三轮通过。
- `completion-current-final-atomic.txt`：错误 attempt 被拒，注入用量 Outbox 写失败时相关写入回滚，重试后检查指定事件和账本；三轮通过。失败为应用回调注入，不是真实 MySQL 崩溃或提交确认丢失。
- `atomic-reserve-current-final.txt`：现金预占的实验 owner 写失败后账单与事件回滚、余额恢复，重试写入 owner 和租约；三轮通过。该测试不验证订阅预占与实验 owner 的组合。

首次组合使用过期网关 overlay 因 `Chat` 签名不符编译失败，原日志 `completion-current-candidate-2026-11-04.txt` 保留；更换当前网关后首次生成脚本经差异检查发现订阅路径重复写 intent、现金路径漏写，已纠正，旧通过日志不作为最终候选证据。最终测试均在纠正后的候选上运行。

## 正式旧入口组合回归：失败，不可部署

`bash eval/billing-comparison-2026-11-02/run-current-combination-regression.sh --candidate` 三轮 race，完整日志 `../billing-comparison-2026-11-02/current-combination-regression-final.txt`。指纹并发 `TestContentFingerprintConcurrentStore` 三轮通过，保留同内容重放、不同内容冲突及余额/账本检查。`TestContentFingerprintSubscriptionConcurrentQuota` 与 `TestDisabledTenantOrdinaryKeyAndSubscriptionReserve` 三轮失败：测试使用当前正式入口，入口没有执行实验性的 forwarding/reversing 转换，候选因而拒绝用量或冲正，后续结算及相应事件缺失。该失败是预期的集成缺口的实际证据，不能归因于原有指纹或禁用租户代码，也不能据此宣称实验候选具备向后兼容性。

在正式协议及严格混版屏障尚未建立前，不应将该 Store overlay 投入使用；不能用移除守卫的方式掩盖失败。先设计并测试每种入口与历史在途账单的安全迁移，再重跑此类业务回归。

## 订阅与实验发送许可的组合补测

`bash eval/billing-comparison-2026-11-02/run-experimental-subscription-current.sh --candidate` 在同一当前 Store overlay、独立 MySQL/Redis 下执行 `TestExperimentalSubscriptionIntentQuota`，race 三轮通过，日志 `../billing-comparison-2026-11-02/experimental-subscription-combined-final.txt`。每轮执行：

1. 注入 owner/lease 写入失败，断言对应订阅账单和 reserve Outbox 都未提交；随后仍可使用完整额度。
2. 单租户订阅额度 300、8 个各预占 100 token，3 个成功、5 个额度拒绝；成功账单含预占量、owner hash、lease，且各有一条 reserve Outbox。
3. 同请求 ID、相同账务参数但不同 v2 内容指纹被拒；随后禁用租户，新预占被拒，先前已预占的三个请求经**测试专用** capability RPC 获得 forwarding 许可，再经现有 billing gRPC 上报与结算。三笔结算成功，Redis 余额和账本均为 100000 分。

这里将禁用前已预占视为在途，测试允许其在禁用后获取发送许可；是否应允许尚未发出的请求继续，需要正式明确权限语义。测试中的 owner 固定、RPC 为测试实现、发送许可不代表真实上游已执行；未验证供应商、真实进程故障、旧入口/混版、退款或事件消费，不能抵消上一节正式入口失败。验证仅覆盖指定 reserve Outbox 和余额，不能推断全事件投递正确。

最初把内容冲突验证安排在禁用之后，实际先触发租户拒绝，三轮失败，日志 `experimental-subscription-disabled-final.txt` 保留；调整顺序后才分别验证内容冲突和禁用行为。测试代码也可在不启用 overlay 时编译并跳过，避免污染普通测试构建。
