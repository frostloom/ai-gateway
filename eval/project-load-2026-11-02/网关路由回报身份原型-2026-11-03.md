# 网关路由回报身份原型（隔离构建）

当前真实 `client.Router.Report` 仅发送 provider ID 和成功标记；网关 failover 中每个被尝试 provider 发生一次成功或失败回报，非流式和流式分别有独立路径。其签名不提供可重试的事件身份，当前客户端也不处理 HTTP 回报失败。

测试候选通过 Go overlay 在实际 gateway handler 的六个 Report 调用传入测试 scope，由 tenant ID、请求 ID、attempt 序号、provider ID 和版本域构造 SHA-256 事件 ID，在回报 JSON 中额外发送；不更改生产源码。该身份不包含成功/失败值，使同一尝试的不同结果复用 ID 并由接收端判冲突。请求参数冲突仍要由另行的请求/账单指纹守卫处理，不等同于响应保存或重放。

`python3 eval/project-load-2026-11-02/run_gateway_identity_test.py` 在真实网关 handler、真实 router HTTP client 与本地假 provider/假路由上，使用假的 billing 允许多次调用以单独验证身份：第一渠道返回 503，第二渠道成功；非流式和流式均有两条回报。原代码不发送事件 ID，预期失败 `gateway-identity-red.txt`；加 `--candidate` 后同账户相同请求/尝试重复相同，不同账户、渠道尝试不同，`gateway-identity-green.txt`。该测试的假 billing 允许重复不是声称真实请求会安全重放。候选 overlay 的 handler/client 两包完整 race 测试见 `gateway-identity-full-race.txt`。

`bash eval/project-load-2026-11-02/run-gateway-durable-identity.sh` 将真实 gateway router HTTP client 的测试身份候选与独立 MySQL 事件原型通过本地 httptest handler 连接：首条失败事件提交后人为返回 503，测试代码显式调用第二次，结果同 ID 不再重复加一；用同 ID 改成成功被拒，下一 attempt ID 不同并加一。三轮 race 通过，`gateway-durable-identity.txt`。这不是实际网络丢包，也不是 gateway 自动重试——当前 Report 返回 void 且忽略 503；测试 handler 不是生产 router，不含熔断/AutoBan。

**未覆盖与禁止上线：**实际网关未生成、持久保存或跨进程恢复这个 scope；请求 ID 的租户范围、参数指纹、重复上游执行仍有已记录的问题。以固定 ordinal 表示 attempt 在进程重启、路由变化、并发重放或同 provider 多次真实调用时可能错误合并；必须在发送前持久化独立 attempt 身份并定义恢复。测试 scope 缺失会省略 ID，不能当安全 fail-closed 协议；上游回报何时产生、客户端断开、事件持久化顺序、Router 的内存熔断、混版协商、队列满和结果未知都未解决。不得将该 overlay 当生产方案。
