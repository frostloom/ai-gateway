# 路由回报缩锁落地

`internal/router/registry.go` 为每个已有 breaker 增加回报锁：同渠道回报的内存变化及同步数据库写入串行，不同渠道的数据库写入不互相持有全局状态锁；选路仍在全局锁内原子选择和占用半开探测位。AutoBan 在写库前发布内存 OPEN 并失效缓存，写入尝试结束后再次失效，避免并发刷新把写入前快照长期留在本实例。回报更新内存后、数据库提交前，选路可看到新内存状态；这是与旧实现不同的可见时序。写入仍同步、没有新增队列或重试。

旧 `TestCanceledRouteDoesNotConsumeHalfOpenProbe` 以 HTTP 包装器开始作为取消先于选路的证明，依赖另一个 Report 持全局锁；缩锁后不能再保证此顺序。两项取消测试现在在测试包装器等待请求 context 取消后才调用真实 handler，明确验证取消先于选路或刷新；已选路后取消仍占用探测位的原有边界由 `TestRouterProbeCancellationOrder` 单独覆盖。这个修改不再测试“等待 Report 全局锁时取消”，因为数据库写已不持该锁；也不证明网络断连的全部时序。

隔离 MySQL/Redis：旧实现三轮复现回报阻塞其他选路和渠道；新实现的两个阻塞用例、同渠道顺序、取消前/后顺序、刷新与封禁竞争、刷新取消及阈值持久化，各三轮 race 通过（`router-report-main-red-20261105.txt`、`router-report-main-green-v2-20261105.txt`）。router 与 gateway/client 包 race 通过（`router-report-package-v2-20261105.txt`）；链接器警告保留。对 MySQL 写入前注入错误，真实 `/report` 仍返回 200、内存失败计数 1、数据库计数 0，三轮均复现（`router-report-write-failure-v2-20261105.txt`）；该测试 PASS 代表复现缺陷，不是可靠回报通过。重复事件、跨进程顺序、提交确认丢失、迟到回报和半开探测身份仍未解决。
