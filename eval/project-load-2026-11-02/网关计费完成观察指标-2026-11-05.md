# 网关计费完成观察指标

持续压测中出现 HTTP 200 但用量未记录或结算尚未完成，原 handler 只有日志。当前工作树在 `internal/gateway/handler/chat.go` 的 `settleAndLog` 和 `internal/pkg/metrics/metrics.go` 增加 Prometheus counter `gateway_billing_completion_total`，仅允许三个固定 `result` 标签：

- `usage_unacknowledged`：网关看到 ReportUsage 返回错误、空响应或未接受，未继续调用 Settle。
- `settlement_unacknowledged`：用量已获确认，但 Settle 返回错误、空响应或 `settled=false`。
- `settlement_acknowledged`：网关收到 `settled=true`。

**这些是进程观察到的 RPC 结果，不是最终账单状态或唯一账单数。** 未确认可能已经提交；同请求多次执行可能重复计数；进程在计数前退出会漏计，重启计数归零。该指标只覆盖调用 `settleAndLog` 的路径，不覆盖缺失/无效 usage 时没有进入该函数、预占失败、直接 Store 调用或旧版本。没有 request、tenant、provider 等高基数标签，不暴露模型内容或凭据。它不修改计费判断、重试、返回状态或恢复策略，不能据此释放预占或声称用量安全持久化。

## 验证
