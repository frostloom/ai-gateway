# 路由和鉴权改动后的 Redis 中断

使用工作树（HEAD `d66ebc53c37470dcfae00b463e58d3f52ca3f914` 加未提交改动）、隔离 MySQL/Redis、真实 gateway/billing/router/reconciler、64 合成账户、50% 浏览器、本地 15ms mock、严格 V2/unknown hold。测试脚本仅停止并重启其新建的 Redis 容器；Kafka relay、Agent 和周期重建关闭。每阶段 20 请求/秒、3 秒，带不同幂等键，无发压丢弃。

| 阶段 | HTTP | 全请求平均/P95/P99 ms | 账务观察 |
|---|---|---|---|
| 正常 | 60 个有效 200 | 196/344/396 | 含 5 smoke，65 settled、0 pending |
| Redis 停止 | 60 个 500，idempotency unavailable | 368/1303/1377 | 重启后逐请求审计均无 reserve/usage/settle |
| Redis 重启并 PING 后立即请求 | 56 个有效 200、4 个 500 | 133/250/287 | 56 已结算，余额核对发现 8 个缺失键 |

对 8 个缺失账户各顺序发送一个新请求，均成功；最终 129 settled、0 pending/reversed、64 个余额键齐全且无账本差异。387 条 Outbox 未发送，relay 关闭。测试没有验证停机前在途操作、同账户并发、重试相同幂等键、流式、主从切换或长时间恢复。Redis `PING` 成功不代表 gateway 全部连接已恢复；四个 500 的物理原因未定位。一次短测不能作为故障恢复时限或容量承诺。

当前结果表明 Redis 既参与余额投影，也参与幂等中间件；停止时整网关不能依靠鉴权回退继续处理请求。不能仅凭余额键恢复就删除 Redis，也不能根据该次测试证明所有情况下账务安全。[原始运行目录](gateway-open-load-runs/20261105-152033/)含配置、源/二进制/镜像哈希、trace、故障后核对及探针；stdout `../router-auth-redis-restart-20261105.txt`。临时容器已清理；无生产数据、付费调用、部署或提交。
