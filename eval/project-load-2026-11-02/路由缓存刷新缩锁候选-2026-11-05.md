# 路由缓存刷新缩锁：测试候选

当前 `Registry.snapshot` 持有与选路、回报共用的全局锁进行 MySQL 查询。隔离 MySQL 测试将一次未命中缓存的渠道查询在读取完成后人为停住：另一模型的已缓存选路、同一 Registry 的封禁回报均在 500ms 内无法完成，释放后才继续，三轮复现；红灯 `router-refresh-lock-red-20261105.txt`。这是受控长查询，不等同实际数据库故障频率或全网关瓶颈归因。

`../billing-comparison-2026-11-02/build_router_refresh_scope_overlay.py` 从当前工作树构造仅测试用 overlay：缓存命中仍持短暂状态锁；未命中在单个可取消的刷新许可内查询数据库，锁外构建列表；发布前检查本 Registry 的缓存失效代次。刷新期间本实例封禁导致缓存清理时，丢弃旧快照并重新查询。未改变回报持锁写数据库、半开策略、跨实例同步或生产源码。多个不同模型的缓存未命中仍串行刷新；等待其他全局锁的过程仍不能保证及时响应取消。

隔离 MySQL/Redis race 三轮：已缓存选路可在另一个刷新被人为阻塞时完成；封禁可先完成，原刷新丢弃旧快照并再次查询；刷新许可等待可响应取消；既有取消探测位、取消刷新、阈值计数测试同次通过，日志 `router-refresh-cancel-green-20261105.txt`。移除代次检查的反例中，最初仅检查返回渠道仍通过，因为本地熔断暂时挡住了被封禁渠道，不能证明缓存正确；增加 SQL 重查次数断言后三轮失败，保留 `router-refresh-unfenced-count-red-20261105.txt`。第一版使用不可取消 mutex，取消测试三轮失败 `router-refresh-cancel-red-20261105.txt`；改为可取消许可后上述测试通过。测试针对指定进程和交错，不代表跨进程一致性或权限更新全覆盖。候选 overlay 下 router 与 gateway client 包 race 测试通过。
