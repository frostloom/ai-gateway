# 固定路由隔离对照

## 用途和方法

这是瓶颈诊断，**不是等价方案对比**。`fixed-router/main.go` 只返回一个合成渠道，接受成功/失败回报但不执行熔断、AutoBan、数据库持久化、渠道选择或故障转移；不能替换真实路由上线。真实网关、鉴权、billing、MySQL、Redis 和本地模拟模型均保留。测试用随机隔离容器、64 合成账户、模拟模型 15 ms，并发以表中总 worker 数为准，每账户可多请求；闭环 3 秒并排空。两套 gateway/billing 同时常驻且各自二进制哈希相同，真实 router 与固定替身同时运行，MySQL/Redis 共享，两个重复按相反顺序执行，使用不同账户组。MySQL max_connections=500、billing 各自连接池上限 100、GOMAXPROCS=8、relay 关闭；与生产部署无关。

复现：`python3 eval/project-load-2026-11-02/run_fixed_router_comparison.py`。原始目录 `router-fixed-comparison-runs/20261103-190834/` 包含源码/二进制哈希、配置、资源采样、HTTP 统计和全局账务审计。脚本从新库实际查询合成 provider ID 后传给替身，非生产数据；全部服务监听本机。脚本沿用对照框架中未使用的旧协议和前次 router candidate overlay 构建材料，实际 `router_new` 编译的是 fixed-router，配置及二进制哈希可核对；不得把那些未使用 overlay 视为本次被测逻辑。

## 结果

吞吐为有效完整 HTTP 请求/秒，分母含排空时间；P95 是所有完成请求延迟，含失败。每组只测两次：

| 总并发 | 路由 | 有效请求/秒 | P95 ms | 503/请求数 |
|---:|---|---|---|---|
| 256 | 真实 | 142.9、140.4 | 2089、1958 | 0/621、0/658 |
| 256 | 固定替身 | 176.6、192.7 | 2006、1730 | 0/702、0/787 |
| 512 | 真实 | 142.8、128.8 | 4187、4649 | 0/888、0/862 |
| 512 | 固定替身 | 178.3、172.0 | 3745、3991 | 4/873、6/818 |

两次顺序反转下固定替身吞吐更高，支持“真实路由路径存在值得进一步定位的开销”这一假设；因为替身省略业务功能、账户组和历史数据不同、共享本机负载波动且样本仅两轮，不能将差额归因于某一锁或承诺可获得同幅提升。512 组替身依然发生 503，负载程序未记录其错误分类；说明固定路由不能消除全部失败，但不知道具体来源。

最终累计 6228 有效 HTTP 响应（含烟测）对应 6228 settled，pending 0，Redis 余额与账本一致；未保存逐失败请求账单关联，不能证明所有故障的恢复。18684 条 Outbox 均未发送，因 relay 关闭。MySQL 最终累计最大连接数 203、连接数上限错误 0、行锁等待 0；不包含所有 pool/advisory lock 或时间序列证据。下一步需要保留路由功能，分别测量成功回报 MySQL 写、共享锁和连接等待，并在受控失败及多实例场景保证状态语义；此短测不能作为稳定并发上限。
